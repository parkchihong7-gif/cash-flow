# 누가 어느 문으로 들어오는가

프로그램을 팔기 시작하면 **화면을 보는 사람이 셋**이 된다. 셋을 한 화면에
섞으면 고객에게 내 매출이 보이고, 나는 내가 필요한 것을 못 찾는다.
주소부터 갈라 두었다.

| 누구 | 주소 | 어떻게 들어오나 | 무엇을 보나 |
|---|---|---|---|
| **메인 관리자** (나) | `/` | 대시보드 접속 코드 | 16종 전부, 회원·매출·실행 기록 |
| **프로그램 관리자** (산 사람) | `/apps/<상품>/admin` | 대시보드 접속 코드 | **자기 프로그램 하나.** 접속키를 발급한다 |
| **클라이언트** (산 사람의 고객) | `/c/<상품>` | **이중키** | 결과만. 관리자 기능은 없다 |

## 키는 어디서 만드나

통합 대시보드 왼쪽 메뉴 **🎟 접속키** 에서 시작합니다.

    통합 대시보드 → 🎟 접속키 → 프로그램 줄의 [키 만들기 →]
      → 이름·이메일 → [발급하고 안내문 만들기]

주소로 바로 가시려면 `/keys` 입니다. 프로그램 안에서 바로 여시려면
`/apps/<프로그램>/admin/t/keys` 이고, 관리자 모드 왼쪽의 **🔑 접속키** 탭과
같은 자리입니다.

**키는 프로그램마다 따로입니다.** 13번 키로 14번에 들어갈 수 없습니다 —
한 프로그램을 산 사람이 나머지 열다섯까지 열면 안 되기 때문입니다.

발급하면 이렇게 됩니다.

1. 키 네 개가 한 번에 — 1차키 1개(사람) + 2차키 3개(PC·노트북·휴대폰)
2. 보낼 **안내문이 같이** 만들어집니다. `[전체 복사]` 로 복사해 보내시면 됩니다
3. 고객은 안내문의 주소(`/c/<프로그램>`)로 들어옵니다

화면을 벗어나면 키는 **다시 볼 수 없습니다**(목록에는 남습니다).
먼저 복사하거나 메일을 보내세요.

## 왜 문을 따로 냈나

통합 대시보드는 접속 코드 하나로 통째로 잠겨 있다. 그 안에 고객 이름·연락처와
매출이 있으니 당연하다. 그런데 프로그램을 판 뒤 고객이 자기 화면을 보려면
바로 그 코드가 필요해진다. **고객에게 내 대시보드 코드를 줄 수는 없다.**

그래서 `/c/<상품>` 을 냈다. 이 문은 이중키만 받는다. 열린 것은 **문이지 화면이
아니다** — 키가 없으면 안으로 못 들어온다.

키를 발급하면 만들어지는 안내문에 적히는 주소도 이것이다.

## 클라이언트 화면은 따로 만들지 않았다

**관리자 화면에서 관리자 것만 덜어낸 것**이다. 따로 만들면 반드시 한쪽만
고치게 되고, 그때부터 "고객이 보는 화면은 다르더라" 가 시작된다.

덜어내는 것은 이렇다.

- 🔑 접속키 · ⚙️ 기본 세팅 · 📁 파일 위치 — 탭째로 빠진다
- 기록을 지우는 것처럼 **되돌릴 수 없는 자리** — 상품이 `admin_only` 로 표시한다
- API 키·모델 같은 값 — 칸 단위로 빠진다
- 실제 실행 — 화면에서 감추는 것과 별개로 **주소로 들어와도 막는다**

메뉴에서 감추는 것은 잠금이 아니다. 주소를 직접 쳐서 들어오는 길까지 닫아 두었고,
그것을 시험으로 못 박아 두었다 (`tests/test_clientdoor.py`).

## 16종이 공유하는 두 가지 표준

프로그램마다 인증과 설정이 제각각이면 파는 사람이 관리를 못 한다.
**이미 돌아가고 있는 프로그램들의 관리자 매뉴얼에서 규격을 그대로 가져왔다.**

### 이중키 (`core/keyauth.py`)

공인중개사 기출문제 대시보드와 maim 네이버 블로그 관리자에서 가져왔다.

```
마스터 토큰   영구 · 본인만 · 절대 배포하지 않는다
 ├ 1차키      사람 1명당 1개 · 동시접속 제한 없음 · 이메일로 배포
 │  └ 2차키   PC·노트북·휴대폰 3개 · 기기당 1세션
 │            중복 로그인 시 먼저 있던 기기가 잠긴다
 └ 레거시     1차키 칸에 단독 입력 (예전에 뿌린 키 하위호환)
```

한 겹이면 키 하나가 새는 순간 몇 명이 쓰는지 알 수 없다. 두 겹이면 1차키는
사람을, 2차키는 기기를 붙잡는다. 키를 빌려줘도 기기 수만큼만 쓸 수 있다.

되돌릴 수 있는 것과 없는 것을 손끝에서 구분되게 했다.

| 하는 일 | 되돌리기 | 화면에서 |
|---|---|---|
| ⏸ 사용중지 | 된다 | 한 번 누르면 된다 |
| 🗑 삭제 | 안 된다 | **두 번** 눌러야 한다 |
| 전체 초기화 | 안 된다 | `초기화` 를 정확히 쳐야 버튼이 살아난다 |

세션이 끊길 때는 **왜 끊겼는지** 화면에 적는다. "다른 기기에서 로그인되어
세션이 종료되었습니다" 를 안 알려 주면 사람은 프로그램이 고장 났다고 여긴다.

### 검증값 기본 세팅 (`core/presets.py`)

유튜브 자동 제작 관리자(`admin\MANUAL.html`)에서 가져왔다.

> 모든 설정 탭 맨 위에는 ☑ 기본 세팅(검증값) 사용 체크가 있습니다.
> 초록이면 지금 값이 검증된 기본값과 같고, 노랑이면 사장님이 바꾼 상태입니다.

설정을 만지다 보면 어디를 건드렸는지 잊는다. 그러면 이상해졌을 때 원인을 못
찾고 결국 "처음부터 다시" 가 된다. **파는 물건에서 이 일이 나면 그날로 환불이다.**

되돌리기가 한 번에 되면 사람이 겁내지 않고 만져 본다. 만져 봐야 자기 것이 된다.

## 16종이 공유하는 여섯 탭

상품이 자기 탭을 몇 개 만들든 **마지막 여섯 자리는 항상 같다.**

| 탭 | 무엇 | 누가 보나 |
|---|---|---|
| ✋ 손으로 할 일 | 프로그램이 대신 못 하는 일과 **그 이유** | 둘 다 |
| 🕒 자동 실행 | 정해진 시각에 도는 일 | 둘 다 |
| 🔑 접속키 | 1차키·2차키 발급과 회수 | 관리자만 |
| ⚙️ 기본 세팅 | 지금 값이 검증값과 같은지 | 관리자만 |
| 🛟 문제 해결 | 증상 → 조치 | 둘 다 |
| 📁 파일 위치 | 무엇이 어디에 | 관리자만 |

16종을 번갈아 쓰는 사람이 매번 다른 곳을 뒤지지 않게, **자리를 외우게 하는
편이** 예쁘게 배치하는 것보다 낫다.

**앞쪽 탭은 상품마다 전부 다르다.** 공인중개사는 문항 채우기·과목별 성적·약한
단원이고, 유튜브는 기획 수치·견적·줄이기·시니어 규격이고, 블로그는 키워드
수요·초안 채우기·대가 표시다. 참조한 관리자에서 빌린 것은 **문법**(왼쪽 탭,
상태 타일, 오늘 할 일, 손으로 할 일 표)이지 **내용**이 아니다.
