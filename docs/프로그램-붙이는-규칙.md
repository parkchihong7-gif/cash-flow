# 프로그램을 하나씩 붙일 때 지킬 것

> **왜 이 문서가 있나.** 2개를 붙이는 중에 3번 DB 가 깨져 초기화했다.
> 원인은 통합보드가 무거워서가 아니라, 3번이 제 살림을 잘못 챙겨서였다.
> 16개가 되면 기억으로는 못 지킨다. 적어 둔다.

---

## 1. 통합보드가 들고 있는 것 / 안 들고 있는 것

| 통합보드에 있다 | 통합보드에 **없다** |
|---|---|
| 누구에게 무엇을 팔았나 (회원·라이선스) | 프로그램이 만든 글·이미지·문제 |
| 접속키와 지금 접속 중인 기기 | 프로그램의 설정 파일·로그인 정보 |
| 언제 돌렸고 잘 됐나 (최근 것만) | 프로그램의 DB |

**프로그램 자료는 한 줄도 안 들어옵니다.** 그래서 프로그램이 16개가 되어도
통합보드는 거의 안 커집니다 (지금 **100KB**).

무거워지는 것이 걱정되어 구조를 바꾸실 필요가 없습니다. 이미 그 구조입니다.

## 2. 프로그램 하나 = 제 자리에서 제 살림

```
통합보드 ──(주소만 들고 있음)──▶  1번  github.io/...
                              ▶  3번  maim-...run.app
```

`program.yaml` 의 `live.admin` / `live.client` 에 주소를 적으면 [프로그램
열기 ↗] 가 그쪽으로 보냅니다. **통합보드는 주소를 들고 있을 뿐입니다.**

주소가 없으면 통합보드가 제 문(`/c/<id>`)을 내줍니다. 2번이 지금 그 상태입니다.

## 3. 버킷 — 한 칸에 하나

한 버킷을 여러 프로그램이 나눠 씁니다. **제 칸 밖은 한 글자도 건드리지
않습니다.**

```
gs://<버킷>/
  cash-flow/     통합보드 몫    (GCS_PREFIX=cash-flow)
  app.db         3번 몫
  home/          3번 몫 (Claude 로그인)
  generated/     3번 몫 (만든 이미지)
```

**한 번 데였습니다.** 3번이 「`generated/` 빼고 전부」를 제 것으로 알고
`cash-flow/` 까지 60초마다 덮어쓰고 있었습니다. 통합보드가 글을 쓰는 중에
덮였으면 그때 이쪽 DB 도 깨졌을 것입니다.

새 프로그램을 붙이실 때 이것만 확인하세요.

- [ ] 제 칸(접두사)이 정해져 있나
- [ ] 남의 칸을 읽거나 쓰지 않나
- [ ] 버킷 전체를 훑는 코드가 없나

## 4. DB 를 버킷에 올릴 때 — **파일을 그냥 올리지 않는다**

SQLite 가 글을 쓰는 중에 파일을 바이트째 뜨면 **반쯤 쓰인 판**이 올라갑니다.
다음에 그걸 내려받은 판은 읽기는 되는데 쓰려고만 하면 죽습니다.

```
database disk image is malformed
```

3번이 그렇게 깨졌고, **통합보드도 같은 코드였습니다**(2026-09-22 고침).

지켜야 할 두 가지.

1. `backup()` 으로 **앞뒤 맞는 한 벌**을 떠서 올린다
2. 떠 놓고 검사해서 **깨졌으면 올리지 않는다** — 버킷의 성한 판을 덮으면
   되살릴 길이 사라진다

## 5. 램디스크를 아껴 쓴다

Cloud Run 의 `/tmp` 는 디스크가 아니라 **컨테이너 메모리를 깎아 쓰는
램디스크**입니다. 시작할 때 버킷에서 푸는 양이 통째로 메모리에서 빠집니다.

3번이 512Mi 안에서 102MB 를 풀다가 깨졌습니다.

- [ ] 메모리는 **2Gi** 로 (쓴 시간만큼만 과금됩니다)
- [ ] 시작할 때 꼭 필요한 것만 내려받나 (이미지·백업은 빼고)
- [ ] 파일을 한꺼번에 수백 개씩 주고받지 않나 (8개씩 나눠서)

## 6. 무한히 쌓이는 것을 만들지 않는다

실행 로그 한 번이 2만 자입니다. 천 번이면 20MB 고, 그것이 60초마다 통째로
올라갑니다.

통합보드는 **프로그램마다** 최근 20개만 로그를 남기고, 200개가 넘으면 줄까지
지웁니다(`core.db.LOG_KEEP` / `ROW_KEEP`). 천 번을 돌려도 **0.5MB** 입니다.

새 프로그램에도 같은 잣대를 대세요 — **"1년 뒤에 이것이 몇 줄인가"** 를
만들 때 한 번 물어보시면 됩니다.

## 7. 다 되기 전에는 붙이지 않는다

`program.yaml` 의 `paused` 에 이유를 적으면 **실행이 막힙니다.** 지금
4~16번이 그 상태입니다.

```yaml
paused: 아직 만드는 중입니다
```

다 되면 그 줄을 지웁니다. **덜 된 것을 붙여 놓고 "나중에 고치지" 하지
마세요** — 그 나중이 오늘 같은 날입니다.

## 8. 새 프로그램 붙이는 차례

1. 프로그램을 **제 저장소에서** 완성하고 제 자리에 배포한다
2. `products/<이름>/program.yaml` 을 만든다 (`paused` 를 적은 채로)
3. `live.admin` / `live.client` 에 주소를 적는다
4. 위 3~6번 항목을 확인한다
5. `paused` 를 지우고 통합보드를 올린다
6. 접속키를 하나 발급해 **끝까지 들어가 본다**

6번을 건너뛰지 마세요. 오늘 하루가 그것 때문이었습니다.
