### 유튜브가 클라우드를 버린 이유

문서에 숫자가 있습니다.

| | 전환 전 | 전환 후 |
|---|---|---|
| 구조 | Make + Cloud Run + Gemini 이미지 API | 집 PC 로컬 파이프라인 |

**→ "클라우드가 비싸다" 가 아니라 "이미지 생성 API 가 비쌌다" 입니다.**
우리 1번은 이미지를 만들지 않으므로 그 문제가 없습니다.

## 3. 요청 수 이야기 — "월 200만 건" 이 무슨 말인가

**요청 = 브라우저가 서버에 한 번 물어보는 것**입니다.
화면 하나 여는 게 1건이 아니라 여러 건입니다.

| 행동 | 요청 수 |
|---|---|
| 화면 하나 열기 (HTML + CSS + JS) | 약 **3건** |
| 탭 다섯 개 눌러 보기 | 약 **15건** |
| 하루 종일 만지기 | 약 **300~500건** |
| 한 달 내내 혼자 쓰기 | 약 **1만~1.5만건** |

**무료 한도가 월 200만 건이니 1% 도 안 씁니다.**

돈이 나가는 곳은 요청 수가 아니라 따로입니다.

| 항목 | 언제 |
|---|---|
| **최소 인스턴스 ≥ 1** | 안 잠들고 계속 켜 둘 때. **여기가 제일 큽니다** |
| **이미지·영상 생성 API** | 유튜브가 겪은 그것 — 편당 ₩3,200 |
| Cloud SQL | 관리형 DB 를 붙일 때 |
| 나가는 데이터 | 큰 파일을 계속 내보낼 때 |

maim 은 최소 인스턴스 0 이라 안 쓸 때 요금이 안 붙고, 1번도 같게 두면 됩니다.

## 4. 이미 같은 규격입니다 — 접속키

**maim 의 접속 코드가 우리 이중키와 구조가 같습니다.**

| | maim | 이 저장소 (`core/keyauth.py`) |
|---|---|---|
| 1차 | 초대 코드 (1회용) | 1차키 (사람) |
| 2차 | **기기별 PC/노트북/휴대폰 3개** | **2차키 PC/노트북/휴대폰 3개** |
| 세션 | 2차 코드만 로그인 발급 | 2차키가 기기 하나 = 세션 하나 |
| 중복 | 원자적 SQL 로 딱 하나만 성공 | 중복 로그인 시 먼저 기기 잠금 |
| 마스터 | 영구 고정 토큰 | 관리자 비밀번호 |

우연이 아닙니다 — `core/keyauth.py` 는 두 프로그램의 매뉴얼에서 규격을
가져와 만들었습니다(`docs/unify-existing.md`). **셋을 한 장부로 묶을 수 있습니다.**

## 5. maim 이 Cloud Run 에서 겪은 것 — 1번도 그대로 겪습니다

사장님 문서의 트러블슈팅 표가 **그대로 우리 일**입니다. 미리 알고 가면
같은 데서 안 넘어집니다.

| maim 이 겪은 것 | 1번에도 해당? | 미리 할 일 |
|---|---|---|
| 요청 제한 5분에 걸려 실패 | △ 연결 확인은 15초라 여유 | `--timeout` 은 기본값으로 충분 |
| **시작 시 버킷 전체를 받다가 시작 제한 초과** | **○** | DB 하나만 받게. 산출물은 지연 로딩 |
| **GCS FUSE 위 SQLite 불안정** | **○ 우리도 SQLite** | 로컬 디스크 + 버킷 동기화 (maim 과 같게) |
| 토큰 게이트가 정적 파일까지 막음 | ○ | `/static` 을 접속 코드에서 빼기 (이미 그렇습니다) |
| 환경변수가 `YOUR_...` 자리표시자로 남음 | ○ | 배포 전 점검 목록 |

`Dockerfile` 은 이미 저장소에 있고 Cloud Run 규격에 맞습니다
(`PORT` 를 호스팅이 주는 대로 씀, `/healthz` 로 살았는지 확인).
**고칠 곳은 하나 — `/app/data` 를 GCS 와 맞추는 것**입니다.

## 6. 회사에서 고칠 때 — 매일 저녁 자동 맞추기

집에서 주로 하시고 가끔 회사에서 고치신다고 하셨습니다.
**두 프로그램 모두 이미 예약 실행을 쓰고 계십니다** — 같은 방식이면 됩니다.

| | 하는 일 | 어디서 | 이미 쓰고 계신 것 |
|---|---|---|---|
| GitHub Actions 예약 | 매일 20:00 웹주소 다시 올림 | GitHub (무료) | — |
| 집 PC 작업 스케줄러 | 매일 20:00 `git pull` | 집 PC | **유튜브가 22:00 에 이 방식** |
| Cloud Scheduler | Cloud Run 을 깨움 | GCP (작업 3개 무료) | **maim 이 06:00 에 이 방식** |

지금 워크플로는 **푸시할 때만** 돕니다. 여기에
`cron: "0 11 * * *"` (한국 시각 20:00) 을 더하면 됩니다.

## 7. 지금 막아 둔 것

**4번부터 16번까지 실행을 막았습니다.** 손보는 중에 실수로 돌아가
산출물이 덮이거나 바깥 API 를 부르는 일을 막기 위해서입니다.

- 열람·매뉴얼은 그대로 보입니다
- 실행·테스트만 거부합니다. 화면에서 감추는 것이 아니라 **서버에서 막습니다**
  (`core/runner.py`) — 주소를 직접 치거나 예약이 불러도 안 돕니다
- 막힌 프로그램도 **코드가 멀쩡한지는 계속 시험합니다**.
  막았다고 시험까지 끄면 나중에 풀었을 때 깨진 것을 모릅니다
- 푸는 법: `products/<이름>/program.yaml` 의 `paused:` 줄을 지우면 됩니다

1·2·3번은 쓰고 계셔서 막지 않았습니다.
