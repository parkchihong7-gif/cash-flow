# 이미 돌아가고 있는 두 프로그램을 같은 키 체계로 묶으려면

지금 두 프로그램이 **각자의 서버에서, 각자의 키로** 돌아갑니다.

| 프로그램 | 어디서 도나 | 키를 어디에 두나 |
|---|---|---|
| 공인중개사 기출문제 대시보드 | GitHub Pages + Apps Script | Google 시트 `공인중개사_접속키_DB` |
| maim 네이버 블로그 | Cloud Run + GCS | GCS |
| **이 저장소의 16종** | 아직 내 컴퓨터 | `data/dashboard.db` |

세 군데에 키가 흩어져 있으면, 고객 한 명을 정지시킬 때 세 군데를 들어가야 합니다.
사람이 늘면 반드시 빠뜨립니다.

## 규격은 이미 맞춰 두었습니다

`core/keyauth.py` 는 **두 프로그램의 관리자 매뉴얼에서 규격을 그대로 가져왔습니다.**
1차키·2차키, 기기당 한 세션, 중복 로그인 시 기존 기기 잠금, 사용중지/삭제/초기화의
확인 단계까지 같습니다. 그래서 고객에게 이미 보내신 안내문을 고치지 않아도 됩니다.

남은 것은 **어디에 둘지** 하나입니다.

## 제가 할 수 있는 것과 없는 것

제가 할 수 있는 것은 여기까지입니다.

- 16종 공통 이중키 모듈과 발급 화면 (**끝났습니다**)
- 키를 확인해 주는 API 를 이 대시보드에 여는 것
- 두 외부 프로그램이 그 API 를 부르도록 고치는 코드

할 수 없는 것은 이것입니다.

- **대시보드를 인터넷에 올리는 것.** 외부에서 부를 주소가 있어야 하는데,
  지금은 사장님 컴퓨터에서만 돕니다
- Apps Script 와 Cloud Run 에 배포하는 것. 그 계정의 권한이 필요합니다

## 순서

**1. 대시보드를 올립니다.** `render.yaml` 이 이미 있어서 Render 에 붙이면 됩니다
(README 의 '항상 켜 두기'). 주소가 생깁니다 — `https://….onrender.com`.

**2. 그 주소를 알려 주시면** 키 확인 API 를 열고, 두 프로그램이 그걸 부르도록
고쳐 드리겠습니다. 그때부터 키 발급·정지·삭제가 **이 대시보드 한 군데**에서 됩니다.

**3. 기존 키는 옮깁니다.** 이미 뿌리신 키를 못 쓰게 하면 고객이 다시 연락해야
합니다. Google 시트의 키를 그대로 `레거시` 로 넣어 두면 계속 통합니다 —
`레거시 단일키` 가 그래서 있습니다.

## 지금 당장 하실 수 있는 것

올리지 않으셔도 **16종은 이미 이 규격으로 돕니다.** 새로 파시는 프로그램부터
여기서 키를 발급하시면 되고, 기존 둘은 그대로 두셨다가 나중에 묶으셔도 됩니다.

굳이 서두를 이유는 이것 하나입니다 — **고객이 늘어난 뒤에 옮기면 더 번거롭습니다.**
