# 클라우드에 올려 진짜로 쓰기

확인용 웹주소(GitHub Pages)와 **다른 것**입니다. 헷갈리시면 아래 표부터 보세요.

| | 확인용 웹주소 | 클라우드 대시보드 |
|---|---|---|
| 주소 | `parkchihong7-gif.github.io/cash-flow` | `내주소.onrender.com` |
| 정체 | 화면을 떠 온 **사진** | **진짜로 도는 프로그램** |
| 키 발급 | **안 됩니다** | 됩니다 |
| 고객이 키로 들어오기 | 안 됩니다 | 됩니다 (`/c/<프로그램>`) |
| 저장·실행 | 안 됩니다 | 됩니다 |
| 돈 | 무료 | 디스크를 붙이려면 유료 |

확인용 주소에서 키 발급이 안 되는 것은 고장이 아닙니다. GitHub Pages 는
파일만 내어 주는 곳이라 파이썬이 돌지 않고, 키 발급은 `dashboard.db` 에
**쓰는** 동작이라 저장할 자리 자체가 없습니다.

---

## 1. 올리기

1. [render.com](https://render.com) 에 가입합니다.
2. **New → Blueprint** 에서 이 저장소를 고릅니다.
   저장소의 `render.yaml` 을 알아서 읽습니다.
3. 물어보는 값을 채웁니다.

   | 값 | 무엇 |
   |---|---|
   | `DASHBOARD_ACCESS_CODE` | 사장님만 아는 접속 코드. **저장소에 적지 마세요** |
   | `ANTHROPIC_API_KEY` | 없어도 올라갑니다. 없으면 모의 실행만 됩니다 |

   `DASHBOARD_SECRET` 은 Render 가 만들어 줍니다. 손대지 마세요.
   이 값이 바뀌면 열려 있던 창이 전부 로그아웃됩니다.

4. **디스크를 꼭 확인하세요.** `render.yaml` 에 `/app/data` 로 1GB 를
   붙이게 적어 두었습니다. **이게 안 붙으면 다시 배포할 때마다 고객
   정보와 발급한 키가 지워집니다.** 디스크는 유료 플랜에서만 붙습니다.

5. 초록불이 들어오면 주소가 나옵니다. 접속 코드를 넣고 들어가 보세요.

### 가지(branch) 주의

이 저장소에는 지금 `claude/new-session-9lqy1t` 하나뿐이고, `render.yaml`
도 그렇게 적혀 있습니다. 나중에 `main` 으로 옮기시면 `render.yaml` 의
`branch:` 도 같이 바꾸셔야 합니다. 안 바꾸면 옛 코드가 계속 올라갑니다.

---

## 2. 고객에게 주는 주소

발급 화면이 안내문을 만들어 줄 때 이미 이 주소가 들어갑니다.

```
https://내주소.onrender.com/c/<프로그램>
```

이 주소에는 **대시보드 접속 코드가 필요 없습니다.** 키만 있으면 열립니다.
관리자용 주소(`/apps/...`)를 고객에게 보내면 고객은 들어오지 못합니다.

---

## 3. 집 컴퓨터로 백업받기 — 꼭 해 두세요

클라우드에 올리면 고객 이름·이메일·발급한 키가 **전부 거기에만** 있습니다.
호스팅 계정이 잠기거나 요금을 못 내거나 디스크를 잘못 지우면 판 키의
목록이 통째로 사라집니다.

### 처음 한 번

`tools/home/클라우드주소.txt` 를 메모장으로 만들고 두 줄을 적습니다.

```
https://내주소.onrender.com
접속 코드
```

이 파일은 저장소에 올라가지 않습니다(`.gitignore` 에 넣어 두었습니다).

### 받을 때마다

`tools/home/클라우드_백업받기.bat` 을 누릅니다.
`data\backup\dashboard-날짜-시각.db` 로 저장됩니다. 날짜가 붙어서
어제 것이 덮어써지지 않습니다.

바탕화면에 바로가기를 만들어 두고 **일주일에 한 번**쯤 누르시면 됩니다.

### 되살릴 때

1. 대시보드를 끕니다.
2. `data\backup\` 의 파일을 `data\dashboard.db` 로 덮어씁니다.
3. 다시 켭니다.

### 받은 파일이 DB 가 아닐 때

접속 코드가 틀리면 로그인 화면(HTML)이 내려옵니다. `.bat` 이 그것을
알아채고 지운 뒤 알려 줍니다. `클라우드주소.txt` 의 둘째 줄을 보세요.

---

## 4. 올리기 전에 한 번씩 볼 것

- [ ] `DASHBOARD_ACCESS_CODE` 를 Render 화면에서 넣었고, **저장소에는 없다**
- [ ] 디스크가 `/app/data` 에 붙었다
- [ ] `render.yaml` 의 `branch:` 가 지금 쓰는 가지와 같다
- [ ] 들어가 보고 접속 코드 없이는 안 열리는 것을 확인했다
- [ ] 키를 한 개 발급해 보고, `/c/<프로그램>` 에서 그 키로 들어가 봤다
- [ ] `클라우드_백업받기.bat` 을 한 번 눌러 파일이 생기는 것을 봤다

---

## 5. 자주 나오는 것

**접속 코드를 잊었습니다**
Render → 서비스 → Environment 에서 `DASHBOARD_ACCESS_CODE` 를 바꾸고
다시 배포하면 됩니다. 고객 자료는 디스크에 있어 지워지지 않습니다.

**고객이 "키가 안 먹는다" 고 합니다**
2차키는 기기당 한 세션입니다. 같은 2차키로 다른 기기에서 들어오면
먼저 있던 기기가 잠깁니다. 기기가 셋이면 2차키도 셋을 쓰셔야 합니다.

**확인용 웹주소도 계속 쓰나요**
쓰셔도 됩니다. 화면 구성을 남에게 보여 드릴 때 편합니다. 다만 거기서는
아무것도 저장되지 않는다는 것만 기억하세요.
