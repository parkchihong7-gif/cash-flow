# 관리자 매뉴얼

> 이 대시보드를 **운영하는 사람**을 위한 문서입니다.
> 컴퓨터를 잘 모르셔도 따라 할 수 있도록 하나하나 적었습니다.
> 구매자에게 줄 문서는 [클라이언트 매뉴얼](/manual/client) 입니다.

---

## 1장. 이 대시보드가 무엇인가

프로그램을 여러 개 만들다 보면 이런 문제가 생깁니다.

- 어떤 프로그램이 있었는지 기억나지 않는다
- 각각 어떻게 실행하는지 매번 찾아봐야 한다
- 설정을 바꾸려면 어느 파일을 열어야 하는지 모른다
- 누가 무엇을 샀는지 엑셀에 따로 적어둔다

이 대시보드는 그걸 한 화면에 모읍니다. **터미널을 몰라도 프로그램을 쓸 수 있게** 하는 것이 목적입니다.

### 화면 구성

| 화면 | 하는 일 |
|---|---|
| **홈** | **오늘 볼 것**, 현황 숫자, 매출 추이, 프로그램 목록 |
| **검색** | 프로그램·매뉴얼·설정·고객을 한 칸에서 찾기 (`/` 키) |
| **프로그램 → 열람** | 그 프로그램이 뭘 하는지, 어떤 순서로 쓰는지, FAQ |
| **프로그램 → 수정** | 설정값 바꾸기, 프롬프트·템플릿 파일 직접 편집 |
| **프로그램 → 테스트** | 브라우저에서 바로 실행하고 결과 확인 |
| **프로그램 → 회원관리** | 이 프로그램을 산 고객 목록 |
| **실행 이력** | 전체 실행을 프로그램·결과·방식으로 걸러 보기 |
| **회원관리** | 전체 고객, 라이선스 발급, 응대 기록 |
| **기타 설정** | API 키 상태, 기본 모델, 금지 문구 목록 |
| **매뉴얼** | 지금 보고 계신 문서와 클라이언트용 문서 |

## 1.5장. 홈 화면 읽는 법

프로그램이 여러 개가 되면서 홈이 바뀌었습니다. 위에서부터 이 순서로 보시면 됩니다.

### 오늘 볼 것 — 맨 위

대시보드가 **직접 찾아서** 올려 주는 목록입니다. 찾아 들어가지 않아도 보입니다.

| 색 | 뜻 | 예 |
|---|---|---|
| 빨강 | 지금 손봐야 합니다 | 실패한 실행, 기한이 지난 이용권 |
| 노랑 | 곧 문제가 됩니다 | 30일 안에 끝나는 이용권, 검증에 걸린 실행 |
| 파랑 | 알아 두시면 됩니다 | 아직 안 돌려 본 프로그램, API 키 없음 |

**할 일이 없으면 이 칸이 통째로 사라집니다.** "확인할 것이 없습니다" 한 줄만 남습니다.
늘 떠 있는 경고는 며칠 지나면 안 보게 되기 때문에, 있을 때만 띄웁니다.

특히 **기한이 지난 이용권**은 꼭 처리하세요. '유효' 로 남아 있으면
누적 결제액과 월 리테이너가 실제보다 크게 나옵니다. 내 매출을 내가 잘못 알게 됩니다.

### 매출 추이 — 가운데

최근 12개월 매출입니다. 결제일(라이선스 발급일) 기준이고, **환불한 건은 뺐습니다.**
만료된 건은 돈을 돌려준 것이 아니므로 그대로 둡니다.

막대에 마우스를 올리면 그달 건수가 나옵니다. 0원인 달도 자리를 비워 두는데,
빈 달을 건너뛰면 추이가 실제보다 좋아 보이기 때문입니다.

아래 **프로그램별 매출**은 어느 상품이 실제로 팔리는지 보여 줍니다.
만들 때 들인 시간과 견주어 보세요. 다음에 뭘 만들지 정하는 데 도움이 됩니다.

> 그래프는 인터넷 없이도 그려집니다. 라이브러리를 받아 오지 않고
> 서버에서 직접 그리기 때문입니다.

### 프로그램 카드 — 아래

카드마다 **마지막 실행**이 붙습니다. 언제 돌렸고 성공했는지가 한눈에 보입니다.
"아직 한 번도 안 돌렸습니다" 가 보이면 모의 실행을 한 번 해 보세요. 비용이 들지 않습니다.

## 1.6장. 검색과 실행 이력

### 검색 — `/` 키

왼쪽 위 검색칸입니다. **키보드에서 `/` 를 누르면 바로 커서가 갑니다.**

찾는 범위가 넓습니다.

- 프로그램 이름·설명·**이용 순서·FAQ**
- **매뉴얼 본문 전체** (관리자용·고객용 18개)
- 설정 항목과 편집 가능한 파일
- 고객 이름·이메일·유입 경로

매뉴얼 본문까지 찾기 때문에 "이탈률을 어디서 설명했더라" 같은 것이 바로 나옵니다.
찾은 자리의 앞뒤 문장도 함께 보여 주므로, 열어 보기 전에 맞는지 알 수 있습니다.

색인을 따로 만들어 두지 않습니다. **파일을 고치면 바로 반영됩니다.**

### 실행 이력

홈에는 최근 5건만 나옵니다. 전체를 보시려면 왼쪽 **실행 이력**입니다.

프로그램별·결과별·방식별로 거를 수 있습니다. 가장 많이 쓰시게 될 것은
**결과 = 실패**입니다. 홈의 '오늘 볼 것' 에서 "실패만 보기" 를 누르면 바로 이 화면입니다.

### 휴대폰에서

화면이 좁으면 왼쪽 메뉴가 접힙니다. 위쪽 **☰ 메뉴**를 누르면 펼쳐집니다.
프로그램이 열두 개라 늘 펼쳐 두면 본문이 한참 아래로 밀리기 때문입니다.

## 1.62장. 권한·환경 — 오늘 바로 되는 것과 기다려야 하는 것

왼쪽 **🔑 권한·환경**입니다. 프로그램마다 **쓰기 전에 무엇이 필요한지**를
한 장에 모았습니다.

### 돈보다 자주 발목을 잡는 것은 기다리는 시간입니다

카드는 바로 긁히지만 **API 심사는 못 당깁니다.** 유튜브 업로드 감사처럼
며칠에서 몇 주가 걸리는 것이 있습니다.

이걸 모르고 "설치만 하면 바로 씁니다" 라고 팔면 환불로 돌아옵니다.
사기까지는 아니어도 신뢰는 거기서 끝납니다. 그래서 화면이 네 갈래로 나눕니다.

| 표시 | 뜻 | 상세페이지에 쓸 말 |
|---|---|---|
| **지금 바로** | 가입도 설치도 없이 내려받아 바로 돕니다 | "계정 없이 바로 쓰십니다" |
| **준비 먼저** | 계정을 만들거나 프로그램을 깔아야 합니다 | "무료 계정 하나만 만드시면 됩니다" |
| **심사를 기다려야** | 신청하고 답을 받아야 합니다 | **"승인에 며칠~몇 주 걸립니다"** |
| **집 컴퓨터로는 어려움** | 서버나 별도 장비가 필요합니다 | "월 5천 원대 서버가 필요합니다" |

세 번째 줄을 **상세페이지 맨 위에** 쓰세요. 안 쓰면 환불입니다.

### 지금 어떤 상태인가

| 프로그램 | 어떤가 |
|---|---|
| 11번 자동화 대행 키트 | 카카오 오픈빌더·인스타 권한 검수가 **심사 필요** |
| 14번 시니어 영상 | 유튜브 API 감사가 **심사 필요** (견적만 낼 거면 바로 됩니다) |
| 나머지 14종 | 대부분 **지금 바로** |

### 키가 들어갔는지도 같이 봅니다

계정마다 `.env` 키 이름이 붙어 있고, 값이 들어갔는지를 **넣었습니다 /
아직 안 넣었습니다** 로만 보여 줍니다.

**값은 절대 화면에 띄우지 않습니다.** 대시보드는 터널로도 열 수 있고,
화면은 어깨너머로도 보입니다. 설정 한눈에와 같은 원칙입니다.

### 상담에서 쓰는 법

고객과 이 화면을 **같이 보세요.** 특히 심사가 걸린 상품이면 계약 전에
보여 드리는 편이 낫습니다. 기다려야 한다는 걸 미리 알면 불만이 안 생기고,
오히려 "이런 것까지 챙겨 주는구나" 가 됩니다.

### 새 프로그램을 만들 때

`program.yaml` 의 `requirements:` 에 적습니다. 5장에 서식이 있습니다.
**계정마다 `why`(왜 필요한지)와 `how`(어디서 받는지)를 꼭 채우세요.**
비어 있으면 테스트가 잡습니다.

## 1.63장. 정기 실행 — 안 돌린 날을 화면이 기억합니다

왼쪽 **🗓 정기 실행**입니다. 프로그램이 열두 개가 되면서 성격이 둘로 갈렸습니다.

| | 한 번 만들고 끝 | 되풀이해 돌려야 하는 것 |
|---|---|---|
| 예 | 퍼널·전자책·강의 슬라이드·상세페이지 | 12번 니치 리서치(매일), 11번 주간 보고서(매주) |
| 안 돌리면 | 아무 일도 안 생깁니다 | **조용히 망가집니다** |

### 왜 따로 화면을 뒀나

12번 니치 리서치를 사흘 빼먹으면 **그 사흘은 영영 빈 칸으로 남습니다.**
유튜브 API 는 지난 날의 값을 돌려주지 않기 때문입니다. 그런데 이건 화면에
빨간 줄이 뜨지 않으면 아무도 모릅니다. 두 달 뒤에 보고서를 열고 나서야
"어, 왜 이렇게 듬성듬성하지" 하게 됩니다.

### 화면 읽는 법

| 표시 | 뜻 | 하실 일 |
|---|---|---|
| **밀렸습니다** | 정한 주기를 넘겼습니다 | cron 이 살아 있는지 보시고, 명령 줄을 복사해 한 번 돌리세요 |
| 아직 한 번도 | 등록만 되고 아직 안 돌았습니다 | 처음 한 번은 손으로 돌려 보세요 |
| 제때 돌고 있습니다 | 주기 안에 돌았습니다 | 없습니다 |
| 필요할 때 | 되풀이할 일이 아닙니다 | 없습니다. 안 돌렸다고 밀린 게 아닙니다 |

각 카드에 **크론 한 줄**이 있습니다. 그대로 복사해서 `crontab -e` 에 붙이면 됩니다.

### 이 화면은 프로그램을 돌리지 않습니다

일부러 그렇게 했습니다. 실제로 돌리는 것은 cron 이나 n8n 이고, **대시보드는
꺼져 있을 수 있습니다.** 실행을 이 화면에 두면 대시보드를 안 켠 날이 그대로
빈 칸이 됩니다. 화면은 "밀렸는지" 만 봅니다.

### 시각은 새벽으로 두세요

유튜브 API 쿼터는 태평양 시간 자정에 초기화됩니다. 낮에 자동 실행을 걸어 두면
손으로 돌린 것과 겹쳐 쿼터를 두 번 씁니다. 새벽 6시쯤이 무난합니다.

### 마지막 실행은 어디서 오나

대시보드의 '테스트' 탭으로 돌린 기록입니다. **cron 으로만 돌리시면 여기에
안 잡힙니다.** 그럴 때는 각 프로그램의 로그 파일(`collect.log` 등)을 보세요.
이 화면이 "아직 한 번도" 라고 해도 cron 은 잘 돌고 있을 수 있습니다.

## 1.65장. 수입 현황

왼쪽 **💰 수입 현황**입니다. **한 번 받는 돈**과 **매달 들어오는 돈**을 나눠 봅니다.

11번 자동화 대행 납품 키트부터는 월 유지비(리테이너)가 생깁니다. 이 둘은
성격이 아주 다릅니다.

| | 일회성 | 월 유지비 |
|---|---|---|
| 다음 달에도 들어오나 | 아니요 | 예 |
| 매달 새 고객이 필요한가 | **예** | 아니요 |
| 한 건의 값어치 | 그때 한 번 | 12개월 × 그 금액 |

### 보셔야 할 숫자는 '고정 수입 비중' 입니다

연 환산 고정 수입이 전체에서 몇 %인지입니다. 이게 올라갈수록 매달 새 고객을
찾아야 하는 압박이 줄어듭니다.

판매는 있는데 유지비가 한 건도 없으면 화면이 알려 줍니다.

### 곧 끝나는 이용권

만료 30일 전부터 보입니다. **연장 안내는 만료 2주 전이 가장 잘 먹힙니다.**
지나고 나서 연락하면 이미 마음이 떠나 있습니다.

### 이 숫자는 등록한 것만 셉니다

회원관리에 넣지 않은 거래는 여기 없습니다. 세무 자료가 아니라
*지금 어디에 서 있는지* 보는 화면입니다.

## 1.7장. 설정 한눈에

왼쪽 **🗂 설정 한눈에**입니다. 프로그램마다 흩어져 있는 것을 한 장에 모았습니다.

| 칸 | 무엇이 보입니까 |
|---|---|
| 환경변수 | `.env` 의 키가 채워져 있는지 — **설정됨 / 비어 있음**만 |
| 공통 설정 | 기본 모델·AI 표시·상호·환불 문구 |
| 프로그램별 | 설정값(지금 값과 기본값), 고칠 수 있는 파일, 매뉴얼 |

### 여기서는 못 고칩니다 — 일부러 그렇게 두었습니다

값을 바꾸는 곳은 **각 프로그램의 '수정' 탭**입니다. 한 화면에서 아홉 개를 다
고치게 만들면, 어느 프로그램을 건드리는지 모른 채 바꾸게 됩니다.

각 줄의 **고치기**를 누르면 그 프로그램 화면으로 갑니다.

### 세 가지를 눈여겨보세요

1. **굵게 표시된 값** — 기본값에서 바뀐 것입니다. "내가 이걸 바꿨었나" 를 여기서 봅니다
2. **빨간 띠** — `program.yaml` 이 가리키는 파일이 실제로 없다는 뜻입니다.
   경로를 잘못 적었거나 파일을 지운 것입니다
3. **비밀 딱지** — 토큰·키·코드는 값을 보여 주지 않습니다.
   이 화면은 터널로 열 수 있고, 어깨너머로도 보입니다

## 1.75장. 규정 점검

왼쪽 **⚖️ 규정 점검**입니다. CLAUDE.md §3 의 금지 사항이 프로그램마다
장치로 붙어 있는지 한 장에 모았습니다.

| 보는 것 | 근거 | 안 지키면 |
|---|---|---|
| AI 생성물 표시 | 인공지능기본법 제31조 | 최대 3,000만 원 과태료 |
| 과장 문구 검사 | 표시광고법 · 소비자원 주의보 | 분쟁 시 그대로 근거가 됩니다 |
| 대가성 문구 강제 | 공정위 심사지침 | 쿠팡파트너스 자격 정지(경고 없음) |
| 사람 검수 지점 | 유튜브 양산형 콘텐츠 정책 | 채널 제재 |
| 비공식 자동화 없음 | CLAUDE.md §3-7 | 계정 정지 · 고객 계정 위험 |

### 이 화면이 보는 것은 '장치가 있는지' 입니다

잘 도는지는 보지 않습니다. 그건 테스트가 하는 일입니다.
그래서 **무엇을 찾았는지**(어느 모듈을 부르는지)를 같이 적어 둡니다.

### `?` 는 잘못이 아닙니다

"확인 필요" 는 그 장치를 코드에서 못 찾았다는 뜻입니다. **그 상품에는 필요
없는 장치일 수도 있습니다.** 예를 들어 8번 수익 시뮬레이터는 Claude 를 아예
부르지 않아서, AI 생성물 표시를 붙이면 오히려 사실과 다릅니다.

보고 판단하시라고 `?` 로 두었지 자동으로 고치지 않습니다.

### `✗` 는 지금 보셔야 합니다

'비공식 자동화 없음' 은 **없어야 통과**인 규칙입니다. selenium·webdriver 같은
것이 코드에 들어오면 빨간불이 뜹니다. 그건 팔면 안 되는 상태입니다.

## 1.8장. 서버 없이 화면 보여 주기 — 정적 스냅샷

```bash
python -m dashboard.snapshot                    # dashboard-snapshot/ 에 만듭니다
python -m dashboard.snapshot --demo             # 모의 실행까지 돌려 산출물 화면도 담습니다
python -m dashboard.snapshot --single           # 화면 전부를 담은 HTML 파일 하나도
python -m dashboard.snapshot --out /경로 --zip  # 압축까지
```

`--single` 을 주면 `통합-관리자-대시보드.html` **파일 하나**가 같이 나옵니다(약 2.5MB).
폴더째 주고받기는 번거로우니, 메일에 붙이거나 메신저로 보낼 때는 이쪽을 쓰세요.
파일 하나만 있으면 열립니다.

대시보드 화면을 **통째로 떠서 HTML 파일 묶음**으로 만듭니다.
만들어진 `index.html` 을 브라우저로 열면 화면을 그대로 돌아다닐 수 있습니다.

### 언제 씁니까

- 노트북을 안 켜 둔 날에도 **메뉴·매뉴얼·설정값**을 봐야 할 때
- 파이썬이 없는 사람에게 보여 줄 때 (동업자, 외주, 가족)
- 크몽 문의에 "관리 화면이 어떻게 생겼나요" 하는 물음이 왔을 때

### 되는 것과 안 되는 것

| 된다 | 안 된다 |
|---|---|
| 화면 넘나들기 | 저장 |
| 매뉴얼 읽기 | 실행 |
| 설정값·FAQ 보기 | 검색 |
| 산출물 미리보기(`--demo`) | 로그인 |

**서버가 없기 때문입니다.** 그래서 모든 화면 위에 그렇다는 띠가 붙고,
눌러 봐야 소용없는 버튼은 아예 못 누르게 막아 둡니다.
눌러 보고 고장난 줄 아는 편이 더 나쁘기 때문입니다.

### 남에게 보내기 전에

기본값은 **빈 임시 DB** 로 뜹니다. 고객 이름·연락처가 찍히지 않습니다.
`--db` 로 실제 DB 를 주면 **고객 정보가 화면에 그대로 찍힙니다.** 그때는
받는 사람을 먼저 생각하세요.

토큰·API 키는 어느 경우에도 실리지 않습니다(설정됨/비어 있음만 보입니다).
다만 **직접 정한 접속 코드**는 매뉴얼 본문에 적어 두셨다면 같이 실립니다.
매뉴얼에 코드를 적지 마세요.

## 2장. 처음 한 번만 하는 준비

### 2-1. 프로그램 설치

명령 프롬프트(Windows) 또는 터미널(Mac)을 열고, 저장소 폴더로 이동한 뒤 한 줄을 실행합니다.

```
pip install -r requirements.txt
```

몇 분 걸립니다. 에러 없이 끝나면 성공입니다.

> **'pip' 을 찾을 수 없다고 나오면** 파이썬이 설치되지 않은 것입니다.
> https://www.python.org 에서 3.11 이상을 설치하고, 설치 화면에서
> "Add Python to PATH" 를 **반드시 체크**하세요.

### 2-2. Claude API 키 넣기

AI 를 쓰려면 키가 필요합니다. 없으면 모의 실행만 됩니다.

1. https://console.anthropic.com/settings/keys 에 접속해 로그인합니다
2. **Create Key** 를 누릅니다
3. `sk-ant-` 로 시작하는 긴 문자열이 나옵니다. **이 화면을 닫으면 다시 볼 수 없으니 복사**하세요
4. **Billing** 메뉴에서 카드를 등록하고 10달러 정도 충전합니다 (충전하지 않으면 키가 있어도 안 됩니다)
5. 저장소 맨 위 폴더에 있는 `.env.example` 파일을 복사해 `.env` 라는 이름으로 만듭니다
6. `.env` 를 메모장으로 열고 `ANTHROPIC_API_KEY=sk-ant-...` 줄에 키를 붙여넣고 저장합니다

> ⚠️ **`.env` 파일은 비밀번호와 같습니다.** 누구에게도 보내지 말고, GitHub 에 올리지 마세요.
> 유출되면 다른 사람이 쓴 요금이 내 카드로 청구됩니다.
> (이 프로젝트는 `.env` 를 자동으로 제외하도록 설정돼 있습니다.)

### 2-3. 대시보드 켜기

```
python -m dashboard
```

브라우저가 자동으로 열립니다. 안 열리면 주소창에 `http://127.0.0.1:8000` 을 직접 칩니다.

**끄는 법**: 터미널 창에서 `Ctrl + C` 를 누릅니다. 창을 닫아도 꺼집니다.

**확인**: 화면 위에 노란 경고("API 키가 설정되지 않았습니다")가 없으면 준비 완료입니다.

### 2-4. 접속 코드

대시보드는 코드를 넣어야 열립니다.

```
기본 접속 코드: redwind7
```

한 번 넣으면 **12시간** 동안 유지됩니다. 끊으려면 왼쪽 아래 **나가기** 를 누릅니다.

**코드 바꾸기** — `.env` 파일에 한 줄 넣고 대시보드를 다시 켭니다.

```
DASHBOARD_ACCESS_CODE=직접-정한-긴-코드
```

기본 코드를 쓰는 동안에는 화면 위에 노란 경고가 뜹니다. 내 PC 에서만 쓰신다면
그냥 두셔도 되지만, 인터넷에 여신다면 반드시 바꾸세요.

**코드를 잊었을 때** — `.env` 파일을 열어 보면 적혀 있습니다.
`.env` 에 없으면 기본값 `redwind7` 입니다.

## 2.5장. 밖에서도 접속하기

집 PC 에서만 쓰실 거라면 이 장은 건너뛰셔도 됩니다.
카페에서, 휴대폰에서, 사무실에서 열고 싶으실 때 보세요.

### 방법 ① 같은 공유기 안에서 (제일 간단)

집이나 사무실 와이파이에 같이 붙어 있는 기기에서만 열립니다.

```
python -m dashboard --host 0.0.0.0
```

그리고 다른 기기에서 `http://내PC주소:8000` 을 엽니다.
내 PC 주소는 윈도우는 `ipconfig`, 맥은 `ifconfig | grep inet` 으로 확인합니다.
보통 `192.168.` 로 시작합니다.

### 방법 ② 어디서나 — 임시 주소

인터넷 어디서나 닿는 https 주소를 잠깐 빌립니다. 가입도 카드도 필요 없습니다.

한 번만 설치합니다.

```
brew install cloudflared                        # macOS
winget install --id Cloudflare.cloudflared      # Windows
```

그다음부터는 이렇게 켭니다.

```
python -m dashboard --public
```

터미널에 주소가 뜹니다.

```
==========================================================
어디서나 접속:  https://아무글자-여기.trycloudflare.com
접속 코드:      redwind7
==========================================================
```

이 주소를 휴대폰에서 열면 그대로 대시보드가 나옵니다.

**알아 두실 것**

- **내 PC 가 켜져 있고 이 터미널 창이 떠 있는 동안만** 열립니다. 창을 닫으면 끊깁니다.
- **껐다 켜면 주소가 바뀝니다.** 매번 새 주소를 알려 줘야 합니다.
- 잠깐 보여 드리거나 외출 중에 확인하실 때 쓰기 좋습니다.

### 방법 ③ 늘 같은 주소로 — 클라우드에 올리기

내 PC 와 상관없이 항상 열려 있고 주소도 바뀌지 않습니다. 대신 월 이용료가 듭니다.

저장소에 `Dockerfile` 과 `render.yaml` 이 들어 있어서 Render(render.com) 기준으로는
이 순서면 됩니다.

1. 이 저장소를 GitHub 에 올립니다
2. render.com 에 가입 → **New → Blueprint** → 저장소를 고릅니다
3. 물어보는 값을 채웁니다
   - `DASHBOARD_ACCESS_CODE` — **꼭 바꾸세요**
   - `ANTHROPIC_API_KEY` — 없으면 모의 실행만 됩니다
4. 몇 분 뒤 `https://이름.onrender.com` 주소가 나옵니다

**알아 두실 것**

| | |
|---|---|
| 요금제 | `free` 로 바꾸면 15분 쉬면 잠들고, 다시 깨는 데 1분쯤 걸립니다 |
| 디스크 | `render.yaml` 의 `disk` 를 빼면 **배포할 때마다 고객 정보가 지워집니다** |
| 산출물 | 엑셀·리포트는 배포할 때 사라집니다. 다시 만들면 되는 것들입니다 |
| 파일 수정 | '수정' 탭에서 고친 내용도 배포하면 되돌아갑니다. 오래 남길 수정은 GitHub 에 올리세요 |

### 인터넷에 열기 전에 — 꼭 읽어 주세요

이 대시보드는 **접속 코드 하나로 전부를 엽니다.** 코드를 아는 사람은

- 고객 이름·연락처·주소를 전부 볼 수 있고
- 프로그램을 실제 실행할 수 있고 (API 요금이 나갑니다)
- `products/` 안의 파일을 고칠 수 있습니다

그래서 인터넷에 여신다면 아래를 지켜 주세요.

1. **접속 코드를 반드시 바꾸세요.** 길수록 좋습니다. 기억하기 쉬운 문장도 괜찮습니다.
2. **코드를 단톡방·메일에 그대로 올리지 마세요.** 한 번 퍼지면 회수할 방법이 없습니다.
3. **주소를 공개된 곳에 적지 마세요.** 코드가 있어도 주소가 안 알려지는 편이 안전합니다.
4. 코드가 샜다 싶으면 `.env` 의 `DASHBOARD_ACCESS_CODE` 와 `DASHBOARD_SECRET` 을
   함께 바꾸고 다시 켜세요. 열려 있던 창이 전부 끊깁니다.

코드를 **7번 틀리면 그 접속자는 10분 동안 잠깁니다.** 자동으로 코드를 찍어 보는
방법은 이것 때문에 통하지 않습니다.

## 3장. 프로그램 쓰기 — 기본 흐름

왼쪽 목록에서 프로그램을 누르면 탭 5개가 나옵니다. 왼쪽부터 순서대로 쓰면 됩니다.

### 3-1. 열람 탭 — 먼저 읽는 곳

- **개요**: 이 프로그램이 뭘 하는지
- **이용 순서**: 1번부터 차례로. 각 단계의 예상 소요 시간도 있습니다
- **산출물**: 어떤 파일이 나오고 각각 뭔지
- **FAQ**: 자주 나오는 질문
- **판매 플랜**: 얼마에 팔지

처음 쓰는 프로그램이라면 **이 탭을 끝까지 읽고 시작**하세요.

### 3-2. 수정 탭 — 설정과 파일 편집

**설정값**은 드롭다운이나 체크박스로 바꿉니다. 각 항목 아래 회색 설명이 있으니 읽어보세요.
바꾸고 **설정 저장**을 누르면 다음 실행부터 적용됩니다.

**파일 편집**은 프로그램의 중요 파일을 브라우저에서 직접 고치는 기능입니다.

> 💡 **저장하면 직전 내용이 자동으로 `.bak` 파일로 남습니다.** 잘못 고쳐도 되돌릴 수 있습니다.
> 되돌리려면 폴더에서 `파일명.bak` 의 내용을 복사해 다시 붙여넣으세요.

### 3-3. 테스트 탭 — 실행하는 곳

버튼이 두 개입니다. **차이를 꼭 알아두세요.**

| 버튼 | 비용 | 걸리는 시간 | 결과물 |
|---|---|---|---|
| **모의 실행** | 없음 | 몇 초 | 형태는 진짜, 내용은 예시 |
| **실제 실행** | 수백 원 | 2~5분 | 진짜 결과물 |

**처음에는 반드시 모의 실행부터** 하세요. 산출물이 어떤 모양인지 보고, 마음에 들면 실제 실행합니다.

실행이 끝나면 세 가지 중 하나가 나옵니다.

| 결과 | 뜻 | 할 일 |
|---|---|---|
| 🟢 **성공** | 다 만들어졌고 문제없음 | 산출물 보기 → 검토 |
| 🟡 **경고** | 만들어졌지만 금지 표현이 남음 | 어느 부분인지 로그를 보고 직접 수정 |
| 🔴 **실패** | 만들어지지 않음 | 로그를 읽고 6장 참고 |

**산출물 보기** 버튼을 누르면 파일 목록이 나오고, **열기** 를 누르면 브라우저에서 바로 볼 수 있습니다.
HTML 은 실제 페이지로, 마크다운은 읽기 좋게 보여줍니다.

### 3-4. 회원관리 탭 — 이 프로그램을 산 사람

누가 샀고 얼마를 냈고 언제까지 쓸 수 있는지 나옵니다. 등록은 5장에서 설명합니다.

### 3-5. 매뉴얼 탭

그 프로그램 전용 매뉴얼입니다. **클라이언트용**은 구매자에게 그대로 전달하세요.

## 4장. 고객이 생겼을 때

### 4-1. 고객 등록

**회원관리** → 아래 **고객 추가** 폼에 입력합니다.

- **이름, 이메일**: 필수
- **유입 경로**: "크몽", "인스타", "소개" 처럼 적어두면 나중에 어디서 손님이 오는지 알 수 있습니다
- **메모**: 상담할 때 들은 내용

### 4-2. 라이선스 발급

고객 이름을 눌러 상세 화면으로 갑니다. **라이선스 발급** 에서:

- **프로그램**: 무엇을 샀는지
- **플랜**: "템플릿" / "세팅 대행" 등
- **결제액**: 실제 받은 돈
- **월 유지비**: 매달 받기로 한 돈. 없으면 0
- **만료일**: 기간 제한이 있으면. 없으면 비워둡니다

발급하면 홈 화면의 누적 결제액과 월 리테이너 숫자에 반영됩니다.

### 4-3. 문의가 오면

고객 상세의 **응대 기록** 에 남기세요. 날짜가 자동으로 붙습니다.
나중에 "이 사람한테 뭐라고 답했더라" 를 찾을 때 씁니다.

### 4-4. 환불했을 때

라이선스 옆 드롭다운에서 `refunded` 로 바꿉니다. 누적 결제액에서 빠집니다.
기록은 남으니 지우지 마세요.

### 4-5. 대행 작업을 할 때

테스트 탭에서 **"어떤 고객을 위한 실행인가요?"** 에 고객을 지정하고 실행하면,
그 고객 상세 화면에 실행 기록이 남습니다. 나중에 "이 고객 건 언제 만들었더라" 를 알 수 있습니다.

## 5장. 새 프로그램을 추가하는 법

**대시보드 코드는 건드리지 않습니다.** 파일 하나만 만들면 됩니다.

### 5-1. 폴더 만들기

```
products/새프로그램이름/
```

폴더 이름은 영어 소문자와 하이픈만 씁니다. 예: `agency-kit`, `niche-research`

### 5-2. `program.yaml` 만들기

그 폴더 안에 `program.yaml` 파일을 만들고 아래를 복사해 채웁니다.

```yaml
id: agency-kit              # 폴더 이름과 똑같이
number: 1                   # 대시보드에 표시될 번호
name: 자동화 대행 납품 키트
tagline: 한 줄 설명
status: wip                 # ready(운영중) / wip(제작중) / planned(계획)
version: "0.1.0"

summary: |
  이 프로그램이 뭘 하는지 문단으로 씁니다.

steps:                      # 열람 탭의 이용 순서
  - title: 첫 번째 할 일
    body: 구체적으로 무엇을 하는지
    estimate: 10분

faq:                        # 열람 탭의 FAQ
  - q: 질문
    a: 답변
    audience: both          # admin / client / both

settings:                   # 수정 탭에 나올 설정 항목
  - key: CLAUDE_MODEL
    label: 사용할 모델
    type: select            # text / textarea / number / boolean / select
    default: claude-sonnet-4-6
    options: [claude-sonnet-4-6, claude-opus-5]
    help: 설명

editable_files:             # 수정 탭에서 편집할 파일
  - path: prompts/main.md
    label: 프롬프트
    kind: markdown
    help: 이 파일이 결과 품질을 좌우합니다

outputs:                    # 산출물 설명
  - path: result.md
    label: 결과 문서
    description: 무엇이 들어 있는지

pricing:                    # 판매 플랜
  - plan: 기본
    price: 550000
    description: 구성 설명

manuals:
  admin: docs/admin.md
  client: docs/client.md

requirements:               # 쓰기 전에 무엇이 필요한가 (🔑 권한·환경 화면)
  home_pc: yes              # yes / partial / no
  home_pc_note: ""          # yes 가 아니면 이유를 꼭 쓴다
  internet: optional        # none / optional / needed
  accounts:
    - name: 무슨무슨 API 키
      why: 이게 없으면 무엇이 안 되는지
      cost: 무료
      lead_time: 즉시       # 즉시 / 하루 이틀 / 심사 필요
      how: 어디서 어떻게 받는지
      env_key: SOME_API_KEY # .env 에 넣을 이름
      blocking: false       # 없으면 아예 못 쓰는가
  software:
    - name: ffmpeg
      why: 영상 합성
      how: brew install ffmpeg
      bundled: false        # requirements.txt 로 같이 깔리면 true
  limits:
    - 하루 몇 회 같은 한도
  cautions:
    - 법·정책상 조심할 것

schedule:                   # 얼마나 자주 돌려야 하는가 (🗓 정기 실행 화면)
  cadence: weekly           # manual / daily / weekly / monthly / continuous
  at: "월요일 09:00"
  cron: "0 9 * * 1  cd /path && python run.py"
  command: "python run.py" # 손으로 돌릴 때
  why: 왜 이 주기인지
  skipped: 거르면 무엇이 깨지는지
  warmup_days: 0            # 며칠은 쌓여야 결과가 뜻을 가지는가

run:                        # 테스트 탭에서 실행하는 방법
  input_file: input.yaml
  command: ["python", "cli.py", "build", "{input}"]
  dry_run_command: ["python", "cli.py", "build", "{input}", "--dry-run"]
  output_dir: outputs
  timeout_seconds: 900
```

필수는 `id`, `number`, `name` 셋뿐입니다. 나머지는 없으면 그 부분이 화면에서 빠집니다.
`requirements` 의 `lead_time` 을 **정직하게 쓰세요.** 심사가 필요한데 '즉시' 라고
적으면 그 거짓말이 상세페이지까지 그대로 갑니다.

`schedule` 을 안 쓰면 '필요할 때만 도는 프로그램' 으로 봅니다. **되풀이해 돌려야 하는
프로그램이라면 `why` 와 `skipped` 를 꼭 채우세요.** 몇 달 뒤에 "이거 왜 매일 돌렸더라"
하게 되는데, 그때 그 두 줄이 답을 대신합니다.
처음에는 `id`, `number`, `name`, `status: planned` 만 넣고 등록해두었다가 나중에 채워도 됩니다.

### 5-3. 대시보드에서 확인

왼쪽 아래 **프로그램 새로고침** 을 누릅니다. 목록에 나타나면 성공입니다.

**빨간 오류 박스가 뜨면** `program.yaml` 에 문제가 있는 것입니다. 메시지에 어느 항목인지 나옵니다.
가장 흔한 실수는 들여쓰기입니다. YAML 은 **스페이스 2칸**을 쓰고 탭을 쓰면 안 됩니다.

### 5-4. 매뉴얼 2종 쓰기

`docs/admin.md` 와 `docs/client.md` 를 만드세요.

- **관리자용**: 내가 나중에 볼 문서. 비용, 품질 올리는 법, 문제 해결
- **클라이언트용**: 구매자가 볼 문서. **컴퓨터를 모르는 사람 기준**으로, 화면에 나오는 말 그대로

## 6장. 문제가 생겼을 때

### 접속 코드가 안 먹힘

| 증상 | 원인 | 조치 |
|---|---|---|
| "접속 코드가 맞지 않습니다" | 코드를 바꿔 놓고 옛 코드를 넣음 | `.env` 의 `DASHBOARD_ACCESS_CODE` 를 확인 |
| `.env` 를 고쳤는데 그대로 | 대시보드를 다시 켜지 않음 | `Ctrl + C` 로 끄고 다시 켜세요 |
| "잠시 잠겼습니다" | 7번 틀림 | 10분 기다리거나, 대시보드를 다시 켜면 풀립니다 |
| 들어갔는데 자꾸 로그인 화면 | 브라우저가 쿠키를 막음 | 시크릿 모드가 아닌 창에서, 쿠키 차단을 풀고 접속 |
| 어제 됐는데 오늘 다시 물어봄 | 12시간이 지남 | 정상입니다. `DASHBOARD_SESSION_HOURS` 로 늘릴 수 있습니다 |
| 다들 갑자기 로그아웃됨 | `DASHBOARD_SECRET` 이 바뀜 | 다시 로그인하면 됩니다 |

### 대시보드가 안 켜짐

| 화면 메시지 | 해결 |
|---|---|
| `ModuleNotFoundError: No module named 'fastapi'` | `pip install -r requirements.txt` 를 다시 |
| `Address already in use` | 이미 켜져 있습니다. 브라우저에서 `http://127.0.0.1:8000` 확인. 또는 `python -m dashboard --port 8001` |
| 브라우저가 안 열림 | 주소창에 `http://127.0.0.1:8000` 직접 입력 |

### 실행이 실패함

테스트 탭의 검은 로그 상자를 보세요. 마지막 줄에 이유가 있습니다.

| 로그 내용 | 원인 | 해결 |
|---|---|---|
| `ANTHROPIC_API_KEY 가 없습니다` | 키 미설정 | 2-2 를 다시 |
| `Claude API 오류 401` | 키가 틀림 | 콘솔에서 키를 새로 발급 |
| `credit balance is too low` | 잔액 없음 | 콘솔 Billing 에서 충전 |
| `쿼터 초과` | 너무 빨리 여러 번 호출 | **재시도하지 말고** 1분 기다렸다 다시 |
| `입력이 올바르지 않습니다` | 입력 파일 오류 | 어느 항목인지 메시지에 나옵니다 |
| `...초 안에 끝나지 않아 중단` | 시간 초과 | 다시 실행. 계속되면 `program.yaml` 의 `timeout_seconds` 를 늘립니다 |

### 프로그램 목록에 안 나옴

1. `products/<이름>/program.yaml` 이 정말 그 위치에 있는지
2. **프로그램 새로고침** 을 눌렀는지
3. 화면 위에 빨간 오류가 있는지 (있으면 YAML 문법 문제)

### 실수로 파일을 망가뜨림

같은 폴더에 `파일명.bak` 이 있습니다. 직전 내용입니다.
메모장으로 열어 내용을 복사한 뒤, 대시보드 편집 화면에 붙여넣고 저장하세요.

## 7장. 꼭 지켜야 할 것

이 셋은 어기면 상품 자체가 위험해집니다.

### 7-1. "수익이 난다"는 표현 금지

고액 부업 강의 관련 소비자 피해가 실재하고 소비자원 주의보까지 나온 영역입니다.
판매 문구에 성과를 단정하는 표현을 쓰면 상품이 내려갈 수 있습니다.

모든 프로그램은 만든 텍스트를 자동으로 검사합니다. 목록은 **기타 설정** 화면에서 볼 수 있습니다.
**경고가 떴는데 무시하고 발행하지 마세요.**

대신 쓸 말: "시간을 줄입니다", "반복 작업을 자동화합니다", "결과는 검증이 필요합니다"

### 7-2. 없는 후기·실적 금지

증거를 입력하지 않으면 해당 섹션이 아예 만들어지지 않도록 설계돼 있습니다.
빈칸을 채우려고 그럴듯한 후기를 지어내지 마세요. 표시광고법 위반입니다.

### 7-3. AI 생성물 표시 켜두기

2026년 1월 시행된 인공지능기본법에 따라, **AI 프로그램을 판매하는 쪽**은 표시 의무 대상입니다.
위반하면 시정명령 후 최대 3,000만 원 과태료입니다.

기본으로 켜져 있습니다. 끄지 마세요. 오히려 "법 준수 도구"라는 점을 판매 포인트로 쓰세요.

### 7-4. 산출물은 초안입니다

어떤 프로그램이든 결과를 그대로 발행하지 마세요.
**초안 생성 → 사람 승인 → 발행** 3단계를 지키세요. 특히:

- 환불 정책과 사업자 정보는 자동으로 채워지지 않습니다. 직접 쓰셔야 합니다
- AI 가 쓴 글에는 그럴듯하지만 틀린 내용이 섞일 수 있습니다

## 8장. 백업

고객 정보와 실행 이력은 저장소 맨 위 폴더의 `dashboard.db` 파일 하나에 들어 있습니다.

**이 파일을 주기적으로 복사해두세요.** 다른 폴더나 클라우드에 복사해두면 그게 백업입니다.
지우면 고객 명단이 전부 사라지고 복구할 수 없습니다.

프로그램 파일 자체는 GitHub 에 올라가 있으니 따로 백업하지 않아도 됩니다.
단, `dashboard.db` 와 `.env` 는 **일부러 GitHub 에 올리지 않도록** 설정돼 있습니다. 직접 백업하세요.
