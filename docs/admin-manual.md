# 관리자 매뉴얼

> 이 대시보드를 **운영하는 사람**을 위한 문서입니다.
> 컴퓨터를 잘 모르셔도 따라 할 수 있도록 하나하나 적었습니다.
> 구매자에게 줄 문서는 [클라이언트 매뉴얼](/manual/client) 입니다.

---

## 1장. 이 대시보드가 무엇인가

프로그램을 여러 개 만들다 보면 이런 문제가 생깁니다.

- 어떤 프로그램이 있었는지 기억나지 않는다
- 각각 어떻게 실행하는지 매번 찾아봐야 한다
- 설정을 바꾸려면 어느 파일을 열어야 하는지 모른다
- 누가 무엇을 샀는지 엑셀에 따로 적어둔다

이 대시보드는 그걸 한 화면에 모읍니다. **터미널을 몰라도 프로그램을 쓸 수 있게** 하는 것이 목적입니다.

### 화면 구성

| 화면 | 하는 일 |
|---|---|
| **홈** | 프로그램 1번, 2번… 목록과 전체 현황 숫자 |
| **프로그램 → 열람** | 그 프로그램이 뭘 하는지, 어떤 순서로 쓰는지, FAQ |
| **프로그램 → 수정** | 설정값 바꾸기, 프롬프트·템플릿 파일 직접 편집 |
| **프로그램 → 테스트** | 브라우저에서 바로 실행하고 결과 확인 |
| **프로그램 → 회원관리** | 이 프로그램을 산 고객 목록 |
| **회원관리** | 전체 고객, 라이선스 발급, 응대 기록 |
| **기타 설정** | API 키 상태, 기본 모델, 금지 문구 목록 |
| **매뉴얼** | 지금 보고 계신 문서와 클라이언트용 문서 |

## 2장. 처음 한 번만 하는 준비

### 2-1. 프로그램 설치

명령 프롬프트(Windows) 또는 터미널(Mac)을 열고, 저장소 폴더로 이동한 뒤 한 줄을 실행합니다.

```
pip install -r requirements.txt
```

몇 분 걸립니다. 에러 없이 끝나면 성공입니다.

> **'pip' 을 찾을 수 없다고 나오면** 파이썬이 설치되지 않은 것입니다.
> https://www.python.org 에서 3.11 이상을 설치하고, 설치 화면에서
> "Add Python to PATH" 를 **반드시 체크**하세요.

### 2-2. Claude API 키 넣기

AI 를 쓰려면 키가 필요합니다. 없으면 모의 실행만 됩니다.

1. https://console.anthropic.com/settings/keys 에 접속해 로그인합니다
2. **Create Key** 를 누릅니다
3. `sk-ant-` 로 시작하는 긴 문자열이 나옵니다. **이 화면을 닫으면 다시 볼 수 없으니 복사**하세요
4. **Billing** 메뉴에서 카드를 등록하고 10달러 정도 충전합니다 (충전하지 않으면 키가 있어도 안 됩니다)
5. 저장소 맨 위 폴더에 있는 `.env.example` 파일을 복사해 `.env` 라는 이름으로 만듭니다
6. `.env` 를 메모장으로 열고 `ANTHROPIC_API_KEY=sk-ant-...` 줄에 키를 붙여넣고 저장합니다

> ⚠️ **`.env` 파일은 비밀번호와 같습니다.** 누구에게도 보내지 말고, GitHub 에 올리지 마세요.
> 유출되면 다른 사람이 쓴 요금이 내 카드로 청구됩니다.
> (이 프로젝트는 `.env` 를 자동으로 제외하도록 설정돼 있습니다.)

### 2-3. 대시보드 켜기

```
python -m dashboard
```

브라우저가 자동으로 열립니다. 안 열리면 주소창에 `http://127.0.0.1:8000` 을 직접 칩니다.

**끄는 법**: 터미널 창에서 `Ctrl + C` 를 누릅니다. 창을 닫아도 꺼집니다.

**확인**: 화면 위에 노란 경고("API 키가 설정되지 않았습니다")가 없으면 준비 완료입니다.

## 3장. 프로그램 쓰기 — 기본 흐름

왼쪽 목록에서 프로그램을 누르면 탭 5개가 나옵니다. 왼쪽부터 순서대로 쓰면 됩니다.

### 3-1. 열람 탭 — 먼저 읽는 곳

- **개요**: 이 프로그램이 뭘 하는지
- **이용 순서**: 1번부터 차례로. 각 단계의 예상 소요 시간도 있습니다
- **산출물**: 어떤 파일이 나오고 각각 뭔지
- **FAQ**: 자주 나오는 질문
- **판매 플랜**: 얼마에 팔지

처음 쓰는 프로그램이라면 **이 탭을 끝까지 읽고 시작**하세요.

### 3-2. 수정 탭 — 설정과 파일 편집

**설정값**은 드롭다운이나 체크박스로 바꿉니다. 각 항목 아래 회색 설명이 있으니 읽어보세요.
바꾸고 **설정 저장**을 누르면 다음 실행부터 적용됩니다.

**파일 편집**은 프로그램의 중요 파일을 브라우저에서 직접 고치는 기능입니다.

> 💡 **저장하면 직전 내용이 자동으로 `.bak` 파일로 남습니다.** 잘못 고쳐도 되돌릴 수 있습니다.
> 되돌리려면 폴더에서 `파일명.bak` 의 내용을 복사해 다시 붙여넣으세요.

### 3-3. 테스트 탭 — 실행하는 곳

버튼이 두 개입니다. **차이를 꼭 알아두세요.**

| 버튼 | 비용 | 걸리는 시간 | 결과물 |
|---|---|---|---|
| **모의 실행** | 없음 | 몇 초 | 형태는 진짜, 내용은 예시 |
| **실제 실행** | 수백 원 | 2~5분 | 진짜 결과물 |

**처음에는 반드시 모의 실행부터** 하세요. 산출물이 어떤 모양인지 보고, 마음에 들면 실제 실행합니다.

실행이 끝나면 세 가지 중 하나가 나옵니다.

| 결과 | 뜻 | 할 일 |
|---|---|---|
| 🟢 **성공** | 다 만들어졌고 문제없음 | 산출물 보기 → 검토 |
| 🟡 **경고** | 만들어졌지만 금지 표현이 남음 | 어느 부분인지 로그를 보고 직접 수정 |
| 🔴 **실패** | 만들어지지 않음 | 로그를 읽고 6장 참고 |

**산출물 보기** 버튼을 누르면 파일 목록이 나오고, **열기** 를 누르면 브라우저에서 바로 볼 수 있습니다.
HTML 은 실제 페이지로, 마크다운은 읽기 좋게 보여줍니다.

### 3-4. 회원관리 탭 — 이 프로그램을 산 사람

누가 샀고 얼마를 냈고 언제까지 쓸 수 있는지 나옵니다. 등록은 5장에서 설명합니다.

### 3-5. 매뉴얼 탭

그 프로그램 전용 매뉴얼입니다. **클라이언트용**은 구매자에게 그대로 전달하세요.

## 4장. 고객이 생겼을 때

### 4-1. 고객 등록

**회원관리** → 아래 **고객 추가** 폼에 입력합니다.

- **이름, 이메일**: 필수
- **유입 경로**: "크몽", "인스타", "소개" 처럼 적어두면 나중에 어디서 손님이 오는지 알 수 있습니다
- **메모**: 상담할 때 들은 내용

### 4-2. 라이선스 발급

고객 이름을 눌러 상세 화면으로 갑니다. **라이선스 발급** 에서:

- **프로그램**: 무엇을 샀는지
- **플랜**: "템플릿" / "세팅 대행" 등
- **결제액**: 실제 받은 돈
- **월 유지비**: 매달 받기로 한 돈. 없으면 0
- **만료일**: 기간 제한이 있으면. 없으면 비워둡니다

발급하면 홈 화면의 누적 결제액과 월 리테이너 숫자에 반영됩니다.

### 4-3. 문의가 오면

고객 상세의 **응대 기록** 에 남기세요. 날짜가 자동으로 붙습니다.
나중에 "이 사람한테 뭐라고 답했더라" 를 찾을 때 씁니다.

### 4-4. 환불했을 때

라이선스 옆 드롭다운에서 `refunded` 로 바꿉니다. 누적 결제액에서 빠집니다.
기록은 남으니 지우지 마세요.

### 4-5. 대행 작업을 할 때

테스트 탭에서 **"어떤 고객을 위한 실행인가요?"** 에 고객을 지정하고 실행하면,
그 고객 상세 화면에 실행 기록이 남습니다. 나중에 "이 고객 건 언제 만들었더라" 를 알 수 있습니다.

## 5장. 새 프로그램을 추가하는 법

**대시보드 코드는 건드리지 않습니다.** 파일 하나만 만들면 됩니다.

### 5-1. 폴더 만들기

```
products/새프로그램이름/
```

폴더 이름은 영어 소문자와 하이픈만 씁니다. 예: `agency-kit`, `niche-research`

### 5-2. `program.yaml` 만들기

그 폴더 안에 `program.yaml` 파일을 만들고 아래를 복사해 채웁니다.

```yaml
id: agency-kit              # 폴더 이름과 똑같이
number: 1                   # 대시보드에 표시될 번호
name: 자동화 대행 납품 키트
tagline: 한 줄 설명
status: wip                 # ready(운영중) / wip(제작중) / planned(계획)
version: "0.1.0"

summary: |
  이 프로그램이 뭘 하는지 문단으로 씁니다.

steps:                      # 열람 탭의 이용 순서
  - title: 첫 번째 할 일
    body: 구체적으로 무엇을 하는지
    estimate: 10분

faq:                        # 열람 탭의 FAQ
  - q: 질문
    a: 답변
    audience: both          # admin / client / both

settings:                   # 수정 탭에 나올 설정 항목
  - key: CLAUDE_MODEL
    label: 사용할 모델
    type: select            # text / textarea / number / boolean / select
    default: claude-sonnet-4-6
    options: [claude-sonnet-4-6, claude-opus-5]
    help: 설명

editable_files:             # 수정 탭에서 편집할 파일
  - path: prompts/main.md
    label: 프롬프트
    kind: markdown
    help: 이 파일이 결과 품질을 좌우합니다

outputs:                    # 산출물 설명
  - path: result.md
    label: 결과 문서
    description: 무엇이 들어 있는지

pricing:                    # 판매 플랜
  - plan: 기본
    price: 550000
    description: 구성 설명

manuals:
  admin: docs/admin.md
  client: docs/client.md

run:                        # 테스트 탭에서 실행하는 방법
  input_file: input.yaml
  command: ["python", "cli.py", "build", "{input}"]
  dry_run_command: ["python", "cli.py", "build", "{input}", "--dry-run"]
  output_dir: outputs
  timeout_seconds: 900
```

필수는 `id`, `number`, `name` 셋뿐입니다. 나머지는 없으면 그 부분이 화면에서 빠집니다.
처음에는 `id`, `number`, `name`, `status: planned` 만 넣고 등록해두었다가 나중에 채워도 됩니다.

### 5-3. 대시보드에서 확인

왼쪽 아래 **프로그램 새로고침** 을 누릅니다. 목록에 나타나면 성공입니다.

**빨간 오류 박스가 뜨면** `program.yaml` 에 문제가 있는 것입니다. 메시지에 어느 항목인지 나옵니다.
가장 흔한 실수는 들여쓰기입니다. YAML 은 **스페이스 2칸**을 쓰고 탭을 쓰면 안 됩니다.

### 5-4. 매뉴얼 2종 쓰기

`docs/admin.md` 와 `docs/client.md` 를 만드세요.

- **관리자용**: 내가 나중에 볼 문서. 비용, 품질 올리는 법, 문제 해결
- **클라이언트용**: 구매자가 볼 문서. **컴퓨터를 모르는 사람 기준**으로, 화면에 나오는 말 그대로

## 6장. 문제가 생겼을 때

### 대시보드가 안 켜짐

| 화면 메시지 | 해결 |
|---|---|
| `ModuleNotFoundError: No module named 'fastapi'` | `pip install -r requirements.txt` 를 다시 |
| `Address already in use` | 이미 켜져 있습니다. 브라우저에서 `http://127.0.0.1:8000` 확인. 또는 `python -m dashboard --port 8001` |
| 브라우저가 안 열림 | 주소창에 `http://127.0.0.1:8000` 직접 입력 |

### 실행이 실패함

테스트 탭의 검은 로그 상자를 보세요. 마지막 줄에 이유가 있습니다.

| 로그 내용 | 원인 | 해결 |
|---|---|---|
| `ANTHROPIC_API_KEY 가 없습니다` | 키 미설정 | 2-2 를 다시 |
| `Claude API 오류 401` | 키가 틀림 | 콘솔에서 키를 새로 발급 |
| `credit balance is too low` | 잔액 없음 | 콘솔 Billing 에서 충전 |
| `쿼터 초과` | 너무 빨리 여러 번 호출 | **재시도하지 말고** 1분 기다렸다 다시 |
| `입력이 올바르지 않습니다` | 입력 파일 오류 | 어느 항목인지 메시지에 나옵니다 |
| `...초 안에 끝나지 않아 중단` | 시간 초과 | 다시 실행. 계속되면 `program.yaml` 의 `timeout_seconds` 를 늘립니다 |

### 프로그램 목록에 안 나옴

1. `products/<이름>/program.yaml` 이 정말 그 위치에 있는지
2. **프로그램 새로고침** 을 눌렀는지
3. 화면 위에 빨간 오류가 있는지 (있으면 YAML 문법 문제)

### 실수로 파일을 망가뜨림

같은 폴더에 `파일명.bak` 이 있습니다. 직전 내용입니다.
메모장으로 열어 내용을 복사한 뒤, 대시보드 편집 화면에 붙여넣고 저장하세요.

## 7장. 꼭 지켜야 할 것

이 셋은 어기면 상품 자체가 위험해집니다.

### 7-1. "수익이 난다"는 표현 금지

고액 부업 강의 관련 소비자 피해가 실재하고 소비자원 주의보까지 나온 영역입니다.
판매 문구에 성과를 단정하는 표현을 쓰면 상품이 내려갈 수 있습니다.

모든 프로그램은 만든 텍스트를 자동으로 검사합니다. 목록은 **기타 설정** 화면에서 볼 수 있습니다.
**경고가 떴는데 무시하고 발행하지 마세요.**

대신 쓸 말: "시간을 줄입니다", "반복 작업을 자동화합니다", "결과는 검증이 필요합니다"

### 7-2. 없는 후기·실적 금지

증거를 입력하지 않으면 해당 섹션이 아예 만들어지지 않도록 설계돼 있습니다.
빈칸을 채우려고 그럴듯한 후기를 지어내지 마세요. 표시광고법 위반입니다.

### 7-3. AI 생성물 표시 켜두기

2026년 1월 시행된 인공지능기본법에 따라, **AI 프로그램을 판매하는 쪽**은 표시 의무 대상입니다.
위반하면 시정명령 후 최대 3,000만 원 과태료입니다.

기본으로 켜져 있습니다. 끄지 마세요. 오히려 "법 준수 도구"라는 점을 판매 포인트로 쓰세요.

### 7-4. 산출물은 초안입니다

어떤 프로그램이든 결과를 그대로 발행하지 마세요.
**초안 생성 → 사람 승인 → 발행** 3단계를 지키세요. 특히:

- 환불 정책과 사업자 정보는 자동으로 채워지지 않습니다. 직접 쓰셔야 합니다
- AI 가 쓴 글에는 그럴듯하지만 틀린 내용이 섞일 수 있습니다
