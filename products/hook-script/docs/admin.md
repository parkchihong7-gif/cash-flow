# 후킹 대본 생성기 — 관리자 매뉴얼

> 이 프로그램을 **운영하고 판매하는 사람**을 위한 문서입니다.
> 구매자에게 줄 문서는 `docs/client.md` 입니다.

---

## 1장. 이 프로그램이 파는 것

### 1-1. 한 문단 요약

주제와 시청자를 적으면 첫 3초 후크 후보 10개를 뽑고, 그중 하나로 타임코드가 붙은
대본 초안을 씁니다. 쇼츠는 자막 한 줄 단위까지, 롱폼은 챕터별 전환 문장까지 만듭니다.

### 1-2. 이 도구의 진짜 가치는 "구조"입니다

문장을 예쁘게 써주는 것이 아닙니다. 구조를 강제하는 것이 핵심입니다.

- 쇼츠 자막 15자 제한 — 대부분의 초보가 여기서 틀립니다. 한 줄에 25자를 넣으면
  읽기 전에 자막이 넘어갑니다. 이 프로그램은 넘으면 자동으로 쪼갭니다.
- 타임코드 — "핵심 3포인트"를 몇 초씩 배정할지 매번 고민하지 않아도 됩니다.
- 챕터 전환 문장 — 롱폼 이탈의 가장 큰 원인이고, 초보가 가장 자주 빠뜨립니다.

판매 문구를 쓸 때 이 점을 앞세우세요. "AI가 대본 써줍니다"는 흔하지만
"쇼츠 자막 15자를 프로그램이 강제합니다"는 구체적입니다.

### 1-3. 만들지 않은 기능과 그 이유

**"터진 영상 찾아서 따라 만들기" 기능은 넣지 않았습니다.**
같은 기능을 제공하던 국내 서비스가 표절 논란으로 2023년 2월 서비스를 종료하고
전액 환불한 전례가 있습니다. 이 도구는 특정 채널·영상을 재현 대상으로 받지 않습니다.
`evidence` 는 사실 자료만 받습니다.

이건 기능 부족이 아니라 **판매 포인트**입니다. 상세페이지에 명시하세요.

## 2장. 준비

### 2-1. API 키

1. https://console.anthropic.com/settings/keys 에서 키 발급 (`sk-ant-` 로 시작)
2. Billing 에서 카드 등록 + 10달러 정도 충전 (충전 없으면 키가 있어도 호출이 거절됩니다)
3. 저장소 맨 위 폴더의 `.env` 에 `ANTHROPIC_API_KEY=sk-ant-...` 저장
4. 대시보드 **기타 설정**에서 "API 키: 설정됨" 확인

> `.env` 는 절대 공유하지 마세요. 유출되면 남이 쓴 요금이 내 카드로 나갑니다.

### 2-2. 비용 감각

한 편에 LLM 을 4번 부릅니다 (후크 → 본문 → 제목 → 체크리스트).
금지 문구나 길이 위반이 나오면 그 섹션만 최대 2번 더 부릅니다.

| 상황 | 대략 호출 수 |
|---|---|
| 정상 | 4회 |
| 한 섹션 재생성 | 5~6회 |
| 배치 10편 | 40~60회 |

**배치를 돌리기 전에 반드시 모의 실행이나 1편 실제 실행으로 확인하세요.**
설정이 잘못된 상태로 20편을 돌리면 그만큼 그대로 나갑니다.

## 3장. 매일 쓰는 흐름

```
주제 정하기 → 모의 실행(형태 확인) → 실제 실행 → 후크 10개 보기
→ 마음에 안 들면 --hook-index 로 다시 → 체크리스트 채우기 → 촬영
```

### 3-1. 입력 채우기

대시보드 **수정** 탭에서 `script_input.yaml` 을 엽니다.

| 항목 | 잘 쓰는 법 |
|---|---|
| `topic` | 질문형이나 주장형이 좋습니다. "엑셀 팁"(X) → "같은 도구를 쓰는데 속도가 두 배 차이 나는 이유"(O) |
| `format` | `long` / `shorts` / `reels` |
| `duration_sec` | 쇼츠·릴스 15~60, 롱폼 300~1200. 범위를 벗어나면 오류 |
| `audience` | **좁을수록 좋습니다.** "직장인"(X) → "매일 같은 문서 작업을 반복하고 도구를 바꿀 권한은 없는 사무직 3년차"(O) |
| `tone` | 3장 3-2 참고 |
| `cta` | `구독` / `링크` / `댓글`. 하나만 고릅니다 |
| `evidence` | 사실 자료. **없으면 `[]`** |

### 3-2. 톤 고르는 법

| 톤 | 언제 쓰나 | 주의 |
|---|---|---|
| `정보형` | 방법·정리·비교 주제 | 가장 무난하지만 밋밋해지기 쉽습니다 |
| `스토리형` | 본인 경험이 있는 주제 | **본인 경험이 없으면 쓰지 마세요.** AI가 지어낸 경험담은 티가 납니다 |
| `반전형` | 통념이 명확한 주제 | 뒤집을 통념이 진짜 있어야 합니다. 없으면 억지가 됩니다 |

### 3-3. `evidence` 를 넣을 때와 안 넣을 때

**비워두면** 대본에 숫자와 출처가 아예 들어가지 않습니다. "연구에 따르면" 같은
출처 없는 권위 표현도 나오지 않습니다. 안전합니다.

**넣으면** 그 자료 범위 안에서만 씁니다. 넣을 때는 이렇게 쓰세요.

```yaml
evidence:
  - "본인 채널 2026년 6월 쇼츠 12편 평균 조회수 3,200회 (유튜브 스튜디오)"
  - "수강생 42명 중 31명이 4주 차에 주 3회 업로드 유지 (2026-06 자체 설문)"
```

출처를 함께 적는 습관을 들이세요. 나중에 "이 숫자 어디서 났지"를 막습니다.

### 3-4. 후크 10개 활용법

`hooks.json` 에 후보 10개가 들어 있습니다. 각각 이런 모양입니다.

```json
{"text": "이거 모르면 손해", "tags": ["손실회피", "호기심"], "strength": 5,
 "reason": "손실 프레임이 가장 강하다"}
```

- `tags` 는 8가지 멈춤 이유 중 쓴 것 (돈·시간·관계·지위·안전·호기심·비교·손실회피)
- `strength` 는 모델이 스스로 매긴 예상 강도. **참고값일 뿐 실측이 아닙니다**

**활용법**: 같은 주제로 후크만 바꿔 A/B 테스트를 하고, 실제로 통한 후크의 `tags` 를
기록해두세요. 3~4편이 쌓이면 내 채널에서 어떤 심리 요인이 통하는지 보입니다.
그때부터는 `--hook-index` 로 그 조합을 우선 고르면 됩니다.

```bash
python cli.py build script_input.yaml --hook-index 3
```

후크만 바꿔 다시 돌리면 본문도 그 후크에 맞게 다시 써집니다 (비용이 또 듭니다).

### 3-5. 배치 실행

`topics.txt` 에 주제를 한 줄씩 적고:

```bash
python cli.py build --batch topics.txt --format shorts --duration 30 --audience "사무직 3년차"
```

또는 YAML 을 기본값 삼아 주제만 갈아 끼우기:

```bash
python cli.py build script_input.yaml --batch topics.txt
```

**배치 주의**
- 모든 편에 같은 포맷·길이·시청자가 적용됩니다
- 중간에 실패해도 나머지는 계속 만듭니다
- 하나라도 확인 필요 항목이 있으면 종료 코드 2가 됩니다
- 10편이면 40~60회 호출입니다. 비용을 계산하고 돌리세요

## 4장. 산출물 읽는 법

### 4-1. `checklist.md` 를 가장 먼저 엽니다

이 파일이 이 프로그램의 핵심 산출물입니다. 대본보다 먼저 보세요.

**"사람이 반드시 추가할 것" 3가지**가 주제에 맞게 구체적으로 제안됩니다.

```
### 1. 개인 경험
- 넣을 위치: 문제 제기 (3~7초)
- 무엇을: 이 설정을 바꾸기 전 본인이 실제로 몇 분을 썼는지
- 왜: 숫자가 본인 것이어야 시청자가 믿습니다
- 어떻게 구하나: 지난주 작업 기록이나 화면 녹화를 확인하세요
```

**이걸 채우지 않으면 이 도구를 쓴 의미가 없습니다.** AI 대본만으로 영상을 만들면
유튜브 양산형 정책에 걸려 수익화에서 제외될 수 있습니다.

맨 아래 **자동 검사 결과** 표도 확인하세요.

| 표시 | 뜻 | 할 일 |
|---|---|---|
| 통과 | 문제없음 | 넘어가도 됩니다 |
| 금지 문구에 단어가 적힘 | 2번 다시 만들어도 남음 | 대본에서 직접 찾아 고치세요 |
| `⚠ N건 자동 보정` | 길이 제한을 프로그램이 강제로 맞춤 | 의미가 끊기지 않았는지 확인 |

### 4-2. `script.md`

쇼츠는 `- ` 로 시작하는 줄 하나가 자막 하나입니다. 그대로 자막 프로그램에 넣으면 됩니다.

롱폼은 챕터마다 **핵심 문장 / 본문 / 예시 / 전환 문장**이 있습니다.
`[사람이 채울 곳: ...]` 표시는 반드시 실제 내용으로 바꾸세요. 그대로 두고 찍으면 안 됩니다.

### 4-3. `titles.json`

제목 10개와 썸네일 문구 5개. 제목은 40자, 썸네일은 12자 이내로 강제됩니다.

**썸네일 문구는 제목과 다른 말을 쓰세요.** 같은 말을 두 번 보여주면 정보량이 절반입니다.
제목이 "설정 3개로 10분 아끼기"면 썸네일은 "10분 → 1분" 처럼요.

### 4-4. `ai_label.txt`

영상 설명란에 붙여 넣을 문구입니다. 그리고 **유튜브 업로드 화면의
'변경된 콘텐츠 또는 합성 콘텐츠' 항목도 사실대로 체크**해야 합니다.
목소리나 얼굴을 AI로 합성했다면 반드시 체크 대상입니다.

## 5장. 품질을 올리는 법

효과가 큰 순서대로입니다.

### 5-1. `audience` 를 좁힌다 (가장 효과 큼, 비용 0)

입력 한 줄만 고치면 됩니다.

- (X) "직장인"
- (O) "매일 같은 보고서를 만들고 도구를 바꿀 권한은 없는 사무직 3년차"

### 5-2. `prompts/` 를 고친다

| 파일 | 무엇이 바뀌나 |
|---|---|
| `common.md` | 8가지 멈춤 이유, 사실 조작 금지, 베끼기 금지 — 전 포맷 공통 |
| `format_shorts.md` | 자막 규칙, 구간 구성, 문체 |
| `format_long.md` | 챕터 구성, 전환 문장, 이탈 방지 |

**효과 있는 수정 예**
- 본인 업종을 명시: "한국어 대본 작가" → "소상공인 대상 실무 콘텐츠 대본 작가"
- 싫어하는 상투구를 금지 목록에 추가: "여러분", "~하시길 바랍니다" 등
- 잘 나온 후크 2~3개를 "이런 톤으로" 하고 붙여두면 톤이 안정됩니다

바꾼 뒤에는 **모의 실행이 아니라 실제 실행**으로 확인하세요.
모의 실행은 프롬프트를 쓰지 않습니다.

### 5-3. 모델을 올린다 (비용 증가)

대시보드 **수정** 탭에서 모델을 바꿉니다. 초안 용도면 sonnet 계열로 충분하고,
정말 안 나올 때만 opus 를 시도하세요. 프롬프트를 고치는 것이 먼저입니다.

## 6장. 문제 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| `duration_sec 은 15~60초여야 합니다` | 포맷과 길이가 안 맞음 | 쇼츠·릴스 15~60, 롱폼 300~1200 |
| `--hook-index 는 1 이상` | 0이나 음수 입력 | 1부터 셉니다 |
| `--batch 를 쓰려면 ... 지정` | 배치인데 포맷·길이·시청자 없음 | 인자로 주거나 YAML 을 함께 주세요 |
| `설정 오류: ANTHROPIC_API_KEY` | 키 미설정 | 2-1 |
| `Claude API 오류 401` | 키가 틀림 | 콘솔에서 재발급 |
| `credit balance is too low` | 잔액 없음 | 콘솔 Billing 충전 |
| `쿼터 초과` | 분당 한도 초과 | **재시도하지 말고** 1분 대기. 배치는 특히 자주 발생 |
| 자막이 계속 자동 보정됨 | 모델이 15자 규칙을 못 지킴 | `format_shorts.md` 의 자막 규칙에 예시를 더 넣으세요 |
| 체크리스트 제안이 일반론임 | 주제가 너무 넓음 | `topic` 과 `audience` 를 구체적으로 |

## 7장. 판매할 때

### 7-1. 상세페이지에 반드시 넣을 것

- "초안 생성기이며 발행 전 사람 검수가 필수"라는 문장
- 양산형 정책 이야기와 체크리스트 3가지가 그 대응이라는 설명
- Claude API 키는 **구매자가 직접 발급**하고 사용료는 별도라는 안내
- 조회수·구독자 증가를 약속하지 않는다는 점

### 7-2. 쓰면 안 되는 표현

조회수나 성과를 단정하는 표현, "알고리즘 공략" 같은 과장 표현은 쓰지 마세요.
프로그램이 산출물은 자동 검사하지만 **상세페이지는 검사하지 않습니다.**
대시보드 **기타 설정**에서 금지 문구 목록 전체를 확인하고 직접 대조하세요.

### 7-3. 1번 퍼널 빌더와 묶어 팔기

퍼널 빌더(랜딩+이메일)와 이 도구(대본)는 같은 고객을 봅니다.
강의를 파는 사람은 유입용 콘텐츠도 필요합니다. 묶음 플랜을 만들 때는
대시보드 **회원관리**에서 두 프로그램의 라이선스를 각각 발급하세요.

### 7-4. 회원관리 연동

1. **회원관리** → 고객 추가
2. 고객 상세 → **라이선스 발급** → 프로그램 `hook-script` 선택
3. 대행 작업 시 테스트 탭에서 고객을 지정해 실행하면 이력이 남습니다
