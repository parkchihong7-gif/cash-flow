# 롱폼 대본 규칙

## 구조

주어진 구간(타임코드)을 그대로 따른다.

1. **후크 (30초)** — 끝까지 볼 이유를 준다. 결론의 일부를 먼저 보여줘도 좋다.
2. **약속 (30초)** — 이 영상을 다 보면 무엇을 알게 되는지 명시한다.
3. **챕터 5~7개** — 각 챕터마다 네 가지를 쓴다.
   - `title`: 챕터 제목 (20자 이내, 목차에 그대로 쓸 수 있게)
   - `key_sentence`: 이 챕터에서 시청자가 가져갈 문장 하나
   - `body`: 설명 (3~6문장)
   - `example`: 구체적인 예시. `evidence` 가 없으면 지어내지 말고
     `[사람이 채울 곳: 본인 사례]` 로 남긴다
   - `transition`: 다음 챕터로 넘어가는 한 문장
4. **요약 (60초)** — 챕터 핵심을 다시 짚는다. 새 정보를 넣지 않는다.
5. **CTA (30초)** — 요청은 하나만.

## 이탈을 막는 장치

- 챕터마다 **다음 챕터를 궁금하게 만드는 전환 문장**을 붙인다.
  "다음은 이것보다 더 자주 틀리는 부분입니다" 처럼.
- 약속(2번)에서 말한 내용을 챕터에서 반드시 지킨다. 안 지키면 이탈한다.

## 문체

- 말로 읽었을 때 자연스러운 문장. 한 문장 40자 안팎.
- 목록을 나열하지 말고 이유와 함께 설명한다.
- 전문 용어는 처음 나올 때 한 번 풀어준다.

## 출력 형식

```json
{
  "hook": {"body": "...", "note": "화면 지시"},
  "promise": {"body": "...", "note": ""},
  "chapters": [
    {"key": "chapter1", "title": "...", "key_sentence": "...",
     "body": "...", "example": "...", "transition": "..."}
  ],
  "summary": {"body": "...", "note": ""},
  "cta": {"body": "...", "note": ""},
  "human_slots": ["사람이 채워야 할 자리 설명"]
}
```

`chapters` 의 `key` 는 주어진 구간의 key(chapter1, chapter2 …)를 그대로 쓴다.
챕터 개수는 주어진 구간 개수와 정확히 같아야 한다.
