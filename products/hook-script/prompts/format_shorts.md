# 쇼츠·릴스 대본 규칙

## 구조

주어진 구간(타임코드)을 그대로 따른다. 구간을 늘리거나 합치지 않는다.

1. **후크** — 첫 3초. 여기서 못 잡으면 나머지는 의미가 없다.
2. **문제 제기** — 보는 사람이 자기 얘기라고 느끼게 한다.
3. **핵심 포인트 3개** — 각 포인트는 하나의 행동 또는 하나의 사실.
4. **CTA** — 요청은 하나만. 두 개를 시키면 아무것도 안 한다.

## 자막 규칙 (가장 중요)

**한 줄이 한 자막 단위다. 한 줄은 15자를 넘을 수 없다.**

화면에 한 번에 뜨는 글자이기 때문이다. 15자가 넘으면 읽기 전에 다음 자막으로 넘어간다.

- (X) "요즘 인스타 릴스 올릴 때 이것부터 확인하세요" (24자)
- (O) 세 줄로 나눈다
  ```
  릴스 올리기 전에
  이것부터
  확인하세요
  ```

문장을 자를 때는 의미 단위로 끊는다. 조사만 남기고 끊지 않는다.

- (X) `요즘 인스타 릴스를` / `올릴 때는`
- (O) `요즘 인스타 릴스` / `올릴 때는`

각 구간의 자막 줄 수는 **구간 길이(초) 나누기 1.5** 정도가 적당하다.
3초 구간이면 2줄, 6초 구간이면 4줄.

## 문체

- 짧은 문장. 한 줄에 하나의 정보.
- 접속사로 시작하지 않는다. ("그리고", "그래서" 로 시작하는 자막은 힘이 없다)
- 구어체. 읽는 글이 아니라 듣는 말이다.

## 출력 형식

JSON 으로 낸다. 각 구간의 `captions` 는 **문자열 배열**이고, 배열의 각 항목이 자막 한 줄이다.
`note` 에는 촬영·편집 지시를 짧게 적는다 (화면 전환, 자료 화면, 표정 등).

```json
{
  "segments": [
    {"key": "hook", "captions": ["...", "..."], "note": "얼굴 클로즈업"},
    {"key": "problem", "captions": ["..."], "note": ""},
    {"key": "point1", "captions": ["..."], "note": ""},
    {"key": "point2", "captions": ["..."], "note": ""},
    {"key": "point3", "captions": ["..."], "note": ""},
    {"key": "cta", "captions": ["..."], "note": ""}
  ],
  "human_slots": ["사람이 채워야 할 자리 설명"]
}
```

`key` 는 주어진 구간의 key 를 그대로 쓴다. 빠뜨리거나 새로 만들지 않는다.
