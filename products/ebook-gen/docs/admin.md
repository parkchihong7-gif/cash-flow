# 전자책 원고 생성기 — 관리자 매뉴얼

> 이 프로그램을 **운영하고 판매하는 사람**을 위한 문서입니다.
> 구매자에게 줄 문서는 `docs/client.md` 입니다.

---

## 1장. 이 프로그램이 파는 것

### 1-1. 한 문단 요약

주제를 적으면 목차를 설계하고, 그 목차로 챕터 원고를 쓰고, 워드 파일로 조립합니다.
세 단계가 따로 돌아가고 **단계마다 사람이 파일을 열어 고칠 수 있습니다.**

### 1-2. 진짜 가치는 "3단계로 쪼갠 것"입니다

"AI로 전자책 써드립니다"는 흔합니다. 이 도구가 다른 점은 **한 번에 다 주지 않는다**는 것입니다.

| 단계 | 산출물 | 사람이 하는 일 |
|---|---|---|
| 1 | `outline.yaml` | 목차 순서와 제목을 고칩니다 |
| 2 | `chapters/*.md` | 원고를 읽고 사례를 본인 것으로 바꿉니다 |
| 3 | `ebook.docx` | 워드에서 F9 눌러 목차를 갱신합니다 |

통째로 받은 원고는 고칠 엄두가 안 납니다. 챕터 파일로 쪼개져 있으면 한 장씩 손봅니다.
**이 차이를 상세페이지에 쓰세요.**

### 1-3. 챕터를 따로 호출하는 이유

한 번에 열 개 챕터를 요청하면 세 가지 문제가 생깁니다.

1. 뒤로 갈수록 품질이 떨어집니다 (앞에서 쓴 말을 반복)
2. 중간에 실패하면 전부 다시 해야 합니다
3. 응답이 길어져 잘립니다

그래서 챕터마다 따로 부르고, 앞 챕터의 **요약만** 다음 프롬프트에 넣습니다.
전문을 넣으면 토큰이 낭비되고, 아무것도 안 넣으면 같은 사례가 두 번 나옵니다.

## 2장. 준비

### 2-1. API 키

1. https://console.anthropic.com/settings/keys 에서 키 발급 (`sk-ant-` 로 시작)
2. Billing 에서 카드 등록 + 충전 (충전 없으면 키가 있어도 거절됩니다)
3. 저장소 맨 위 폴더의 `.env` 에 `ANTHROPIC_API_KEY=sk-ant-...` 저장
4. 대시보드 **기타 설정**에서 "API 키: 설정됨" 확인

> `.env` 는 절대 공유하지 마세요. 유출되면 남이 쓴 요금이 내 카드로 나갑니다.

### 2-2. 비용 감각 — 다른 프로그램보다 비쌉니다

전자책은 **한 권에 수천 원**이 듭니다. 퍼널 빌더나 대본 생성기와 자릿수가 다릅니다.

| 단계 | 호출 수 |
|---|---|
| 1단계 목차 | 1회 |
| 2단계 원고 | 챕터 수만큼 (보통 10~12회) |
| 3단계 판매글·표지 | 2회 |
| **합계** | **13~15회** (재작성 발생 시 더) |

각 챕터 호출은 2,000자 이상을 만들어야 해서 출력 토큰이 많습니다.

**비용을 줄이는 법**
- 1단계를 여러 번 돌려 목차를 확정한 뒤 2단계로 넘어가세요. 1단계는 1회 호출이라 쌉니다
- `--only` 로 문제 있는 챕터만 다시 쓰세요. 전체를 `--overwrite` 하지 마세요
- 처음엔 `--pages 20` 정도로 짧게 만들어 품질을 확인하세요

## 3장. 3단계 운용

### 3-1. 1단계 — 목차가 전부입니다

```bash
python cli.py outline "주제" --audience "대상" --pages 40 --author "이름"
```

**목차가 나쁘면 원고도 나쁩니다.** 여기서 시간을 쓰세요. 1회 호출이라 여러 번 돌려도 쌉니다.

좋은 목차인지 보는 법:
- 챕터 제목만 읽었을 때 순서가 이해되는가
- 3장을 읽으려면 2장이 필요한 구조인가
- 마지막 챕터가 "정리"가 아니라 "실행"으로 끝나는가

마음에 안 들면 `--pages` 를 바꾸거나 `--audience` 를 더 좁게 써서 다시 돌리세요.

### 3-2. `outline.yaml` 손보기

대시보드 **수정** 탭이나 편집기로 엽니다. 가장 효과가 큰 수정 셋:

1. **제목 순서 바꾸기** — 3안 중 마음에 드는 것을 맨 앞으로. 그게 표지 제목이 됩니다
2. **`key_message` 다듬기** — 각 장에서 독자가 가져갈 문장 하나.
   여기가 흐릿하면 그 장 본문이 통째로 흐릿해집니다
3. **`target_chars` 조절** — 할 말이 많은 장은 2,500, 가벼운 장은 1,500

규칙(챕터 8~12개, 번호 연속, 소제목 3~5개, 1,500~2,500자)을 어기면
2단계에서 어느 항목이 문제인지 알려줍니다.

### 3-3. 2단계 — 원고

```bash
python cli.py write outputs/<slug>/outline.yaml
```

챕터마다 한 줄씩 진행 상황이 나옵니다.

```
 1장 완료 1,977자 (1회 시도)
 2장 완료 2,140자 (2회 시도)  ⚠ 분량 이탈
```

| 표시 | 뜻 | 할 일 |
|---|---|---|
| `(1회 시도)` | 한 번에 통과 | 없음 |
| `(2회 시도)` | 금지 문구나 분량 때문에 다시 씀 | 그 장을 한 번 읽어보세요 |
| `⚠ 금지 문구` | 2번 고쳐도 남음 | 직접 고쳐야 합니다 |
| `⚠ 분량 이탈` | 목표의 ±25% 밖 | 내용이 부족하거나 반복됩니다 |
| `실패` | LLM 호출 자체가 실패 | `--only N` 으로 그 장만 다시 |

마지막에 총 글자 수와 허용 범위가 나옵니다.

```
✓ 총 19,764자 (목표 20,000자, 허용 16,000~24,000자)
```

### 3-4. `chapters/*.md` 손보기

**여기가 이 도구를 제대로 쓰는 지점입니다.**

우선순위대로:

1. **`[저자가 채울 곳: ...]` 표시** — 반드시 실제 내용으로. 그대로 두면 안 됩니다
2. **도입 사례** — AI가 만든 익명 사례를 본인 경험으로 바꾸면 책이 완전히 달라집니다
3. **수치·출처** — 참고 자료를 넣지 않았다면 숫자가 없어야 정상입니다. 있으면 확인하세요
4. **체크리스트** — 추상적인 항목("꾸준히 관리한다")을 확인 가능한 행동으로

⚠️ **제목 구조는 건드리지 마세요.** `## 도입 사례`, `## 핵심 설명`, `## 실행 체크리스트`,
`## 요약 3줄` 네 개는 3단계가 읽는 표지판입니다. 바꾸면 어느 줄이 문제인지 알려주며 멈춥니다.

### 3-5. 3단계 — docx

```bash
python cli.py build outputs/<slug>/
```

만들어진 워드 파일을 열고 **전체 선택(Ctrl+A) 후 F9**. 목차 쪽 번호가 채워집니다.
Word 필드는 문서를 열 때 계산되는 방식이라 프로그램이 미리 넣을 수 없습니다.
이 안내가 목차 페이지에도 적혀 있어 구매자가 당황하지 않습니다.

원고를 고친 뒤 3단계를 다시 돌리면 고친 내용이 반영됩니다. 몇 번을 돌려도 됩니다.
다만 `sales_copy.md` 와 `cover_brief.md` 는 매번 다시 생성되므로 그 파일을 손봤다면
다른 이름으로 복사해두세요.

## 4장. 품질을 올리는 법

효과가 큰 순서대로입니다.

| 순서 | 무엇을 | 비용 | 효과 |
|---|---|---|---|
| 1 | `--audience` 를 좁게 쓴다 | 없음 | 가장 큼 |
| 2 | `outline.yaml` 의 `key_message` 를 다듬는다 | 없음 | 큼 |
| 3 | `prompts/chapter.md` 를 고친다 | 없음 | 큼 |
| 4 | 챕터 원고를 직접 손본다 | 없음 | 큼 (시간이 듦) |
| 5 | 모델을 올린다 | 증가 | 보통 |

### 4-1. `--audience` 예시

- (X) "직장인"
- (O) "혼자 일하며 파일을 직접 관리하는 3년차 프리랜서 디자이너"

### 4-2. 프롬프트 수정

| 파일 | 바뀌는 것 |
|---|---|
| `prompts/outline.md` | 목차 구성 방식, 챕터 흐름, 제목 3안의 각도 |
| `prompts/chapter.md` | 챕터 네 부분의 구성, 문체, 사례 쓰는 법 |

효과 있는 수정 예:
- 분야를 명시: "실무 전자책 저자" → "소상공인 대상 실무서 저자"
- 싫어하는 표현을 금지 목록에 추가
- 잘 나온 문단을 "이런 톤으로" 하고 붙여두기

바꾼 뒤에는 **모의 실행이 아니라 실제 실행**으로 확인하세요.
모의 실행은 프롬프트를 쓰지 않습니다.

## 5장. 문제 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| `목차 파일이 없습니다` | 경로가 틀림 | 1단계가 알려준 경로를 그대로 복사 |
| `챕터 번호는 1부터 빠짐없이` | outline.yaml 을 고치다 번호가 꼬임 | 번호를 1부터 순서대로 |
| `target_chars` 오류 | 1,500~2,500 범위 밖 | 범위 안으로 |
| `'실행 체크리스트' 를 찾지 못했습니다` | 챕터 제목 구조를 바꿈 | `## 실행 체크리스트` 를 원래대로 |
| `원고가 없습니다` | 2단계를 안 돌림 | `python cli.py write ...` 먼저 |
| 특정 장만 계속 실패 | 그 장 내용이 정책에 걸릴 수 있음 | 제목·핵심 메시지를 바꿔보세요 |
| 분량이 계속 모자람 | `target_chars` 가 소제목 수에 비해 큼 | 소제목을 늘리거나 목표를 줄이세요 |
| 워드에서 목차가 비어 있음 | 필드 미갱신 | Ctrl+A 후 F9 |
| `credit balance is too low` | 잔액 없음 | 콘솔 Billing 충전 |
| `쿼터 초과` | 챕터를 연달아 부르다 한도 초과 | **1분 대기 후** `--only` 로 남은 장만 |

## 6장. 판매할 때

### 6-1. 상세페이지에 반드시 넣을 것

- "초안 생성기이며 발행 전 사람 검수가 필수"라는 문장
- API 키는 **구매자가 직접 발급**하고 사용료는 별도(한 권 수천 원)라는 안내
- 판매량을 약속하지 않는다는 점
- 3단계로 나뉘어 있어 사람이 고칠 수 있다는 것 — 이게 차별점입니다

### 6-2. 쓰면 안 되는 표현

성과를 단정하는 표현은 쓰지 마세요. 프로그램이 산출물은 자동 검사하지만
**상세페이지는 검사하지 않습니다.** 대시보드 **기타 설정**에서 금지 문구 목록을
확인하고 직접 대조하세요.

### 6-3. 묶음 구성

이 도구가 만드는 `sales_copy.md` 의 가격 3안이 그대로 참고가 됩니다.

- 전자책 단독
- 전자책 + 템플릿
- 전자책 + 1:1 피드백

프로그램 자체를 팔 때도 같은 구조가 통합니다. 1번 퍼널 빌더와 묶으면
"전자책을 만들고 그 전자책을 파는 페이지까지"가 한 세트가 됩니다.

### 6-4. 회원관리 연동

1. **회원관리** → 고객 추가
2. 고객 상세 → **라이선스 발급** → 프로그램 `ebook-gen` 선택
3. 대행 작업 시 테스트 탭에서 고객을 지정해 실행하면 이력이 남습니다
