# 전자책 원고 생성기 (ebook-gen)

주제 하나로 **목차 → 챕터 원고 → 완성된 docx** 까지 3단계로 만드는 CLI입니다.

> ## ⚠️ 이 도구는 초안 생성기입니다. 발행 전 사람 검수가 필수입니다.
>
> AI가 쓴 문장에는 그럴듯하지만 사실과 다른 내용이 섞일 수 있습니다.
> 이 프로그램은 **단계마다 사람이 끼어들도록** 설계했습니다.
> 1단계 산출물(`outline.yaml`)과 2단계 산출물(`chapters/*.md`)은 손으로 고치는 것이 전제이고,
> 3단계는 고쳐진 파일을 그대로 읽어 docx 로 조립합니다.

## 3단계 워크플로우

```
1단계  outline   주제 → outline.yaml         ← ✋ 여기서 목차를 고칩니다
2단계  write     outline.yaml → chapters/    ← ✋ 여기서 원고를 고칩니다
3단계  build     chapters/ → ebook.docx
```

### 1단계 — 목차 만들기

```bash
python cli.py outline "혼자 일하는 사람의 파일 관리" \
  --audience "혼자 일하며 파일을 직접 관리하는 프리랜서" \
  --pages 40 --author "홍길동"
```

`outputs/<slug>/outline.yaml` 이 만들어집니다. 안에는 제목 3안, 부제, 서문 요지,
챕터 8~12개(각각 소제목 3~5개·핵심 메시지·목표 글자 수)가 들어 있습니다.

### ✋ 수정 지점 ① — `outline.yaml`

**이 단계가 책의 품질을 가장 크게 좌우합니다.** 파일을 열어 고치세요.

| 고칠 것 | 이유 |
|---|---|
| `title_options` | 3안 중 마음에 드는 것을 **맨 앞으로** 옮기면 그게 표지 제목이 됩니다 |
| `chapters` 순서·제목 | 목차만 읽어도 흐름이 보여야 합니다. 어색한 순서를 바꾸세요 |
| `key_message` | 각 장에서 독자가 가져갈 문장. 여기가 흐릿하면 본문도 흐릿해집니다 |
| `subheadings` | 3~5개. 챕터 안의 논지 전개입니다 |
| `target_chars` | 1,500~2,500자. 할 말이 많은 장은 늘리고 가벼운 장은 줄이세요 |
| `preface` | 서문 요지. 왜 이 책을 썼는지를 본인 말로 바꾸는 편이 좋습니다 |

지켜야 하는 규칙(챕터 8~12개, 번호 연속, 소제목 3~5개, 목표 글자 수 범위)을 어기면
2단계에서 어디가 문제인지 알려줍니다.

### 2단계 — 챕터 원고 쓰기

```bash
python cli.py write outputs/<slug>/outline.yaml
```

`chapters/ch01.md` 부터 차례로 만들어집니다. 각 챕터는 1,500~2,500자이고 네 부분으로 나뉩니다.

```
## 도입 사례        구체적인 장면 하나로 시작
## 핵심 설명        소제목별 설명
## 실행 체크리스트   책을 덮고 바로 할 수 있는 4~6개
## 요약 3줄         정확히 3줄
```

**챕터마다 따로 호출합니다.** 한 챕터가 실패해도 나머지는 살아 있고, 그 챕터만 다시 쓰면 됩니다.

```bash
python cli.py write outputs/<slug>/outline.yaml --only 3 7   # 3장과 7장만 다시
python cli.py write outputs/<slug>/outline.yaml --overwrite  # 전부 다시
```

앞 챕터의 요약이 다음 챕터 프롬프트로 들어갑니다. 같은 사례를 두 번 쓰거나
같은 설명을 반복하는 것을 막기 위해서입니다.

### ✋ 수정 지점 ② — `chapters/*.md`

원고를 읽고 고치세요. **제목 구조(`## 도입 사례` 등)는 그대로 두고 내용만 바꿉니다.**
3단계가 이 구조를 보고 docx 를 조립하기 때문입니다. 구조가 깨지면 어느 줄이
문제인지 알려드립니다.

`[저자가 채울 곳: ...]` 표시가 있으면 반드시 실제 내용으로 바꾸세요.

### 3단계 — docx 조립

```bash
python cli.py build outputs/<slug>/
```

`ebook.docx`, `sales_copy.md`, `cover_brief.md` 가 만들어집니다.

## 산출물

| 파일 | 내용 |
|---|---|
| `outline.yaml` | 목차 (1단계) |
| `chapters/ch01.md` … | 챕터 원고 (2단계) |
| `ebook.docx` | 완성본. 표지·목차·서문·챕터·AI 고지 |
| `sales_copy.md` | 크몽·인스타 판매용 소개글 500자, 목차 요약, 추천 대상, 가격 3안 |
| `cover_brief.md` | 표지 디자인 지시서 + 이미지 생성 도구용 영문 프롬프트 |

### docx 서식

| 항목 | 값 |
|---|---|
| 본문 | 맑은 고딕 10.5pt |
| 줄 간격 | 1.5 |
| 여백 | 상하좌우 2.5cm |
| 페이지 | A4, 푸터 가운데 쪽 번호 |
| 제목 | Heading 1(장) / Heading 2(소제목) — 목차 필드가 잡히도록 내장 스타일 사용 |
| 체크리스트 | 표로 삽입 |

**목차 쪽 번호는 Word 에서 채워집니다.** 파일을 열고 전체 선택(Ctrl+A) 후 `F9` 를 누르세요.
Word 필드는 문서를 열었을 때 계산되는 방식이라 프로그램이 미리 넣을 수 없습니다.

`core properties` 의 comments 에 `AI-generated: true; tool: ebook-gen; date: ...` 가
기록됩니다 (인공지능기본법 제31조).

## 쪽수와 분량

`--pages` 는 목표 쪽수입니다. A4·여백 2.5cm·10.5pt·줄간격 1.5 기준으로
**한 쪽에 약 750자**로 잡아 환산합니다.

챕터 8~12개, 챕터당 1,500~2,500자라는 제약이 있어 만들 수 있는 범위는 **약 16~40쪽**입니다.
이 범위를 벗어나는 쪽수를 요청하면 맞출 수 있는 분량을 알려드리고 그대로 진행합니다.

완성 원고의 총 글자 수는 목차의 예상 분량에서 **±20% 이내**여야 하고,
벗어나면 2·3단계에서 경고합니다.

## 모의 실행

어느 단계든 `--dry-run` 을 붙이면 Claude 를 부르지 않고 예시 콘텐츠로 만듭니다.
비용이 들지 않고, 산출물이 어떤 모양인지 확인할 수 있습니다.

```bash
python cli.py outline "주제" --audience "대상" --dry-run
```

## 크몽 상세페이지 초안

### 전자책 한 권을 쓰는 데 걸리는 시간을 줄입니다

전자책을 팔고 싶은데 원고에서 막히는 경우가 많습니다.
목차는 대충 잡았는데 3장쯤에서 흐름이 무너지고, 결국 파일을 닫게 됩니다.

이 프로그램은 **목차 → 원고 → docx** 세 단계로 나눠 진행합니다.
한 번에 다 쓰려 하지 않고, 단계마다 멈춰서 고칠 수 있게 만들었습니다.

**이런 분께 맞습니다**
- 알려줄 내용은 있는데 책 구조를 잡는 데서 막히는 분
- 목차는 있는데 각 장을 어떻게 채울지 감이 없는 분
- 원고는 썼는데 워드 서식을 맞추는 게 번거로운 분

**이런 분께는 맞지 않습니다**
- AI가 쓴 글을 그대로 팔고 싶은 분 — 이 도구는 사람 검수를 전제로 만들었습니다
- 소설·에세이처럼 문체가 상품인 글 — 실무서 구조에 맞춰져 있습니다
- 터미널에서 명령어를 실행하기 어려우신 분

**드리는 것**
- 목차 자동 설계 (제목 3안, 챕터 8~12개, 챕터별 소제목과 목표 분량)
- 챕터 원고 (도입 사례 / 핵심 설명 / 실행 체크리스트 / 요약 3줄 구조)
- 완성된 워드 파일 (표지·목차·쪽 번호·체크리스트 표까지)
- 판매용 소개글과 가격 제안 3안
- 표지 디자인 지시서 (이미지 생성 도구용 프롬프트 포함)

**차별점**
- 단계마다 파일로 떨어져 사람이 고칠 수 있습니다. 통째로 받고 끝나지 않습니다.
- 챕터를 따로 호출해서 한 장이 실패해도 그 장만 다시 씁니다.
- 앞 챕터 요약을 다음 챕터에 넘겨 같은 사례가 두 번 나오는 것을 막습니다.
- 분량이 목표에서 크게 벗어나면 다시 쓰고, 그래도 안 되면 알려드립니다.
- 성과를 단정하는 표현을 자동으로 검사합니다.
- 인공지능기본법(2026.1.22 시행)에 맞춰 고지 페이지와 문서 메타데이터를 넣습니다.

**미리 알려드립니다**
- 산출물은 **초안**입니다. 읽고 고쳐서 쓰세요. 특히 사례와 수치는 직접 확인하셔야 합니다.
- Claude API 키가 필요하며 사용료는 별도입니다 (한 권에 수천 원 수준).
- 판매량은 주제·가격·유입에 따라 달라집니다. 이 도구는 원고 쓰는 시간을 줄일 뿐이며
  결과는 검증이 필요합니다.
