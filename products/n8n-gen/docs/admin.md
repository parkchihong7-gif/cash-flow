# 관리자 매뉴얼 — n8n 워크플로 JSON 생성기

이 문서는 프로그램을 **파는 쪽**(대행자·관리자)이 봅니다.
고객에게 그대로 주는 문서는 `docs/client.md` 와 매 실행마다 생성되는 `setup_guide.md` 입니다.

---

## 1장. 이 프로그램이 대신하는 일

자동화 대행의 실제 작업 시간은 대략 이렇게 나뉩니다.

| 단계 | 사람 시간 | 이 프로그램 |
|---|---|---|
| 고객 업무 듣고 자동화 범위 정하기 | 1~2시간 | 대신하지 못합니다 |
| 노드 구성 초안 짜기 | 1~3시간 | **대신합니다** |
| n8n 에서 노드 놓고 연결하기 | 30분~1시간 | **대신합니다** |
| credential 연결·테스트 | 30분~1시간 | 대신하지 못합니다 (사람이 해야 안전) |
| 설치 가이드 문서 쓰기 | 1~2시간 | **대신합니다** |
| 고객 교육·인수인계 | 1시간 | 대신하지 못합니다 |

즉 **중간 3개**를 줄입니다. 앞뒤는 사람이 하는 일이고, 그 부분이 대행의 값어치입니다.
프로그램이 대신하지 못하는 항목을 고객에게 설명할 때 그대로 쓰시면 신뢰를 얻는 데 도움이 됩니다.

## 2장. 다섯 개 모듈이 하는 일

요구 문장이 파일이 되기까지 다섯 번 손을 바꿉니다.

```
요구 문장
  │
  ├─ generator.py   Claude 에게 "계획 JSON" 을 받는다 ── 형식 틀리면 되돌려 보냄 (최대 2회)
  │                 ↑ prompts/plan.md + 템플릿 목록(자동 생성)
  ├─ schema.py      pydantic 으로 계획을 검사 ── id 중복·없는 단계 연결을 여기서 잡음
  ├─ assembler.py   템플릿 JSON 에 값만 끼워 넣어 nodes[]·connections{} 조립
  ├─ validator.py   조립 결과를 7가지로 검사
  └─ writers.py     workflow.json · plan.md · setup_guide.md · test_payload.json
```

### 2-1. `generator.py`

`prompts/plan.md` 를 시스템 프롬프트로 쓰되, **템플릿 목록은 코드가 자동으로 붙입니다**
(`nodes.catalog_text()`). 그래서 노드를 추가해도 프롬프트를 손댈 필요가 없습니다.

Claude 응답이 `Plan` 형식에 맞지 않으면, **pydantic 오류 메시지를 그대로 붙여** 다시 시킵니다.
"뭐가 틀렸는지"를 알려 주기 때문에 두 번째 시도에서 대개 맞습니다. 두 번 더 해도 안 되면
`ValueError` 를 내고 멈춥니다. 잘못된 파일을 조용히 만들지 않습니다.

`ask_fn` 을 주입할 수 있어서 테스트와 `--dry-run` 이 같은 코드 경로를 씁니다.

### 2-2. `schema.py`

`Plan` / `PlanStep` / `PlanConnection`. 여기서 잡는 것:

- 단계 `id` 중복 → "겹칩니다"
- 없는 단계로 가는 연결 → "없는 단계"
- 단계 0개
- `slugify()` 로 폴더 이름에 쓸 수 없는 글자를 걸러냄

`PlanConnection` 의 `from` 은 파이썬 예약어라 별칭(alias)으로 받습니다.

### 2-3. `assembler.py` — 가장 중요한 파일

템플릿 JSON 안의 `{{키}}` 를 계획의 파라미터로 치환합니다. 규칙 세 가지:

1. **문자열 전체가 토큰이면 타입을 보존합니다.** `"{{amount}}"` → `30` (문자열 `"30"` 이 아님).
   n8n 이 `amount` 를 숫자로 기대하는데 문자열을 주면 실행 때 실패하기 때문입니다.
2. **토큰이 문장 안에 섞여 있으면 문자열로 치환합니다.** `"{{minute}} {{hour}} * * *"` → `"0 9 * * *"`.
3. 템플릿이 모르는 파라미터는 **버립니다.** Claude 가 지어낸 칸이 노드에 들어가지 않게.

이름 중복은 `_unique_name()` 이 `이름`, `이름 2`, `이름 3` 으로 풀어 줍니다.
connections 는 노드 **이름**으로 연결되므로, 이름이 겹치면 엉뚱한 노드에 붙습니다.

위치는 x 를 250 씩 띄우고 6개마다 줄을 바꿔 y 를 200 내립니다. 화면에서 한눈에 보이게 하려는 것이지
동작과는 무관합니다.

**`workflow_id()`** — 4장에서 자세히 다룹니다. 이름의 sha256 을 16자로 접습니다.

### 2-4. `validator.py`

7가지 검사. 표는 README 6장에 있습니다. 두 가지만 짚습니다.

- **트리거 정확히 1개** — 0개면 워크플로가 시작될 방법이 없고, 2개면 n8n 에서 열리기는 하지만
  의도한 대로 돌지 않습니다.
- **고아 노드 0개** — 트리거에서 연결을 따라가 닿지 못하는 노드입니다. 화면에는 보이는데
  실행되지 않아서, 고객이 "왜 슬랙에 안 오죠" 하고 물어보는 전형적인 원인입니다.

모르는 노드 타입은 **경고**입니다. n8n 커뮤니티 노드를 쓰는 경우가 있어 오류로 막지 않습니다.

### 2-5. `writers.py`

`CREDENTIAL_GUIDE` 가 credential 종류별 발급 방법을 들고 있고, `setup_guide.md` 에는
그 워크플로가 실제로 쓰는 것만 골라 넣습니다. 쓰지도 않는 Notion 안내가 들어가면
고객이 헷갈리기 때문입니다.

테스트가 이 대응을 강제합니다. credential 이 있는 템플릿을 추가하면서 `CREDENTIAL_GUIDE` 에
안내를 안 넣으면 테스트가 실패합니다.

## 3장. 노드 템플릿 추가하기

가장 자주 하게 될 작업입니다. 예를 들어 **디스코드 메시지** 노드를 추가한다고 합시다.

### 3-1. n8n 에서 노드 JSON 꺼내기

1. `http://localhost:5678` 에서 아무 워크플로나 엽니다.
2. Discord 노드를 하나 놓고 값을 대충 채웁니다.
3. 그 노드를 클릭해 선택하고 **Ctrl+C** 를 누릅니다. 클립보드에 노드 JSON 이 들어갑니다.
4. 붙여넣으면 이런 모양입니다.

```json
{
  "parameters": { "authentication": "webhook", "content": "안녕" },
  "type": "n8n-nodes-base.discord",
  "typeVersion": 2,
  "position": [0, 0],
  "id": "…",
  "name": "Discord"
}
```

**이 방법이 중요한 이유**: `typeVersion` 과 파라미터 구조를 추측하지 않고 설치된 n8n 에서
그대로 가져오기 때문에, 문서가 낡아 틀릴 일이 없습니다.

### 3-2. 템플릿 파일로 만들기

`templates/nodes/discord-send.json`:

```json
{
  "id": "discord-send",
  "label": "디스코드 메시지",
  "description": "디스코드 채널에 메시지를 보냅니다.",
  "n8n_type": "n8n-nodes-base.discord",
  "type_version": 2,
  "is_trigger": false,
  "credential": "discordWebhookApi",
  "params": [
    {"key": "content", "label": "보낼 내용", "example": "={{ $json.summary }}"}
  ],
  "parameters": {
    "authentication": "webhook",
    "content": "{{content}}"
  }
}
```

- `id` 는 파일 이름과 같게 합니다. Claude 가 이 id 로 고릅니다.
- `description` 은 프롬프트에 그대로 들어갑니다. **여기를 잘 쓰면 Claude 가 잘 고릅니다.**
- 바뀌어야 할 값만 `{{키}}` 로 만들고, 나머지는 고정값으로 둡니다.
- `credential` 이 있으면 `writers.CREDENTIAL_GUIDE` 에 `("표시 이름", "발급 방법")` 을 추가합니다.

### 3-3. 확인

```bash
python3 -m pytest ../../tests/test_n8n_gen.py -q
python cli.py "디스코드로 알림 보내줘" --dry-run
```

프롬프트는 자동으로 갱신되므로 따로 고치지 않습니다.
`templates/examples.txt` 에 새 노드를 쓰는 예시를 넣어두면 회귀 확인이 쉬워집니다.

## 4장. 실제 n8n 으로 확인한 것과, 거기서 찾은 결함

예시 5개를 **n8n 2.35.7** 에 CLI 로 넣어 봤습니다. 처음에는 5개 전부 이렇게 실패했습니다.

```
SQLITE_CONSTRAINT: NOT NULL constraint failed: workflow_entity.id
```

원인은 workflow JSON 에 **최상위 `id` 가 없어서**입니다. 화면의 Import from File 은 id 를
알아서 만들어 주지만, `n8n import:workflow` 는 만들어 주지 않고 DB 에 그대로 넣으려다 막힙니다.

화면으로만 확인했다면 못 찾았을 결함입니다. 그래서 다음 둘을 넣었습니다.

- `assembler.workflow_id()` — 워크플로 이름의 sha256 을 nanoid 문자집합 16자로 접습니다.
  **이름이 같으면 id 도 같습니다.** 그래서 같은 워크플로를 다시 import 하면 새로 쌓이지 않고
  덮어써집니다. 고객에게 수정본을 보낼 때 중복이 생기지 않습니다.
- `validator` 의 `missing-id` 검사 — 이 조건이 다시 깨지지 않게 고정합니다.

고친 뒤 5개 모두 들어갔고, `export:workflow --all` 로 되읽어 노드 수와 연결 수가 그대로였습니다.

이 컨테이너에서는 Docker 레지스트리가 프록시에 막혀 이미지를 받지 못해 `npm install -g n8n`
설치본으로 확인했습니다. README 에는 요청하신 대로 docker 명령도 함께 적어 두었습니다.

**배운 것**: 산출물이 "열리는지"는 실제 대상 프로그램에 넣어봐야 압니다.
JSON 이 유효한 것과 n8n 이 받아 주는 것은 다른 문제입니다.

## 5장. 고객 납품 절차

### 5-1. 권장 순서

1. **상담** — 고객이 지금 손으로 하는 일을 순서대로 받아 적습니다. "매일 아침 뭐부터 하세요?"
2. **범위 확정** — 연동할 서비스에 공식 API 가 있는지 먼저 확인합니다. 없으면 그 부분은 제외합니다.
3. **생성** — `python cli.py "..."` 로 초안을 뽑습니다.
4. **본인이 먼저 돌려봅니다** — 본인 계정으로 n8n 에 넣고 credential 을 연결해 실행해 봅니다.
   **이 단계를 건너뛰고 납품하지 마세요.**
5. **파라미터 정리** — 시트 ID·채널 이름·수신자 같은 값을 고객 것으로 바꿉니다.
6. **납품** — `workflow.json` + `setup_guide.md` 를 보냅니다.
7. **설치 지원** — 화면 공유로 고객이 **직접** credential 을 넣게 합니다.
8. **인수인계** — `plan.md` 로 각 노드가 무슨 일을 하는지 설명합니다.

### 5-2. credential 을 대신 받지 마세요

고객의 비밀번호나 API 키를 카톡·메일로 받아 대신 입력하는 일은 하지 마세요.

- 주고받는 과정에서 새어 나갈 수 있습니다.
- 나중에 사고가 나면 책임 소재가 불분명해집니다.
- 화면 공유로 고객이 직접 넣게 하면 5분 더 걸릴 뿐입니다.

이 프로그램이 credential 을 이름만 자리표시로 넣는 이유가 이것입니다.
**만들어진 `workflow.json` 은 그대로 메일로 보내도 안전합니다.**

### 5-3. 월 유지보수

한 번 팔고 끝나는 것보다, 월 유지보수를 붙이는 쪽이 매출이 이어집니다. 실제로 손이 가는 일:

- n8n 버전이 올라가면서 노드 동작이 바뀌는 경우
- 고객 쪽 시트 구조·채널 이름이 바뀌는 경우
- 연동 서비스의 API 가 바뀌는 경우
- 실행 실패 알림 확인

유지보수를 팔 때는 **무엇을 해 드리는지**를 적어 두세요. "문제 생기면 봐 드립니다"로 팔면
범위 분쟁이 납니다.

## 6장. 통합 대시보드에서 쓰기

| 탭 | 하는 일 |
|---|---|
| 열람 | 이 매뉴얼과 고객 매뉴얼, 산출물 목록 |
| 수정 | `request.txt` (요구), `prompts/plan.md` (계획 프롬프트) |
| 테스트 | 모의 실행(비용 0) / 실제 실행 |
| 회원관리 | 이 프로그램을 산 고객과 이용권 |
| 설정 | Claude 모델, AI 표시, n8n 주소 |

**모의 실행을 먼저 누르세요.** Claude 를 부르지 않아 비용이 들지 않고, 산출물 형태를
그대로 볼 수 있습니다.

실행 결과의 색이 **노랑(경고)** 이면 파일은 만들어졌지만 검증에 걸린 곳이 있다는 뜻입니다.
`plan.md` 를 열어 대체된 항목이나 오류를 확인하세요. 빨강은 만들지 못한 것입니다.

## 7장. 문제 해결

| 증상 | 원인 | 조치 |
|---|---|---|
| `NOT NULL constraint failed: workflow_entity.id` | 최상위 id 없음 | 이 프로그램이 만든 파일이면 나지 않습니다. 손으로 고친 파일이면 `id` 를 되살리세요 |
| n8n 에서 "노드를 인식할 수 없음" | 해당 노드가 없는 n8n 버전 | n8n 을 올리거나, 템플릿의 `type_version` 을 그 버전에 맞춰 낮춥니다 |
| 실행은 되는데 아무 일도 안 일어남 | 고아 노드 | validator 가 잡습니다. 로그에 `orphan-node` 가 있는지 보세요 |
| IF 분기가 한쪽으로만 감 | `from_output` 이 둘 다 0 | 계획의 연결에서 참=0, 거짓=1 입니다. `plan.md` 의 연결 표를 확인 |
| Claude 노드가 401 | Header Auth 이름이 `x-api-key` 가 아님 | n8n Credentials → Header Auth 의 Name 칸을 확인 |
| 슬랙에 안 옴 | 봇을 채널에 초대하지 않음 | 채널에서 `/invite @봇이름` |
| 텔레그램에 안 옴 | 봇과 대화를 시작한 적 없음 | 봇에게 아무 메시지나 한 번 보냅니다 |
| `계획을 만들지 못했습니다` | 3회 시도 모두 형식 불일치 | 요구를 더 구체적으로 적거나 단계를 쪼개세요 |
| 대체 항목이 계속 나옴 | 필요한 노드가 템플릿에 없음 | 3장을 보고 템플릿을 추가하세요 |
| `--push` 가 401 | API 키 문제 | n8n Settings → API 에서 새로 발급 |

## 8장. 규정 관련

- **AI 생성물 표시** — `plan.md`·`setup_guide.md` 에 기본으로 들어갑니다(인공지능기본법 제31조).
  끄지 않는 것을 권합니다. 대행 견적서나 계약서에도 "설계에 생성형 AI 를 활용함"을 적어 두세요.
- **비밀키** — `.env` 에만 두고 커밋하지 않습니다. `workflow.json` 에는 이름만 들어갑니다.
- **공식 API 만** — 브라우저 매크로나 비밀번호 저장형 자동화는 만들지 않습니다.
- **사람 검수 지점** — 만들어진 워크플로는 비활성 상태이고, 켜는 것은 사람의 결정입니다.
  이 순서를 우회하는 기능은 넣지 마세요.
- **판매 문구** — 성과를 단정하는 표현을 쓰지 않습니다. 자동화는 시간을 줄이는 것이지
  없던 성과를 만드는 것이 아니라고 설명하는 편이, 나중의 분쟁을 줄입니다.
