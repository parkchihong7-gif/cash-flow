# 상세페이지 작성 규칙

크몽 상세페이지는 위에서 아래로 읽으며 **"이 사람에게 맡겨도 되나"** 를 판단하는 문서다.
자랑이 아니라 판단 재료를 준다.

## 섹션별 규칙

### 헤드라인 (30자 이내)
무엇을 해 주는지 한 줄. 서비스명을 그대로 반복하지 않는다.
- (X) "최고의 로고 디자인 서비스"
- (O) "3일 안에 쓸 수 있는 로고 파일 일체"

### 서비스 요약 3줄
각 줄이 하나의 정보. 무엇을·누구에게·어떻게.

### 이런 분께 추천 (4~5개)
**상황**으로 쓴다. 속성이 아니라.
- (X) "스타트업 대표님"
- (O) "명함을 만들어야 하는데 로고가 없는 분"

마지막에 **맞지 않는 경우 2개**도 넣는다. 구매 전 걸러지면 분쟁이 줄어든다.

### 제공 내용 (표)
`what_you_deliver` 를 표로. 각 항목에 "무엇을 받는지"와 "어떤 형식인지"를 적는다.

### 작업 프로세스 5단계
각 단계에 이름·하는 일·걸리는 시간. 구매자가 언제 무엇을 해야 하는지 알 수 있게.

### 차별점
`differentiators` 3개를 각각 문단으로 풀어 쓴다. **왜 그게 구매자에게 이득인지**까지.

### 자주 묻는 질문 (7개)
최소 3개는 아래에 답한다.
1. 가격이 비싼 것 아닌가 (무엇을 대신하는 비용인지)
2. 나에게 맞을까 (맞지 않는 경우도 함께)
3. 늦어지거나 마음에 안 들면 (수정·환불 절차)

나머지는 진행 방식·파일 형식·저작권 등 실무 질문.

### 작업 전 준비 요청사항
구매자가 미리 준비할 것. 이게 없으면 작업이 늦어진다는 점도 밝힌다.

### 환불·수정 정책
**전자상거래법상 필수 표기다.** 아래를 반드시 포함한다.
- 수정 가능 횟수와 범위
- 추가 수정 시 비용
- 환불 가능한 경우와 불가능한 경우
- 작업 시작 후 취소 시 처리 방식

## 출력 형식

```json
{
  "headline": "30자 이내",
  "summary": ["3줄", "각 줄", "하나의 정보"],
  "recommended_for": ["상황1", "상황2", "상황3", "상황4"],
  "not_for": ["맞지 않는 경우1", "맞지 않는 경우2"],
  "deliverables": [{"item": "산출물명", "detail": "형식과 내용"}],
  "process": [{"step": "1단계 이름", "what": "하는 일", "when": "소요 시간"}],
  "differentiators": [{"title": "차별점", "body": "왜 구매자에게 이득인지"}],
  "faq": [{"q": "질문", "a": "답변"}],
  "prepare": ["미리 준비할 것1", "준비할 것2"],
  "policy": {
    "revisions": "수정 횟수와 범위",
    "extra_cost": "추가 수정 비용",
    "refund_ok": "환불 가능한 경우",
    "refund_no": "환불이 어려운 경우",
    "cancel": "작업 시작 후 취소 시"
  }
}
```
