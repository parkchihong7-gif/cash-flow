# 공구 정산 엑셀 자동 생성기

인스타 공동구매 운영자가 쓰는 **주문·정산·재고 엑셀 장부**를 만들고,
회차가 끝나면 **정산 리포트**까지 뽑습니다.

```
상품 CSV ──→ 빈 장부(xlsx)
주문 CSV ──→ 장부에 주문 채우기 ──→ 정산 리포트(md)
```

> **이 도구는 장부를 만들어 줄 뿐, 정산을 확정해 주지 않습니다.**
> 마지막에 순이익을 통장 잔액 증감과 맞춰 보는 것은 사람이 해야 합니다.
> 차이가 나면 대개 배송비나 수수료율 설정이 실제와 다른 것입니다.

---

## 1. 왜 엑셀인가

공구 운영자는 대부분 이미 엑셀이나 구글시트를 씁니다. 새 프로그램을 배우게 하는 것보다,
**쓰던 도구 안에서 계산이 저절로 되게** 만드는 편이 실제로 쓰입니다.
그래서 이 도구는 값을 계산해서 적어 넣지 않고 **수식을 넣습니다.**
주문 한 줄을 고치면 정산·재고·배송 목록이 함께 바뀝니다.

### 엑셀 2010 호환 함수만 씁니다

`XLOOKUP`·`FILTER`·`SORT`·`TEXTJOIN` 같은 신형 함수는 구형 엑셀에서 `#NAME?` 로 깨집니다.
고객이 어느 버전을 쓰는지 알 수 없으므로 **아예 쓰지 않습니다.**

실제로 쓰는 함수는 열 가지뿐입니다.

```
SUM  SUMIFS  COUNTA  COUNTIFS  INDEX  MATCH  IFERROR  IF  ROUND  RANK
```

`lint.py` 가 만들어진 파일의 수식을 전부 훑어 이 규칙을 기계적으로 확인합니다.
목록에 없는 함수가 하나라도 있으면 `new` 명령이 종료 코드 2 로 멈춥니다.

## 2. 설치

```bash
pip install -r requirements.txt     # 루트 requirements.txt 로도 됩니다
cp .env.example .env                # 리포트 코멘트를 쓸 때만 API 키가 필요합니다
```

장부를 만들고 주문을 넣는 데는 **API 키가 필요 없습니다.** 리포트의 세 줄 코멘트에만 씁니다.

## 3. 사용법 — 세 단계

### ① 빈 장부 만들기

```bash
python cli.py new \
  --name "9월 원두 공구" \
  --products samples/products.csv \
  --start 2026-09-01 --end 2026-09-14 \
  --cost 9000 --price 15000
```

→ `outputs/groupbuy_9월-원두-공구.xlsx`

상품 CSV 는 이 다섯 칸입니다.

```csv
상품코드,옵션,공급가,판매가,초기재고
COFFEE-01,에티오피아 200g,9000,15000,60
```

| 옵션 | 뜻 | 기본값 |
|---|---|---|
| `--name` | 공구명 (필수) | — |
| `--round` | 회차. 파일 이름에 들어갑니다 | 공구명에서 자동 |
| `--start` / `--end` | 기간 | 오늘 / 시작일+13일 |
| `--cost` / `--price` | 기본 공급가·판매가 | 0 / 10000 |
| `--shipping` | 건당 배송비 | 3000 |
| `--payment-fee` | 결제수수료율 | 0.032 |
| `--platform-fee` | 플랫폼수수료율 | 0 |
| `--vat-rate` / `--no-vat` | 부가세 | 0.1 / 적용함 |

### ② 주문 CSV 넣기

```bash
python cli.py import-orders outputs/groupbuy_9월-원두-공구.xlsx 주문.csv --verbose
```

쇼핑몰·구글폼마다 컬럼 이름이 달라서 `mapping.yaml` 이 이름을 맞춰 줍니다.
`타임스탬프`·`구매자명`·`주문상태` 같은 이름도 알아봅니다.

**같은 파일을 두 번 넣어도 주문이 두 배가 되지 않습니다.** 주문번호로 걸러냅니다.

이런 것은 조용히 넘어가지 않고 알려 줍니다.

- 이미 있는 주문번호 → 건너뛴 건수
- 상품 시트에 없는 상품코드 → 공급원가가 0원으로 잡힌다고 경고
- 모르는 배송상태 → '대기' 로 두고 무엇이었는지 알려 줌
- 주문일을 읽지 못한 줄 → 몇 번째 줄인지

하나라도 있으면 종료 코드가 `2` 입니다 (만들어졌지만 사람이 볼 곳이 있음).

### ③ 정산 리포트

```bash
python cli.py report outputs/groupbuy_9월-원두-공구.xlsx --dry-run   # 비용 없음
python cli.py report outputs/groupbuy_9월-원두-공구.xlsx             # 실제
```

→ `outputs/report_9월-원두-공구.md`

정산 요약 · 주문 현황 · 상품별 실적 · 재고 경고 · 발송 대기 · **Claude 코멘트 3줄** ·
다음에 할 일.

### 덤: 검산

```bash
python cli.py verify outputs/groupbuy_9월-원두-공구.xlsx
```

엑셀이 계산한 값과 파이썬이 따로 계산한 값을 16개 항목에 걸쳐 맞춰 봅니다.
**납품 전에 한 번 돌려 보세요.**

## 4. 시트 여섯 장

| # | 시트 | 하는 일 |
|---|---|---|
| 1 | **설정** | 공구명·기간·공급가·판매가·마진율·배송비·수수료율·부가세. 여기를 고치면 전부 다시 계산됩니다 |
| 2 | **상품** | 상품코드·옵션·공급가·판매가·초기재고와 **현재재고(수식)** |
| 3 | **주문** | 주문 한 줄씩. 배송상태는 드롭다운, 상품코드는 상품 시트에서 고르는 목록 |
| 4 | **정산** | 총매출 → 순이익까지 전부 수식. 아래에 상품별 실적표(SUMIFS) |
| 5 | **배송** | 배송상태가 `대기` 인 주문만 **INDEX/MATCH** 로 뽑은 발송 목록. 택배사 양식 순서 |
| 6 | **대시보드** | 일별 매출 추이(꺾은선), 상품별 이익 순위(막대), 재고 경고 |

### 계산 규칙

```
순매출   = 총매출 − (취소 + 환불)
순이익   = 순매출 − 결제수수료 − 플랫폼수수료 − 공급원가 − 배송비 − 부가세
순마진율 = 순이익 / 순매출
현재재고 = 초기재고 − 유효판매수량        (취소·환불은 재고를 까지 않습니다)
배송비   = 유효 주문건수 × 건당 배송비
부가세   = 순매출 ÷ 1.1 × 0.1            (판매가에 부가세가 포함된 경우)
```

### 조건부 서식

- 배송상태가 **취소·환불**인 줄 → 회색 + 취소선
- **현재재고 10개 미만** → 빨강

### 도우미 열

상품 시트의 `F~J`, 주문 시트의 `N~O` 는 **자동 계산용 도우미 칸**입니다.
회색 머리글에 설명이 붙어 있습니다. 보기 싫으면 열을 숨기되 **지우지는 마세요.**
지우면 배송 시트와 대시보드가 빈칸이 됩니다.

## 5. 검증 — "수식이 들어갔다" 와 "열어 보면 맞다" 는 다른 문제

openpyxl 은 수식을 **글자로 써 넣을 뿐 계산하지 않습니다.**
그래서 수식이 들어갔는지 확인하는 것만으로는 부족합니다.

이 저장소는 만들어진 파일을 **실제로 다시 계산해서** 파이썬으로 따로 구한 값과 맞춰 봅니다.

```
엑셀 수식 계산  ←→  calc.py 의 파이썬 계산
```

두 계산은 서로 독립적입니다. `calc.py` 는 수식 문자열을 흉내 내지 않고 정의대로 다시 계산합니다.
그래서 한쪽이 틀리면 테스트가 잡아냅니다. 맞춰 보는 것은 순이익 하나가 아니라

- 정산 요약 **16개 항목 전부**
- 상품별 판매수량·매출·이익·순위
- 상품 시트의 현재재고
- 배송 시트가 뽑아낸 대기 주문
- 대시보드 일별 매출과 재고 경고 목록

재계산 엔진은 두 가지를 이 순서로 시도합니다.

1. **LibreOffice** (`soffice --headless`) — 실제 스프레드시트 프로그램
2. **formulas** — 엑셀 수식을 해석하는 파이썬 라이브러리

### 이 저장소에서 실제로 쓴 엔진

개발 컨테이너의 LibreOffice 24.2.7 은 **어떤 파일도 열지 못합니다**
(xlsx·csv 모두 `Error: source file could not be loaded`). 환경 문제이지 장부의 문제가 아니며,
LibreOffice 가 정상인 컴퓨터에서는 1번 경로가 먼저 쓰입니다.
그래서 여기서는 **formulas 1.3.4** 로 검증했습니다. 결과는 이렇습니다.

```
엔진 formulas · 셀 2660개
✓ 정산 요약 16개 항목이 모두 일치
✓ 수식 오류 0건 (#REF!·#NAME? 없음)
수식 1780개 · 쓰인 함수 COUNTA, COUNTIFS, IF, IFERROR, INDEX,
MATCH, RANK, ROUND, SUM, SUMIFS — 모두 엑셀 2010 호환
```

`python cli.py verify <파일>` 로 언제든 다시 확인할 수 있습니다.

## 6. 두 번째 회차부터

`import-orders` 는 기존 파일을 **열어 고치는 것이 아니라 통째로 다시 만듭니다.**
openpyxl 로 파일을 읽고 다시 쓰면 **차트가 사라지기** 때문입니다.
그래서 설정·상품·주문을 읽어 모델로 되돌린 뒤(`reader.py`) 새 주문을 합쳐 다시 만듭니다.
차트·조건부 서식·드롭다운이 모두 살아남습니다.

덕분에 **엑셀에서 직접 고친 내용도 반영됩니다.** 설정 시트의 수수료율을 바꿔 두면
다음 `import-orders` 때 그 값이 그대로 따라옵니다.

다만 **도우미 열을 지우거나 시트 이름을 바꾸면** 되읽지 못합니다.
그때는 "이 프로그램이 만든 장부가 아닌 것 같습니다" 라고 알려 줍니다.

## 8. 코멘트가 숫자를 지어내지 못하게 하는 법

리포트의 세 줄 코멘트는 Claude 가 씁니다. 여기서 가장 위험한 것은
**모델이 그럴듯한 숫자를 만들어 내는 것**입니다. 정산 문서에 가짜 숫자가 들어가면
장부 전체를 믿을 수 없게 됩니다.

그래서 프롬프트로 부탁하는 데서 그치지 않고 **기계적으로 막습니다.**

1. Claude 에게는 `[수치]` 블록 — 엑셀이 계산한 값만 담은 JSON — 을 줍니다.
2. 답이 오면 글에 나온 숫자를 전부 뽑아냅니다.
3. `[수치]` 에서 나올 수 있는 값이 아니면 **무엇이 틀렸는지 알려 주고 다시 시킵니다** (최대 2회).
4. 끝내 안 되면 그 줄을 빼고, **무엇을 뺐는지 리포트에 적습니다.**

금지 표현 검사도 같은 자리에서 함께 돕니다.

## 9. 판매 문구 초안

### 서비스 제목 후보

- 공동구매 주문·정산·재고 엑셀 제작
- 인스타 공구 정산 장부 + 발송 목록 자동화
- 공구 회차별 정산 리포트 세팅

### 상세 설명 초안

> 공구를 몇 번 돌리고 나면 대개 같은 데서 막힙니다.
> 주문은 폼으로 받았는데, 누구에게 뭘 보냈는지는 카톡을 뒤져야 하고,
> 이번 회차에 얼마가 남았는지는 계산기를 두드려야 아는 상태요.
>
> 주문 CSV 한 장을 넣으면 **정산·재고·발송 목록이 한꺼번에 채워지는 엑셀**을 만들어 드립니다.
>
> **드리는 것**
> - 시트 6장짜리 엑셀 장부 (설정·상품·주문·정산·배송·대시보드)
> - 쓰시는 폼·쇼핑몰의 컬럼 이름에 맞춘 주문 가져오기 설정
> - 회차별 정산 리포트
> - 사용 매뉴얼
>
> **말씀드릴 점**
> - 이 장부는 계산을 대신할 뿐, 정산을 확정해 드리지 않습니다. 마지막에 통장 잔액과 맞춰 보시는 것은 직접 하셔야 합니다.
> - 수량이 자동으로 재고에서 빠지려면 주문 시트의 상품코드가 상품 시트와 같아야 합니다. 첫 회차에 한 번 맞춰 드립니다.
> - 엑셀 2010 이상이면 열립니다. 구글시트에서도 열리지만 차트 모양은 조금 달라집니다.
>
> 이 장부의 정산 리포트 코멘트에는 생성형 AI 를 사용하며, 문서에 그 사실을 표시합니다.

### 패키지 예시

| | BASIC | STANDARD | PREMIUM |
|---|---|---|---|
| 엑셀 장부 | ○ | ○ | ○ |
| 주문 CSV 매핑 | 기본 | 쓰시는 폼에 맞춤 | 쇼핑몰 2곳까지 |
| 정산 리포트 | — | ○ | ○ |
| 사용 안내 | 문서 | 문서 + 화면공유 1회 | 문서 + 화면공유 2회 |

가격은 작업 범위에 맞춰 직접 정하세요.

## 10. 하지 않는 것

- 결제·환불을 대신 처리하지 않습니다. 장부에 적을 뿐입니다.
- 고객 연락처를 어디로도 보내지 않습니다. 파일은 컴퓨터 안에만 있습니다.
- 주문을 자동으로 확정하거나 발송 처리하지 않습니다. 상태를 바꾸는 것은 사람입니다.
- 실제 성과를 단정하지 않습니다. 장부는 일어난 일을 적는 도구입니다.
