# 관리자 매뉴얼 — 공구 정산 엑셀 자동 생성기

이 문서는 프로그램을 **파는 쪽**(관리자·대행자)이 봅니다.
고객에게 그대로 주는 문서는 `docs/client.md` 입니다.

---

## 1장. 이 프로그램이 파는 것

공구 운영자가 실제로 겪는 일은 이렇습니다.

> 폼으로 주문을 받았다. 엑셀로 내려받았다. 누구에게 뭘 보냈는지는 카톡을 뒤진다.
> 재고는 머릿속에 있다. 이번 회차에 얼마 남았는지는 아직 모른다.

이 프로그램이 줄여 주는 것은 **계산과 옮겨 적기**입니다.

| 단계 | 사람 시간 | 이 프로그램 |
|---|---|---|
| 상품·가격 정하기 | 1시간 | 대신하지 못합니다 |
| 주문 받기 (폼·DM) | — | 대신하지 못합니다 |
| 주문을 장부로 옮기기 | 회차당 1~2시간 | **대신합니다** |
| 발송 목록 만들기 | 회차당 30분~1시간 | **대신합니다** |
| 재고 세기 | 회차당 30분 | **대신합니다** |
| 정산 계산 | 회차당 1시간 | **대신합니다** |
| 통장과 맞춰 보기 | 30분 | 대신하지 못합니다 (사람이 해야 안전) |
| 고객 응대 | — | 대신하지 못합니다 |

회차당 서너 시간쯤이고, **매 회차마다 반복되는 시간**이라는 점이 중요합니다.
한 번 세팅해 두면 다음 회차부터는 주문 CSV 한 장만 넣으면 됩니다.
이것이 월 유지보수를 붙이기 좋은 이유이기도 합니다.

## 2장. 설계에서 가장 중요한 두 가지 판단

### 2-1. 값을 적지 않고 수식을 넣는다

openpyxl 로 계산해서 **결과 숫자를 적어 넣는** 방법이 훨씬 쉽습니다. 그렇게 하지 않았습니다.

숫자를 적어 넣으면 고객이 주문 한 줄을 고쳤을 때 정산이 따라오지 않습니다.
그러면 고객은 매번 저희에게 다시 돌려 달라고 하거나, 아니면 장부를 안 쓰게 됩니다.
**수식을 넣으면 장부가 고객 손에서 살아 있습니다.**

대신 어려워지는 것이 있습니다. openpyxl 은 수식을 **글자로 써 넣을 뿐 계산하지 않습니다.**
그래서 "수식이 들어갔다"가 "열어 보면 맞다"를 증명하지 못합니다. 5장에서 다룹니다.

### 2-2. 엑셀 2010 함수만 쓴다

`XLOOKUP` 을 쓰면 코드가 훨씬 짧아집니다. 하지만 엑셀 2010·2016 에서는 `#NAME?` 로 깨집니다.
고객이 어느 버전을 쓰는지 알 수 없고, **깨진 장부를 받은 고객은 환불을 요구합니다.**

그래서 `INDEX`+`MATCH` 조합으로 씁니다. 길지만 어디서든 열립니다.
`lint.py` 가 만들어진 파일의 수식을 전부 훑어 이 규칙을 기계적으로 확인하고,
목록에 없는 함수가 하나라도 있으면 `new` 명령이 종료 코드 2 로 멈춥니다.

허용 목록은 `lint.ALLOWED_FUNCTIONS` 에 있습니다. 함수를 추가하려면
**엑셀 2010 에 그 함수가 있는지 먼저 확인하고** 목록에 넣으세요.

## 3장. 모듈이 하는 일

```
상품 CSV ─┐
          ├─ schema.py     Settings / Product / Order / Ledger 로 검사
주문 CSV ─┘   importer.py  컬럼·상태·결제수단 이름 맞추기
              │
              ├─ workbook.py  시트 6장을 만든다 (수식·서식·차트·드롭다운)
              ├─ reader.py    만든 장부를 도로 읽는다 (두 번째 회차용)
              ├─ calc.py      엑셀과 **따로** 계산한다
              ├─ recalc.py    만든 엑셀을 실제로 다시 계산한다
              ├─ lint.py      엑셀 2010 호환 함수만 썼는지 본다
              └─ report.py    정산 리포트 + Claude 코멘트 3줄
```

### 3-1. `layout.py` 를 먼저 보세요

시트 이름과 셀 주소가 전부 여기 있습니다. 수식을 만드는 쪽과 값을 읽는 쪽,
그리고 테스트가 **같은 상수를 봅니다.** 한쪽만 고쳐 어긋나는 일을 막으려는 것입니다.

정산 요약의 항목을 하나 추가하려면 `SUMMARY` 에 행 번호를, `SUMMARY_LABELS` 에
이름과 설명을 넣고, `workbook._build_ledger_sheet` 의 `formulas` 에 수식을,
`calc.Totals` 에 같은 이름의 필드를 넣으면 됩니다. 테스트가 자동으로 둘을 맞춰 봅니다.

### 3-2. 빈 줄 처리 — `IF($A2="","",…)`

줄 단위 수식은 전부 이렇게 감쌌습니다. 이유가 있습니다.

`현재재고 = 초기재고 − 판매수량` 을 그냥 쓰면, 상품이 없는 빈 줄에서 `0 − 0 = 0` 이 되고,
`0 < 10` 이라 **재고 경고에 빈 줄이 스무 개 뜹니다.** 대시보드가 쓸모없어집니다.

`IF($A2="","",…)` 로 감싸면 빈 줄은 빈 문자열이 되고, 엑셀은 문자열을 숫자 비교에서
제외하므로 경고에 잡히지 않습니다.

### 3-3. 도우미 열

| 시트 | 열 | 하는 일 |
|---|---|---|
| 상품 | `G` 유효판매수량 | 현재재고 계산용 |
| 상품 | `H` 취소·환불수량 | 눈으로 확인용 |
| 상품 | `I` 재고경고순번 | 대시보드가 이걸 `MATCH` 로 찾습니다 |
| 상품 | `J` 조회키 | `상품코드\|옵션`. 두 칸으로 찾는 대신 한 칸으로 |
| 주문 | `N` 발송순번 | 배송 시트가 이걸 `MATCH` 로 찾습니다 |
| 주문 | `O` 조회키 | 상품별 SUMIFS 가 이 칸을 봅니다 |

**조회키를 쓰는 이유**: SUMIFS 로 상품코드와 옵션 두 칸을 함께 맞추려면 조건을 두 개 걸어야 하는데,
옵션이 빈칸인 상품이 섞이면 엑셀의 빈칸 조건 처리가 헷갈립니다
(빈칸 조건이 0 과 빈칸 양쪽에 걸립니다). `코드|옵션` 한 칸으로 만들면 이 문제가 사라집니다.

**재고경고순번·발송순번의 원리**: 배열 수식 없이 "조건에 맞는 n번째 줄" 을 뽑는 고전적인 방법입니다.

```
주문!N2 = IF($J2="대기", COUNTIFS($J$2:$J2,"대기"), "")
```

위에서부터 세면서 대기 건에만 1, 2, 3… 을 붙입니다. 그러면 배송 시트에서

```
배송!A2 = IFERROR(INDEX(주문!$C$2:$C$130, MATCH(1, 주문!$N$2:$N$130, 0)), "")
```

로 첫 번째 대기 건을 꺼낼 수 있습니다. `MATCH` 의 찾는 값은 줄마다 1, 2, 3… 으로 박아 넣습니다.
`ROW()-1` 을 쓸 수도 있지만, 사용자가 줄을 삽입하면 어긋나므로 고정값이 안전합니다.

도우미 열 머리글은 회색이고 설명 메모가 붙어 있습니다.
**고객이 지우면 배송 시트와 대시보드가 빈칸이 됩니다.** 인수인계 때 꼭 말해 주세요.

### 3-4. 순위의 동점 처리

이익이 같은 상품이 둘이면 `RANK` 는 둘 다 같은 순위를 줍니다. 그러면 대시보드가
`MATCH(4, 순위범위, 0)` 로 4위를 찾을 때 하나만 걸리고 5위는 영영 안 나옵니다.

그래서 이렇게 씁니다.

```
RANK(이익, 이익범위) + COUNTIFS(이익범위의_위쪽, 같은_이익) - 1
```

위에 있는 같은 값의 개수를 더해 **순위를 겹치지 않게** 만듭니다.
`calc.py` 도 같은 규칙으로 계산하고, 테스트가 둘을 맞춰 봅니다.

## 4장. 주문 CSV 매핑 — 실전에서 가장 손이 가는 부분

고객마다 쓰는 폼이 다르고, 컬럼 이름이 다릅니다. 이걸 코드로 박아 두면
고객이 바뀔 때마다 코드를 고쳐야 합니다. 그래서 `mapping.yaml` 로 뺐습니다.

```yaml
columns:
  주문일: [주문일, 결제일, 타임스탬프, Timestamp, ...]
  고객명: [고객명, 구매자명, 수취인명, ...]
```

비교할 때 **앞뒤·사이 공백을 지우고 소문자로** 맞춥니다. `주문 번호` 와 `주문번호` 는 같게 봅니다.

### 새 고객을 받으면

1. 고객의 주문 CSV 를 받습니다.
2. `python cli.py import-orders <장부> <csv> --verbose` 로 돌려 봅니다.
3. 매핑 결과가 출력됩니다. 못 찾은 칸이 있으면 CSV 의 실제 컬럼 목록을 알려 줍니다.
4. `mapping.yaml` 의 해당 줄에 그 이름을 후보로 추가합니다.

고객마다 다른 매핑을 쓰려면 `--mapping 고객A.yaml` 로 파일을 나누세요.

### 상태 이름 맞추기

쇼핑몰마다 `배송완료`·`구매확정`·`상품준비중` 처럼 이름이 다릅니다.
`mapping.yaml` 의 `status` 가 이걸 다섯 가지로 옮깁니다.
**모르는 상태는 '대기' 로 두고 무엇이었는지 알려 줍니다.** 조용히 넘어가지 않습니다.

### 필수 칸

`주문일`·`주문번호`·`상품코드`·`수량`·`결제금액` 다섯 개는 없으면 멈춥니다.
멈출 때 **CSV 에 실제로 있던 컬럼 목록을 함께 보여 줍니다.** 그래야 고칠 수 있습니다.

### 인코딩

스마트스토어는 `cp949` 로 내려주는 경우가 많습니다.
`utf-8-sig → utf-8 → cp949 → euc-kr` 순으로 열어 봅니다.

## 5장. 검증 — 이 상품의 핵심

### 5-1. 왜 어려운가

openpyxl 은 수식을 계산하지 않습니다. 파일을 열어 보면 수식 칸이 **비어 있습니다**
(캐시된 값이 없습니다). 엑셀이나 LibreOffice 가 열 때 비로소 계산됩니다.

그래서 "SUMIFS 수식이 B3 에 들어갔다" 를 확인해 봐야, 그 수식이 **맞는 범위를 가리키는지**,
**열었을 때 맞는 값이 나오는지**는 알 수 없습니다. 범위를 한 줄 잘못 잡아도 테스트는 통과합니다.

### 5-2. 어떻게 푸는가

만들어진 파일을 **실제로 다시 계산해서**, 파이썬으로 따로 구한 값과 맞춰 봅니다.

```
엑셀 수식 계산 (recalc.py)  ←→  파이썬 계산 (calc.py)
```

핵심은 **두 계산이 독립적이어야 한다**는 것입니다. `calc.py` 는 수식 문자열을 흉내 내지 않고
정의대로 다시 계산합니다. 그래서 한쪽이 틀리면 값이 어긋나고 테스트가 잡아냅니다.

맞춰 보는 항목:

- 정산 요약 **16개 전부** (순이익만이 아니라)
- 상품별 판매수량·매출·이익·순위
- 상품 시트의 현재재고
- 배송 시트가 뽑아낸 대기 주문 (사람·주문번호·수량까지)
- 대시보드 일별 매출, 이익 순위, 재고 경고 목록
- 수식 오류(`#REF!`·`#NAME?`) 0건

### 5-3. 재계산 엔진

1. **LibreOffice** (`soffice --headless --convert-to xlsx`) — 실제 스프레드시트 프로그램
2. **formulas** — 엑셀 수식을 해석하는 파이썬 라이브러리

1번을 먼저 씁니다. 실패하면 2번으로 넘어가고, **둘 다 없으면 테스트가 건너뛰지 않고 실패합니다.**
완료 기준이 걸린 검증이라 조용히 넘어가면 안 됩니다.

### 5-4. 이 저장소에서 실제로 쓴 엔진

개발 컨테이너의 LibreOffice 24.2.7 은 **어떤 파일도 열지 못합니다.**
xlsx 도 csv 도 `Error: source file could not be loaded` 로 실패합니다.
환경 문제이지 장부의 문제가 아닙니다. LibreOffice 가 정상인 컴퓨터에서는 1번이 먼저 쓰입니다.

그래서 여기서는 **formulas 1.3.4** 로 검증했고, 결과는 이렇습니다.

```
엔진 formulas · 셀 2660개
✓ 정산 요약 16개 항목 모두 일치
✓ 수식 오류 0건
수식 1780개 · 함수 10종 모두 엑셀 2010 호환
```

`python cli.py verify <파일>` 이 같은 검사를 언제든 돌립니다. **납품 전에 한 번 돌리세요.**

### 5-5. 반올림 함정

엑셀 `ROUND` 는 0.5 를 **0 에서 먼 쪽으로** 올립니다. 파이썬 `round` 는 **짝수로 붙입니다**
(banker's rounding). `round(2.5)` 는 2 입니다.

이걸 모르고 비교하면 수수료·부가세가 **1원씩** 어긋나고, 원인을 찾느라 한참 헤맵니다.
`calc.excel_round()` 가 `Decimal` 로 엑셀과 같게 맞춥니다. 테스트가 이 차이를 고정합니다.

## 6장. 두 번째 회차 — 파일을 다시 만드는 이유

`import-orders` 는 기존 파일을 열어 고치지 않고 **통째로 다시 만듭니다.**

openpyxl 로 파일을 읽고 다시 저장하면 **차트가 사라집니다.** 읽을 때 차트 정의를 들고 오지
않기 때문입니다. 그러면 두 번째 회차부터 대시보드가 빈 껍데기가 됩니다.

그래서 `reader.py` 가 설정·상품·주문을 읽어 모델로 되돌리고, 새 주문을 합친 뒤
`workbook.py` 가 전부 다시 만듭니다. 차트·조건부 서식·드롭다운이 모두 살아남습니다.

**덤으로 얻는 것**: 고객이 엑셀에서 직접 고친 설정(수수료율·배송비 등)이 그대로 따라옵니다.
`reader.py` 가 설정 시트의 값을 읽어 오기 때문입니다.

**주의**: 도우미 열을 지우거나 시트 이름을 바꾸면 되읽지 못합니다.
그때는 "이 프로그램이 만든 장부가 아닌 것 같습니다" 라고 알려 줍니다.

## 7장. 코멘트가 숫자를 지어내지 못하게 하기

정산 문서에 가짜 숫자가 들어가면 **장부 전체를 믿을 수 없게 됩니다.**
프롬프트로 "지어내지 마라" 고 부탁하는 것만으로는 부족해서, 기계적으로 막습니다.

1. Claude 에게 `[수치]` 블록 — 엑셀이 계산한 값만 담은 JSON — 을 줍니다.
2. 답이 오면 글에 나온 숫자를 전부 뽑아냅니다 (천 단위 쉼표, 퍼센트, 만 단위 표기까지).
3. `[수치]` 에서 나올 수 있는 값이 아니면 **무엇이 틀렸는지 알려 주고 다시 시킵니다** (최대 2회).
4. 끝내 안 되면 그 줄을 빼고 **무엇을 뺐는지 리포트에 적습니다.** 조용히 지우지 않습니다.

금지 표현 검사도 같은 자리에서 함께 돕니다.

허용 범위는 `report._allowed_numbers()` 가 만듭니다. 순위·건수처럼 자연스럽게 나오는
0~31 의 작은 정수는 허용합니다. 너무 빡빡하면 멀쩡한 문장이 계속 반려되기 때문입니다.

## 8장. 고객 납품 절차

1. **상담** — 지금 어떻게 주문을 받고 계신지, 회차당 몇 건인지, 옵션이 몇 개인지 듣습니다.
2. **상품 CSV 를 함께 만듭니다.** 이게 첫 회차 작업의 대부분입니다.
   상품코드를 정하는 것이 중요합니다. 고객이 폼에서 쓰는 옵션 이름과 **똑같이** 맞춰야
   재고가 자동으로 빠집니다.
3. **장부를 만듭니다.** `python cli.py new ...`
4. **지난 회차 주문 CSV 로 시험합니다.** 이미 정산이 끝난 회차로 돌려 보면
   **숫자가 맞는지 고객이 직접 확인할 수 있습니다.** 신뢰를 얻는 가장 빠른 방법입니다.
5. **`verify` 를 돌립니다.** 납품 전 마지막 점검.
6. **납품** — 엑셀 + `docs/client.md` + 리포트 예시.
7. **인수인계** — 화면 공유로 30분. 반드시 짚을 것:
   - 회색 머리글 칸은 지우지 마세요
   - 배송상태는 직접 쳐 넣지 말고 드롭다운에서 고르세요
   - 마지막에 순이익을 통장과 맞춰 보세요

### 월 유지보수로 팔 것

- 회차마다 주문 CSV 넣어 주기
- 폼·쇼핑몰이 바뀌면 매핑 고치기
- 회차별 정산 리포트
- 상품이 늘면 상품 시트 갱신

**무엇을 해 드리는지 적어 두세요.** "문제 생기면 봐 드립니다" 로 팔면 범위 분쟁이 납니다.

## 10장. 문제 해결

| 증상 | 원인 | 조치 |
|---|---|---|
| 정산이 전부 0원 | 주문 시트가 비어 있음 | `import-orders` 를 돌렸는지 확인 |
| 공급원가만 0원 | 주문의 상품코드가 상품 시트에 없음 | `--verbose` 로 경고를 확인하고 상품 시트에 추가 |
| 재고가 안 줄어듦 | 상품코드+옵션이 한 글자라도 다름 | 조회키(`J` 열)를 눈으로 비교 |
| 배송 시트가 비어 있음 | 대기 상태 주문이 없거나 `N` 열을 지움 | 도우미 열을 되살리려면 다시 만드세요 |
| 재고 경고에 빈 줄이 뜸 | `IF($A2="","",…)` 가 빠진 수식을 손으로 넣음 | 프로그램이 만든 파일이면 나지 않습니다 |
| `#NAME?` | 구형 엑셀에 없는 함수 | `lint` 가 막습니다. 손으로 넣은 수식이면 그걸 고치세요 |
| 연락처 앞의 0 이 사라짐 | 셀 서식이 숫자 | 프로그램은 문자 서식으로 넣습니다. CSV 를 엑셀로 직접 연 경우 발생 |
| 수수료가 1원 다름 | 반올림 방식 차이 | 5-5 를 보세요. `excel_round` 가 맞춥니다 |
| `verify` 가 재계산 못 함 | 엔진 없음 | `pip install formulas` |
| 차트가 사라짐 | 다른 프로그램으로 열어 저장 | 원본을 보관하세요. 다시 만들면 복구됩니다 |
| 되읽기 실패 | 시트 이름을 바꿈 | 시트 이름 6개는 그대로 두어야 합니다 |

## 11장. 규정 관련

- **AI 생성물 표시** — 리포트에 기본으로 들어갑니다(인공지능기본법 제31조).
  엑셀 파일 자체에는 넣지 않습니다. 수치는 AI 가 만든 것이 아니라 고객 주문에서 계산된 것이라,
  표시를 붙이면 오히려 오해를 삽니다. **AI 가 쓴 것은 리포트의 세 줄 코멘트뿐**이고
  그 문서에 표시가 붙습니다.
- **고객 개인정보** — 주문 시트에 이름·연락처·주소가 들어갑니다.
  파일을 주고받을 때 조심하고, 작업이 끝나면 본인 컴퓨터에서 지우세요.
  이 프로그램은 어디로도 데이터를 보내지 않습니다. 리포트 코멘트를 만들 때 Claude 에게
  보내는 것은 **집계된 숫자뿐이고, 고객 이름·연락처는 보내지 않습니다.**
- **정산 확정은 사람이** — 프로그램은 계산할 뿐입니다. 통장과 맞춰 보는 단계를
  매뉴얼과 리포트 양쪽에 넣어 두었습니다. 이 순서를 건너뛰게 만들지 마세요.
- **판매 문구** — 성과를 단정하는 표현을 쓰지 않습니다. 장부는 일어난 일을 적는 도구이지
  결과를 만들어 내는 도구가 아니라고 설명하는 편이, 나중의 분쟁을 줄입니다.
