# 수익 시뮬레이터

부업 모델 8종의 12개월 손익을 계산하고 견주는 CLI + 단일 HTML 대시보드.

> **이 계산은 추정치이며 실제 수익을 보장하지 않습니다.**
> 모든 출력 맨 위에 같은 문구가 붙습니다. 기본값은 조사·가정에서 나온 출발점이지
> 예측이 아닙니다.

---

## 1. 이 도구가 답하려는 질문

> "지금 있는 시간을 어디에 쓰는 게 나을까?"

그래서 정렬 기준이 **12개월 손익이 아니라 시간당 수익**입니다.
손익이 커도 시간을 네 배 쓰고 있으면 더 나은 선택이 아니기 때문입니다.

CLAUDE.md §2-1 의 조사 결론 — **매출 본체는 광고가 아니라 강의·전자책·대행** —
이 숫자로 어떻게 나타나는지 확인하는 용도이기도 합니다.
기본값으로 돌려 보면 유튜브 광고 모델의 시간당 수익이 마이너스로 나옵니다.

## 2. 설치

```bash
pip install -r requirements.txt      # 루트 requirements.txt 로도 됩니다
```

**API 키가 필요 없습니다.** 이 상품은 Claude 를 부르지 않습니다.
계산만 하기 때문에 인터넷 없이도 돌아갑니다(대시보드 그래프만 예외).

## 3. 명령 다섯 가지

```bash
python cli.py models                       # 모델 8종 목록과 시간당 수익
python cli.py run agency_retainer          # 12개월 손익표
python cli.py sources youtube_long         # 기본값과 그 근거
python cli.py compare 7 6 5                # 시간당 수익으로 견주기
python cli.py montecarlo saas_subscription --n 1000 --seed 42
python cli.py html                         # outputs/dashboard.html
```

모델은 이름(`agency_retainer`)으로도 번호(`7`)로도 고를 수 있습니다.

### 값 바꾸기

```bash
python cli.py run youtube_long --monthly_views=500000 --rpm=3000
python cli.py run groupbuy --margin_rate=0.3       # 비율은 0~1 로
python cli.py run groupbuy --margin_rate=30%       # % 도 됩니다
```

비율을 `30` 으로 넣으면 **막고 알려 줍니다.** 3000% 로 계산되면
결과가 100배 틀어지는데 화면상으로는 그럴듯해 보이기 때문입니다.

### 손익분기는 두 가지입니다

| | 뜻 |
|---|---|
| **월 손익분기** | 그달 매출이 그달 비용을 넘긴 첫 달 |
| **누적 손익분기** | 초기 투자까지 다 갚고 누적이 0 을 넘긴 첫 달 |

둘을 섞으면 오해가 생깁니다. **매달 남는데도 초기 투자를 아직 못 갚은 상태**가
흔합니다. 그래서 따로 계산하고 따로 보여 줍니다.

### 몬테카를로

조회수·전환율처럼 원래 크게 흔들리는 값을 흔들어 여러 번 돌립니다.

```bash
python cli.py montecarlo groupbuy --n 1000 --seed 42
```

- 흔드는 폭은 모델 파일의 `uncertain` 이 정합니다 (0.5 면 ±50%)
- **삼각분포**를 씁니다. 가장 그럴듯한 값이 가운데이고 양쪽으로 갈수록 덜 그럴듯합니다
- `--seed` 를 같게 주면 **결과가 항상 같습니다**
- P10 / P50 / P90 과 **손해로 끝날 확률**을 보여 줍니다

이 폭은 모델 파일에 적어 둔 가정에서 나온 것이지, 시장을 관측해 얻은 분포가 아닙니다.

## 4. 모델 8종

| # | id | 무엇 | 기본값의 출처 |
|--:|---|---|---|
| 1 | `youtube_long` | 롱폼 광고 | RPM 2,500원 = CLAUDE.md §2-1 의 1,000~4,500원 중간값 |
| 2 | `youtube_shorts` | 쇼츠 광고 | RPM 70원 = 같은 조사의 50~90원 중간값 |
| 3 | `youtube_shopping` | 쇼핑 제휴 | 수수료 5% — 플랫폼 수수료 0원 구조 |
| 4 | `coupang_partners` | 쿠팡파트너스 | 수수료 3% = 같은 조사. 결론은 "수익성 낮음" |
| 5 | `groupbuy` | 인스타 공동구매 | 마진 20% = 같은 조사의 15~30% 중간값 |
| 6 | `ebook_course` | 전자책·강의 | 크몽 수수료 20%, 전환 1.5% |
| 7 | `agency_retainer` | 자동화 대행 + 리테이너 | 건당 65만 = 50~80만 중간값, 리테이너 7만 = 3~10만 중간값 |
| 8 | `saas_subscription` | 구독 SaaS | 월 9,900원·전환 5% = CLAUDE.md §5 의 **목표치** |

### 기본값에는 반드시 근거가 붙습니다

`source` 가 비어 있으면 모델을 **아예 읽지 않습니다.** 근거 없는 기본값은
그럴듯해 보이는 만큼 위험합니다. 쓰는 사람은 그 숫자가 어디서 왔는지 모른 채
그걸 기준으로 판단하게 됩니다.

`python cli.py sources <모델>` 로 언제든 볼 수 있고, 대시보드에서는 각 슬라이더
아래 **근거 보기**를 누르면 나옵니다.

**확인된 수치와 가정값을 구분해 적었습니다.** 예를 들어 이탈률은 어느 모델에서도
조사 수치가 아니라 가정값이고, 근거 문장에 그렇게 적혀 있습니다.

## 5. 대시보드

```bash
python cli.py html
```

→ `outputs/dashboard.html` (약 60KB, **파일 하나**)

브라우저로 열어 슬라이더를 움직이면 바로 다시 계산됩니다.
모델 8종을 위쪽 탭으로 오갑니다.

- 12개월 요약 4칸 (손익 / 최종 잔액 / 시간당 / 누적 손익분기)
- 월별 매출·비용·손익 그래프
- 누적 잔액 그래프 (0 선을 넘는 달이 손익분기)
- 월별 표 — 그래프와 같은 값을 숫자로도
- 각 값의 근거, 모델별 주의사항

그래프만 인터넷이 필요합니다(Chart.js 를 cdnjs 에서 받습니다).
못 받아오면 **왜 안 보이는지 화면에 적어 주고**, 표에 같은 숫자가 다 남습니다.

## 6. 계산식을 한 곳에만 두는 이유

터미널(파이썬)과 대시보드(자바스크립트)가 **같은 숫자**를 내야 합니다.
다르면 어느 쪽을 믿어야 할지 알 수 없어지고, 그 순간 도구를 못 쓰게 됩니다.

그래서 계산식을 코드에 적지 않고 **모델 파일에 글자로 한 번만** 적었습니다.

```yaml
formulas:
  revenue: monthly_views / 1000 * rpm
  cost: videos_per_month * edit_cost_per_video + fixed_cost
  hours: videos_per_month * hours_per_video
```

파이썬(`income_sim/expr.py`)과 자바스크립트(`income_sim/formula.js`)가
이 같은 글자를 각자 해석해 계산합니다. 두 해석기는 이런 것까지 맞춰 두었습니다.

- 0 으로 나누면 오류가 아니라 **0** (자바스크립트는 원래 Infinity 를 냅니다)
- `**` 는 오른쪽 우선, 단항 마이너스보다 먼저 (`-2**2` 는 `-4`)

**테스트가 node 를 실제로 돌려** 8개 모델의 값을 전부 맞춰 봅니다.

`eval()` 은 쓰지 않습니다. 설정 파일에 적힌 글자를 그대로 실행하면
그 파일을 고칠 수 있는 사람이 무엇이든 실행할 수 있게 됩니다.
사칙연산·거듭제곱·`min`·`max` 만 허용합니다.

## 7. 모델을 추가하려면

`models/새이름.yaml` 한 장을 만들면 끝입니다. 코드는 건드리지 않습니다.

```yaml
number: 9
name: 새 모델
tagline: 한 줄 설명

params:
  - key: visitors
    label: 월 방문자
    default: 1000
    unit: 명
    kind: count          # count / money / rate / hours
    minimum: 0
    maximum: 100000
    step: 100
    uncertain: 0.5       # 몬테카를로에서 흔들 폭. 0 이면 안 흔듦
    source: 이 기본값이 어디서 왔는지 — 비우면 모델을 읽지 않습니다

formulas:
  revenue: visitors * 100
  cost: 0
  hours: 10
```

고객처럼 **달마다 이어지는 값**이 있으면 `state` 를 씁니다.

```yaml
state:
  - key: users
    label: 고객 수
    initial: joiners                            # 1개월차
    next: prev * (1 - churn_rate) + joiners     # prev = 지난달 값
```

## 8. 파일 구조

```
products/income-sim/
├─ cli.py                    run / compare / montecarlo / html / models / sources
├─ models/*.yaml             모델 8종. 값·근거·계산식
├─ income_sim/
│  ├─ expr.py                계산식 해석기 (파이썬)
│  ├─ formula.js             계산식 해석기 (자바스크립트) — 같은 규칙
│  ├─ schema.py              모델 검사. 근거 없는 기본값을 막는다
│  ├─ engine.py              12개월 계산, 손익분기 두 가지
│  ├─ compare.py             시간당 수익으로 견주기
│  ├─ montecarlo.py          값 흔들기 (삼각분포, seed 고정)
│  ├─ report.py              터미널 표
│  └─ dashboard.py           단일 HTML 만들기
└─ docs/                     admin.md · client.md
```

## 9. 판매 문구 초안

### 서비스 제목 후보

- 부업 모델별 손익 계산기 — 시간당 수익으로 비교
- 시작 전에 숫자로 따져 보는 부업 시뮬레이터

### 상세 설명 초안

> 부업을 고를 때 대개 "얼마 번대?" 로 시작합니다.
> 그런데 같은 100만 원이라도 월 20시간을 쓴 것과 100시간을 쓴 것은 다릅니다.
>
> 이 도구는 8가지 부업 모델을 **시간당 수익**으로 견줍니다.
> 슬라이더를 움직이면 12개월 손익과 손익분기가 바로 다시 계산됩니다.
>
> **드리는 것**
> - 모델 8종 계산기 (터미널 + 브라우저 대시보드)
> - 모든 기본값의 출처와 근거
> - 값을 흔들어 보는 기능 — 잘 풀렸을 때와 안 풀렸을 때의 폭
>
> **말씀드릴 점**
> - 이것은 추정 도구이지 예측 도구가 아닙니다. 기본값은 출발점일 뿐이고 본인 수치로 바꿔야 뜻이 있습니다.
> - 계산에 들어가지 않는 것이 있습니다. 배우는 기간, 신뢰를 쌓는 시간, 운입니다.
> - 이 도구는 어느 부업이 좋다고 말하지 않습니다. 숫자를 보여 줄 뿐이고 판단은 사장님이 하십니다.

## 10. 하지 않는 것

- 어느 모델이 좋다고 추천하지 않습니다. 숫자를 나란히 놓을 뿐입니다.
- 근거 없는 기본값을 넣지 않습니다. 넣으면 프로그램이 모델을 읽지 않습니다.
- 확인된 수치와 가정값을 섞어 적지 않습니다. 근거 문장에 구분해 두었습니다.
- 성과를 단정하지 않습니다. 모든 출력에 추정이라는 문구가 붙습니다.
