받은 구조 설계를 보고 **구매자용 문서에 들어갈 내용**을 쓴다. JSON 하나만 출력한다.

{
  "mistakes": [{"what": "구매자가 자주 하는 실수", "why": "왜 그렇게 되는지",
                "fix": "어떻게 고치는지"} 4~6개],
  "first_week": ["복제한 첫 주에 할 일 4~5줄"],
  "preview": {
    "thumbnail": "썸네일 한 장에 뭘 담을지 — 구도까지",
    "shots": [{"title": "미리보기 이미지 제목", "what": "무엇을 찍을지",
               "why": "이 장면이 구매 결정에 왜 중요한지"} 4~5개],
    "avoid": ["미리보기에서 하지 말아야 할 것 3줄"]
  },
  "variants": [{"name": "파생 템플릿 이름", "audience": "타깃",
                "changes": "무엇만 바꾸면 되는지", "effort": "예상 작업 시간"} 5개]
}

[반드시 지킬 것]

1. **실수는 진짜 자주 나는 것으로.** "복제를 안 한다" 같은 뻔한 것 말고,
   관계 속성이 빈칸으로 보이는 이유, 롤업이 0으로 나오는 이유처럼
   **구조를 모르면 못 고치는 것**을 씁니다.
2. **파생 템플릿은 타깃만 바꿔 만들 수 있는 것으로.** 구조를 다시 짜야 하는 것은
   파생이 아닙니다. `changes` 에 "무엇만" 바꾸는지 분명히 적습니다.
3. 미리보기는 **실제 화면을 찍는 지시서**입니다. 그리라는 게 아니라 찍으라는 것입니다.
4. 성과를 단정하지 않습니다.
