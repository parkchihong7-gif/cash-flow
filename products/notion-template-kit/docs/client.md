# 고객용 매뉴얼 — 노션 템플릿 기획·설명서 생성기

노션 템플릿을 만들어 팔고 싶으신 분을 위한 도구입니다.
주제와 타깃만 정하시면 **구조 설계부터 판매 문구, 구매자용 설명서까지** 나옵니다.

---

## 1장. 이 도구가 하는 일

노션 템플릿을 팔려면 만드는 일보다 **정하고 쓰는 일**이 오래 걸립니다.

```
어떤 구조로 만들지 정하기   ← 여기가 제일 오래 걸립니다
노션에서 화면 만들기
판매 문구 쓰기
구매자용 설명서 쓰기
미리보기 이미지 찍기
```

이 도구는 **1·3·4번을 대신하고 2·5번을 안내**합니다.

### 왜 구조를 정하는 일이 제일 중요한가

표 여러 개를 만든 것과 템플릿의 차이는 **연결**에 있습니다.

프로젝트 하나를 열었을 때 거기 딸린 작업과 아직 못 받은 돈이 같이 보이는 것.
그게 사람들이 1~3만 원을 내는 이유입니다. 표만 여러 개면 무료로도 구할 수 있습니다.

그래서 이 도구는 **관계를 2개 이상, 롤업을 1개 이상** 반드시 넣습니다.

---

## 2장. 관리 화면 쓰는 법

브라우저에서 관리 화면을 열고 왼쪽에서 **9번 노션 템플릿 기획·설명서 생성기**를 고릅니다.

| 탭 | 여기서 하는 일 |
|---|---|
| **열람** | 이용 순서·FAQ·이 매뉴얼 |
| **수정** | 설계 규칙·판매 문구 규칙을 고칩니다 |
| **테스트** | 모의 실행 / 실제 실행 |
| **회원관리** | 템플릿을 사 간 고객 |
| **설정** | AI 모델, 노션 토큰 |

### 순서

1. **테스트** 탭에서 **모의 실행**을 먼저 누르세요. 비용이 들지 않습니다.
   예시 템플릿(프리랜서 프로젝트 관리)으로 산출물 6종이 어떤 모양인지 봅니다.
2. 형태가 마음에 들면 터미널에서 실제 주제로 돌립니다.
3. 나온 `spec.yaml` 을 **반드시 읽어 보세요.** 그대로 쓰지 마시고 고치세요.

---

## 3장. 터미널로 쓰기

```
python cli.py plan "프리랜서 프로젝트 관리" --audience "1인 디자이너"
```

1~2분 걸리고 비용은 한 번에 수백 원 수준입니다.

### 타깃을 좁게 쓰세요 — 가장 중요합니다

| 이렇게 쓰면 | 결과 |
|---|---|
| `"1인 사업자"` | 뻔한 구조가 나옵니다. 아무에게도 안 팔립니다 |
| `"1인 디자이너"` | 쓸 만합니다 |
| `"브랜딩만 하는 1인 디자이너"` | 속성 이름까지 그 사람 말로 나옵니다 |

팔리는 이유는 사는 사람이 **"내 얘기네"** 라고 느끼기 때문입니다.
넓게 잡을수록 그 느낌이 옅어집니다.

### 그 밖의 명령

```
python cli.py plan "..." --dry-run      # 비용 없이 형태만
python cli.py check outputs/<폴더>/spec.yaml   # 설계만 다시 검사
python cli.py deploy outputs/<폴더>/spec.yaml  # 노션에 실제로 만들기
```

## 4장. 나오는 파일 6개

| 파일 | 무엇 | 누가 봅니까 |
|---|---|---|
| `spec.yaml` | 구조 설계 전부 | **내가 먼저 읽습니다** |
| `build_guide.md` | 노션에서 만드는 순서 | 내가 보며 만듭니다 |
| `sales_page.md` | 제목·소개·가격 3안 | 내가 올릴 때 |
| `user_manual.md` | 사용 설명서 | **구매자에게 줍니다** |
| `preview_brief.md` | 무엇을 찍을지 | 내가 캡처할 때 |
| `variants.md` | 파생 템플릿 5개 | 다음 것을 만들 때 |

### 읽는 순서

**`spec.yaml` 부터 읽으세요.** 구조가 말이 되는지 보는 것이 먼저입니다.
여기가 잘못되어 있으면 나머지 다섯 개도 다 잘못된 것입니다.

특히 이 세 가지를 보세요.

1. 데이터베이스 이름이 **그 업계에서 실제로 쓰는 말**인가
2. 첫 화면에서 **"오늘 할 일" 이 보이는가**
3. **안 쓸 것 같은 속성**이 있는가 — 있으면 지우세요

안 채우는 칸은 없느니만 못합니다. 빈 화면을 본 구매자는 "별로네" 라고 생각합니다.

## 5장. 노션에서 만들기

`build_guide.md` 를 열고 순서대로 따라가면 됩니다.
맨 위에 **예상 소요 시간**이 적혀 있습니다.

### 순서를 지키세요

```
1. 페이지 만들기
2. 데이터베이스 만들기      ← 전부 다 만들고 나서
3. 관계와 롤업 잇기         ← 그다음에 잇습니다
4. 뷰 만들기
5. 예시 데이터 넣기
6. 버튼 만들기
7. 복제 링크 만들기
```

**2번을 다 끝내고 3번으로 가세요.** 관계는 이을 상대가 이미 있어야 고를 수 있습니다.
먼저 이으려 하면 목록에 아무것도 안 뜹니다.

**롤업은 관계를 먼저 이어야** 고를 수 있습니다. 관계가 비어 있으면 롤업 설정 창에
아무것도 안 나옵니다. 고장이 아니라 순서 문제입니다.

### 마지막 점검 — 꼭 하세요

`build_guide.md` 맨 끝에 점검 목록이 있습니다. 이것만은 꼭 하세요.

> **로그아웃 상태의 다른 브라우저에서 복제 링크를 열어 보세요.**

가장 흔한 사고가 **공유를 안 켜고 링크를 파는 것**입니다.
구매자가 열면 "권한이 없습니다" 가 뜨고, 환불과 별점 1개가 같이 옵니다.

## 6장. 자동으로 만들기 (선택)

노션 토큰이 있으면 일부를 자동으로 만들 수 있습니다.

```
python cli.py deploy outputs/<폴더>/spec.yaml
```

**토큰이 없어도 됩니다.** 없으면 오류가 아니라 안내가 나오고 그대로 끝납니다.
손으로 만드셔도 결과는 같고, 처음 한 번은 손으로 해 보시는 편이 구조를 이해하는 데 낫습니다.

### 준비 — 두 단계 모두 해야 합니다

1. **notion.so/my-integrations** 에서 통합을 만들고 토큰을 받습니다 → `.env` 에 `NOTION_TOKEN`
2. **만들 자리가 될 페이지를 하나 만들고,** 그 페이지 오른쪽 위
   **··· → 연결 → 방금 만든 통합**을 고릅니다 → 페이지 주소를 `.env` 에 `NOTION_PARENT_PAGE_ID`

⚠️ **2번을 빠뜨리는 분이 가장 많습니다.** 토큰만 만들고 페이지에 연결하지 않으면
"권한이 없습니다"(`restricted_resource`) 가 나옵니다. 토큰 문제가 아닙니다.

### 자동으로 되는 것과 안 되는 것

| | 자동 |
|---|---|
| 페이지, 데이터베이스, 속성 | ✅ |
| 관계·롤업 | ✅ |
| 예시 데이터 | ✅ |
| **뷰 (표·보드·달력)** | ❌ **손으로** |
| **템플릿 버튼** | ❌ 손으로 |
| **'상태' 속성** | ❌ 선택으로 만들어지니 타입을 바꾸세요 |

**뷰를 못 만드는 것이 가장 큽니다.** 템플릿의 쓸모는 대부분 뷰에서 나오거든요.
"오늘 할 일" 뷰 같은 것이요. 그래서 `deploy` 를 돌려도 **일이 절반쯤 남습니다.**

무엇이 남았는지는 `deploy_log.md` 의 '손으로 해야 하는 것' 에 적힙니다.

### 중간에 멈췄다면

노션에 절반쯤 만들어진 것이 남습니다.
`deploy_log.md` 를 열면 어디까지 만들었는지 표로 나옵니다.

**다시 돌리기 전에 만들어진 페이지를 지우세요.** 노션은 같은 이름으로 또 만드는 것을
막지 않아서, 안 지우면 두 벌이 생깁니다.

## 7장. 판매 문구 쓰기

`sales_page.md` 를 그대로 올리지 마시고 **읽어 보고 고치세요.**

### 꼭 확인할 것

- **제목은 타깃이 들어간 안을 고르세요.** "프로젝트 관리 템플릿" 보다
  "1인 디자이너용" 이 붙은 쪽이 눈에 띕니다.
- **가격 3안을 그대로 쓰지 마세요.** 시장을 보고 정하시되, 3단 구조는 유지하세요.
  가운데가 가장 많이 팔립니다.
- **"이런 분께는 맞지 않습니다" 를 지우지 마세요.** 안 맞는 분을 미리 걸러 내면
  환불과 낮은 별점이 줄어듭니다.

### 맨 아래 '등록 전 점검' 을 보세요

프로그램이 **성과를 단정하는 표현**을 검사한 결과가 적혀 있습니다.
✅ 이면 통과, ⚠️ 이면 그 표현을 고치고 올리세요.

고액 부업·템플릿 판매는 소비자원 주의보가 나온 분야입니다.
"이걸 쓰면 얼마 법니다" 같은 문구는 분쟁이 났을 때 그대로 근거가 됩니다.

## 8장. 미리보기 이미지

`preview_brief.md` 는 **그리라는 것이 아니라 찍으라는 지시서**입니다.
실제로 만든 노션 화면을 캡처해서 쓰세요.

### 찍기 전에

- 예시 데이터를 **보기 좋게 채워** 두세요. 빈 화면은 팔리지 않습니다.
- **실제 고객 이름이나 실제 금액이 없는지** 꼭 보세요. 그대로 찍힙니다.
- 사이드바를 접으세요. 내 다른 페이지 이름이 찍힙니다.
- 다크 모드와 라이트 모드 중 **하나로 통일**하세요.
- **노션 로고를 넣지 마세요.** 상표 문제가 됩니다.

실제와 다른 이미지는 환불 사유이고, 플랫폼에 따라 제재 대상입니다.

---

## 9장. 이 결과는 초안입니다

나온 파일 여섯 개는 전부 **초안**입니다. 완성품이 아닙니다.

```
프로그램이 초안을 만든다 → 사람이 읽고 고친다 → 그때 팔 수 있는 것이 된다
```

특히 이 세 가지는 **반드시 사람이 손봐야** 합니다.

1. **구조** — 그 업계 말로 되어 있는지, 안 쓸 속성이 없는지
2. **가격** — 시장을 보고 정하는 것이지 계산으로 나오는 것이 아닙니다
3. **미리보기** — 실제로 만든 화면을 찍어야 합니다

그리고 이 도구는 **템플릿이 팔리는 것을 약속하지 않습니다.**
팔리는 이유의 큰 몫은 만든 사람이 그 분야를 안다는 신뢰에 있고,
그건 프로그램이 만들 수 있는 것이 아닙니다.

## 10장. 자주 묻는 질문

**Q. 노션을 잘 몰라도 되나요?**
데이터베이스를 만들어 본 적은 있으셔야 합니다. `build_guide.md` 가 순서를 알려 주지만,
"속성 추가" 나 "뷰" 가 무엇인지는 아셔야 따라올 수 있습니다.

**Q. 나온 구조를 그대로 팔아도 되나요?**
권하지 않습니다. 그 업계에서 실제로 쓰는 말로 고치는 것이 가장 큰 차이를 만듭니다.
AI 가 쓴 티가 나는 템플릿은 별점이 낮습니다.

**Q. 파생 템플릿을 몇 개까지 만들까요?**
3~4개가 적당합니다. 그 이상은 관리가 안 됩니다.
템플릿마다 문의가 들어오고, 노션이 바뀌면 전부 손봐야 합니다.

**Q. 남의 템플릿을 참고해도 되나요?**
구조를 보는 것은 괜찮지만 그대로 베끼면 안 됩니다.
이 도구는 남의 템플릿을 입력으로 받지 않습니다.

**Q. 비용이 얼마나 드나요?**
Claude 호출 3회로 한 번에 수백 원 수준입니다. 노션 API 는 무료입니다.

**Q. deploy 를 돌렸는데 화면이 허전합니다.**
정상입니다. **뷰를 API 로 못 만들기 때문**입니다.
`build_guide.md` 4단계를 보고 뷰를 만들면 달라집니다.
`deploy_log.md` 의 '손으로 해야 하는 것' 목록을 다 처리해야 팔 수 있는 상태가 됩니다.
