# 노션 템플릿 기획·설명서 생성기

템플릿 아이디어 하나로 **구조 설계 + 판매 문구 + 사용 설명서**를 한 번에 만듭니다.
노션 API 토큰이 있으면 **실제 페이지까지** 만들어 줍니다.

```
"프리랜서 프로젝트 관리" + "1인 디자이너"
        ↓
spec.yaml · build_guide.md · sales_page.md
user_manual.md · preview_brief.md · variants.md
```

---

## 1. 이 도구가 없을 때 막히는 곳

노션 템플릿을 팔려면 만드는 일보다 **설계하고 설명하는 일**이 오래 걸립니다.

| 단계 | 혼자 할 때 | 이 도구 |
|---|---|---|
| 어떤 구조로 만들지 정하기 | 2~4시간 | **대신합니다** |
| 노션에서 만들기 | 1~3시간 | 가이드를 만들어 줍니다 (또는 `deploy`) |
| 판매 문구 쓰기 | 2~3시간 | **대신합니다** |
| 사용 설명서 쓰기 | 2~3시간 | **대신합니다** |
| 미리보기 이미지 찍기 | 1~2시간 | 무엇을 찍을지 정해 줍니다 |
| 문의 답하기 | — | 대신하지 못합니다 |

**구조를 정하는 일이 가장 큽니다.** 데이터베이스를 몇 개로 나눌지, 무엇과 무엇을
이을지가 템플릿의 값어치를 거의 다 정합니다. 표를 여러 개 만든 것과 템플릿의
차이가 거기서 납니다.

## 2. 설치

```bash
pip install -r requirements.txt     # 루트 requirements.txt 로도 됩니다
cp .env.example .env                # ANTHROPIC_API_KEY 를 넣으세요
```

노션 토큰은 **없어도 됩니다.** `deploy` 를 쓸 때만 필요합니다.
쓰실 거라면 `.env` 에 두 줄을 더 넣으세요.

```
NOTION_TOKEN=secret_...            # notion.so/my-integrations 에서 발급
NOTION_PARENT_PAGE_ID=...          # 만들 자리가 될 페이지. 통합을 연결해 두세요
```

⚠️ `NOTION_TOKEN` 만 넣고 부모 페이지에 통합을 연결하지 않으면
`restricted_resource` 가 납니다. 토큰 문제가 아니라 연결 문제입니다.

---

## 3. 사용법

```bash
# 설계와 문서 6종 만들기
python cli.py plan "프리랜서 프로젝트 관리" --audience "1인 디자이너"

# 비용 없이 형태만 보기
python cli.py plan "..." --dry-run

# 설계 파일만 다시 검사
python cli.py check outputs/<slug>/spec.yaml

# 노션에 실제로 만들기 (토큰이 있을 때)
python cli.py deploy outputs/<slug>/spec.yaml
```

**`--audience` 를 좁게 쓰는 것이 결과를 가장 크게 좌우합니다.**
"1인 사업자" 보다 "1인 디자이너", 그보다 "브랜딩만 하는 1인 디자이너" 가 낫습니다.
팔리는 이유는 사는 사람이 **"내 얘기네"** 라고 느끼기 때문입니다.

종료 코드: `0` 문제없음 / `2` 만들었지만 사람이 볼 곳이 있음 / `1` 오류.

## 4. 산출물 6종

| 파일 | 내용 | 누가 봅니까 |
|---|---|---|
| `spec.yaml` | 페이지 트리·데이터베이스·속성·뷰·예시 5행·버튼 | 나 / `deploy` |
| `build_guide.md` | 노션에서 손으로 만드는 순서, 소요 시간, 스크린샷 자리 | 나 |
| `sales_page.md` | 제목 5안·소개·포함 내용·사용법 3단계·가격 3안·**등록 전 점검** | 나 |
| `user_manual.md` | 복제 방법·각 DB 설명·**자주 하는 실수** | **구매자** |
| `preview_brief.md` | 썸네일과 미리보기 이미지를 무엇으로 찍을지 | 나 |
| `variants.md` | 타깃만 바꿔 만드는 파생 템플릿 5개 | 나 |

`build_guide.md` 는 Claude 가 쓰지 않습니다. **설계에서 기계적으로 만듭니다.**
사람이 쓴 설명서는 설계가 바뀌면 조용히 낡고, 그 낡은 설명서를 따라 만든 사람이
중간에서 막히기 때문입니다. 소요 시간도 항목 수를 세어 계산합니다.

## 5. 노션 API 로 만들 수 있는 것과 없는 것

**이 절이 이 상품에서 가장 중요합니다.** 모르고 설계하면 납품 직전에 막힙니다.

| | 공개 API |
|---|---|
| 페이지 | ✅ 만듭니다 |
| 데이터베이스와 속성 | ✅ 만듭니다 |
| 관계(relation)·롤업(rollup) | ✅ 만듭니다 (단계를 나눠야 합니다) |
| 예시 데이터 행 | ✅ 만듭니다 |
| **뷰 (표·보드·달력)** | ❌ **못 만듭니다** |
| **상태(status) 속성** | ❌ 못 만듭니다 → select 로 대신 만들고 알려 줍니다 |
| **템플릿 버튼** | ❌ 못 만듭니다 |
| 고유 ID·확인 속성 | ❌ 못 만듭니다 |

그래서 `deploy` 는 만들 수 있는 것만 만들고, **못 만든 것을 목록으로 남깁니다**
(`deploy_log.md`). 그 목록을 다 처리해야 팔 수 있는 상태가 됩니다.

> ⚠️ 이 목록은 공개 문서를 근거로 적었고, 이 저장소를 만든 컨테이너에서는
> api.notion.com 에 닿지 못해 **실제 호출로 확인하지 못했습니다.**
> 노션 API 는 조용히 바뀌는 편이니 처음 쓰실 때 한 번은 직접 확인하세요.
> 틀린 것이 있으면 `notion_kit/notion_types.py` 만 고치면 됩니다.

### 관계를 두 단계로 나누는 이유

관계 속성은 **이을 상대가 이미 있어야** 만들어집니다. 그런데 데이터베이스를
만들면서 동시에 관계를 넣으려면 아직 없는 id 가 필요합니다. 그래서 이렇게 합니다.

```
1단계  관계·롤업을 뺀 나머지 속성으로 데이터베이스를 전부 만든다
2단계  id 를 다 알게 됐으니 PATCH 로 관계를 붙인다
3단계  관계가 생겼으니 롤업을 붙인다   ← 롤업은 관계를 타고 간다
4단계  예시 데이터를 넣는다
```

이 순서가 어긋나면 노션이 거절합니다. 테스트가 **노션인 척하는 서버**를 띄워
요청 순서를 실제로 확인합니다.

### 중간에 실패하면

노션에 **절반쯤 만들어진 것**이 남습니다. 무엇이 남았는지 모르면 지우지도 이어
만들지도 못하므로, 한 단계마다 기록하고 `deploy_log.md` 로 남깁니다.

**다시 돌리기 전에 만들어진 페이지를 지우세요.** 노션은 같은 이름으로 또 만드는 것을
막지 않아서, 안 지우면 두 벌이 생깁니다.

## 6. 설계 검사

`spec.yaml` 은 pydantic 으로 검사합니다. 여기서 막는 것들입니다.

| 검사 | 왜 |
|---|---|
| 노션이 아는 속성 타입인가 | 모르는 타입은 API 가 거절합니다 |
| DB 마다 title 속성이 정확히 하나 | 노션 규칙입니다 |
| 관계가 실제 있는 DB 를 가리키는가 | 없는 곳을 가리키면 만들다 멈춥니다 |
| 롤업이 **같은 DB 의 관계**를 타는가 | 가장 자주 틀리는 곳입니다 |
| 롤업 대상 속성이 **저쪽 DB 에** 있는가 | 이것도 자주 틀립니다 |
| select·multi_select 에 선택지가 있는가 | 빈 선택지는 만들 수 없습니다 |
| 예시 행이 없는 속성을 쓰지 않는가 | 조용히 버려집니다 |
| 뷰가 없는 속성으로 묶지 않는가 | 보드 뷰가 안 만들어집니다 |

**이 검사들이 잡는 문제는 만들 때는 안 보이고 구매자가 열었을 때 보입니다.**
그래서 만들기 전에 잡습니다.

## 8. 판매 문구 초안

### 서비스 제목 후보

- 노션 템플릿 구조 설계 + 판매 문서 제작
- 팔 수 있는 노션 템플릿 기획해 드립니다
- 노션 템플릿 설계서·설명서 일괄 제작

### 상세 설명 초안

> 노션 템플릿을 만들어 팔고 싶은데, 막상 앉으면 **어떤 구조로 만들지**부터 막힙니다.
> 데이터베이스를 몇 개로 나눌지, 무엇과 무엇을 이을지가 템플릿의 값어치를 거의 다 정합니다.
>
> 주제와 타깃만 주시면 구조 설계서와 판매 문구, 구매자용 설명서까지 만들어 드립니다.
>
> **드리는 것**
> - 구조 설계서 — 페이지 트리, 데이터베이스와 속성, 뷰, 예시 데이터
> - 노션에서 만드는 단계별 가이드 (소요 시간 포함)
> - 판매 문구 — 제목 5안, 소개, 가격 3안
> - 구매자용 사용 설명서
> - 미리보기 이미지 촬영 지시서
> - 타깃만 바꿔 만들 수 있는 파생 템플릿 5개
>
> **말씀드릴 점**
> - 설계와 문서를 만들어 드리는 것이지, 템플릿이 팔리는 것을 약속하지 않습니다. 팔리는 이유의 큰 몫은 만든 사람의 신뢰에 있습니다.
> - 노션 화면 만들기는 가이드를 따라 직접 하셔야 합니다. 토큰을 주시면 일부는 자동으로 만들어 드립니다.
> - 뷰와 템플릿 버튼은 노션이 API 로 만들 수 없어 손으로 하셔야 합니다.
>
> 설계와 문구에는 생성형 AI 를 사용하며, 산출 문서에 그 사실을 표시합니다.

## 9. 하지 않는 것

- 남의 템플릿을 보고 베끼지 않습니다. 주제와 타깃에서 구조를 새로 짭니다.
- 팔린다고 약속하지 않습니다. 성과를 단정하는 문구는 검사에서 걸러냅니다.
- 실적 수치를 지어내지 않습니다.
- 타깃만 바꿔 **내용 없이 개수만 늘리는 방식**은 권하지 않습니다.
  `variants.md` 에 그 이유를 적어 두었습니다.
- 노션 계정 정보를 대신 받지 않습니다. 통합 토큰은 본인이 발급해 본인 `.env` 에 둡니다.
