# CELEB ORBIT(셀럽오르빗) — 전체 설계와 MVP 계획 (승인용 초안)

> 작성 2026-10-17 · 대상: 17번 «연예인 착용템 쇼츠 기획기» 를 셀럽오르빗 운영 도구로 키우는 안
> 이 문서는 **코드보다 먼저 정할 것**을 모았다. 승인 후 1단계 MVP 를 5조각으로 나눠 만든다.
> 외부 서비스 조건 중 공식 문서로 확인하지 못한 것은 **[확인 필요]** 로 표시했다.

## 0. 먼저 정할 것 (사장님 결정 4가지)

| # | 결정 | 추천 | 이유 |
|---|---|---|---|
| 1 | 어디에 만드나 | **17번을 키운다** (`products/celeb-shorts/`) | 얼굴 금지·출처·효능·추천 표현 검사가 이미 17번에 있다. 새 번호로 만들면 규칙이 두 벌이 된다. 셀럽오르빗 이름·색·슬로건은 «브랜드 설정»으로 빼서 판매용 17번과 같은 코드로 쓴다 |
| 2 | 슬로건 | «스타가 쓰는 그 아이템, 여기서!» → **«스타 스타일, 여기서 찾기»** 같은 표현 | 소개 상품 대부분은 «비슷한 상품»이다. 지금 슬로건은 매 영상 «스타가 쓰는 바로 그 제품» 이라고 말하는 셈이라 허위 표시 시비가 붙는다. 그대로 쓰려면 화면·설명란에 «비슷한 상품 포함» 고지를 늘 같이 넣는다 |

| 4 | 실행 형태 | **Windows PC 에서 도는 로컬 웹앱** (브라우저로 `http://127.0.0.1:8017`) | 서버 비용 0원, API 키가 PC 밖으로 나가지 않는다. 설치는 `설치.bat` 한 번 |

## 1. 전체 구조

```
[A 발굴] ──► [검증] ──► [B 매칭] ──► [C 대본 3안] ──► [사람 승인①]
                                                        │
          [권리 검사 게이트] ◄── [D 영상 렌더] ◄─────────┘
                 │ 통과
                 ▼
          [미리보기·다운로드] ──► [사람 승인②] ──► [E 업로드(비공개/예약)] ──► [F 성과]
```

- 사람 승인은 **두 번**: 대본(①)과 완성 영상(②). 승인 없이 공개되는 길은 코드에 없다.
- 권리 검사 게이트를 통과하지 못하면 렌더는 되지만 «업로드 불가» 표시가 붙고 업로드 버튼이 잠긴다.

| 층 | 무엇 | 비고 |
|---|---|---|
| 웹 화면 | FastAPI + Jinja 템플릿 + HTMX | 저장소의 대시보드와 같은 방식. 빌드 도구 없음 |
| 작업 실행 | 앱 안의 작업 큐(SQLite 테이블) + 재시도 3회 | 별도 서버(Redis 등) 없음 |
| 데이터 | SQLite 한 파일 (`data/orbit.db`) | 백업 = 파일 복사. 화면에 «백업/복원» 버튼 |
| 렌더 | Python(Pillow) 로 그래픽 레이어 → FFmpeg 로 합성 | 아래 3장 |
| 외부 | Claude API, Google TTS, (2단계) 네이버/YouTube 검색, 쿠팡 API, (3단계) YouTube 업로드 | 키는 `.env` + Windows 자격 증명 관리자(keyring) |

## 2. 기능별 구현 가능 여부와 제약

| 기능 | 가능도 | 제약 (사실대로) |
|---|---|---|
| 상품·출처 직접 입력, 사실 확인 | 100% | — |
| **A 자동 발굴** | 50~70% | «연예인 사용 상품» 을 주는 공식 API는 없다. 쓸 수 있는 것: 네이버 뉴스 검색 API(제목·요약·링크만), YouTube Data API(영상 제목·설명). **네이버 검색 API는 신규 이용 신청이 막혔다는 주장이 있다 [확인 필요]**. 인스타그램은 남의 게시물을 검색하는 API가 없다. 기사 본문 긁어오기(스크래핑)는 하지 않는다. 결과는 늘 «추정» 상태로 들어오고 사람이 출처를 열어 확인해야 «확인» 이 된다 |
| B 제휴 매칭 | 70% | 쿠팡파트너스 API는 승인된 파트너만 키를 받는다. 발급 조건(실적 요건 여부)은 **[확인 필요]**. 키가 없으면 검색 주소 + **사람이 링크를 직접 붙여 넣기**. 링크를 임의로 만들지 않는다 |
| C 대본 3안 | 95% | 17번 규칙(얼굴·출처·가격·효능·추천)을 그대로 통과해야 승인 가능 |
| D 영상 제작 | 85% | 레트로 질감은 코드로 만든다(망점·종이·색 어긋남·별). 이미지 생성 AI는 쓰지 않는다 — 매끈한 AI 느낌을 피하고 비용 0원 |
| D 상품 이미지 | 60% | **권리가 있는 이미지만**: 직접 촬영 / 브랜드·판매자 허락 기록 / 제휴 API가 홍보용으로 준 이미지 **[쿠팡 이미지 사용 조건 확인 필요]**. 없으면 글자·도형으로 만든 «자체 그래픽 카드» 로 자동 대체 |
| 배경음악 | 80% | 사람이 라이선스를 확인하고 등록한 파일만 쓴다(유튜브 오디오 보관함 등). 자동 다운로드 없음 |
| E 업로드 | 60% | YouTube Data API 업로드는 가능. 하지만 **감사(audit)를 통과하지 않은 API 프로젝트로 올린 영상은 비공개로 잠긴다** (공식 문서). 감사 전까지는 «비공개 업로드 → 스튜디오에서 사람이 공개/예약» 이 현실적. 업로드 할당량 수치는 자료마다 다르다 **[확인 필요]** |
| 유튜브 쇼핑 상품 태그 | 0% (자동) | 공개 API가 없다. 스튜디오에서 손으로 |
| F 성과 | 50% | YouTube Analytics API로 조회수·시청 지속 가능. 쿠팡 실적은 API 권한이 있을 때만. **없는 데이터는 «미연동» 으로 표시하고 추정 수익을 확정처럼 보여 주지 않는다** |
| 썸네일 | 70% | 만들 수는 있지만 쇼츠 피드는 대개 영상 프레임을 보여 준다. 첫 프레임을 썸네일처럼 설계한다 |

## 3. 추천 기술 스택

| 영역 | 선택 | 고른 이유 / 버린 것 |
|---|---|---|
| 언어 | Python 3.11 | 저장소 전체가 Python. 하나로 웹·렌더·자동화 |
| 웹 | FastAPI + Jinja + HTMX | 이미 대시보드에서 검증. React 빌드가 필요 없어 설치가 단순 |
| DB | SQLite (→ 필요 시 PostgreSQL) | 파일 하나, 백업 쉬움 |
| 그래픽 | **Pillow + NumPy** | 망점·종이 질감·색 어긋남을 직접 그린다. 결과가 매번 조금씩 달라 «사람 손 느낌» 을 낼 수 있다 |
| 영상 합성 | **FFmpeg (직접 호출)** | 가장 안정적. MoviePy 는 FFmpeg 위의 편의 층이라 디버깅이 어렵고 느리다. Remotion 은 Node·크롬이 필요하고 Windows 설치가 무겁다 |
| 자막 | 대본에서 바로 만든 SRT + FFmpeg 로 굽기 | 음성 인식이 필요 없다(대본이 원문) |
| 글꼴 | 오픈 라이선스 한글 글꼴(예: 검은고딕·도현 계열, OFL) | 상업 이용 가능한 것만, 라이선스 파일 동봉 |
| TTS | Google Cloud TTS (선택) | 공식 API, 무료 한도 있음(수치는 자료마다 다름 **[확인 필요]**). 비공식 엔드포인트(edge-tts 등)는 «공식 API만» 원칙 위반이라 제외 |
| LLM | Claude API (`shared/llm.py`) | 대본 3안·제목·설명 |
| 키 저장 | `.env` + keyring(Windows 자격 증명 관리자) | 화면에서 입력, 파일에 평문으로 남기지 않는 쪽을 기본으로 |

## 7. 자동화 워크플로

| 주기 | 하는 일 | 사람이 할 일 |
|---|---|---|
| 매일 (2단계~) | 검색어 목록으로 후보 수집 → «추정» 으로 저장 → 점수 순 정렬. 등록 상품 가격·판매 여부 재확인. 승인된 대본 렌더 | 후보 출처를 열어 검증, 대본 승인 |
| 매주 (4단계) | 조회·클릭·전환 정리, 잘 된 카테고리, 다음 주 후보 | 다음 주 상품 고르기 |
| 상한 | 하루 렌더 수·API 호출 수 상한을 설정에서. 쿼터를 넘으면 **재시도가 아니라 다음 날까지 대기** | — |

- 상품 점수 = 화제성·구매 가능성·가격 경쟁력·전환 가능성·자료 신뢰도·정보 정확성·제작 난이도. **가중치는 설정 화면에서 조정.** 자료 신뢰도는 claim.relation 으로 정한다(추천확인 > 사용확인 > 등장 > 추정).
- 양산형 판정을 피하려고 기본 상한은 **하루 업로드 2편**, 대본마다 «내 말 한 줄» 칸을 비우면 승인 불가.

## 8. 저작권·광고 고지 검증 (렌더 전·업로드 전 게이트)

| 검사 | 통과 조건 | 실패 시 |
|---|---|---|
| 이미지 권리 | 쓰는 이미지마다 asset.license 와 증빙이 있다 | 그 장면을 «자체 그래픽 카드» 로 바꿈 |
| 연예인 얼굴·방송 화면 | 화면 종류에 아예 없음(17번 규칙) | — |
| 음악 | 라이선스 기록이 있는 음원 | 음악 없이 렌더 |
| 목소리 | TTS 기본 음성만. 음성 복제 기능 없음 | — |
| 사실 관계 | 대본에 나온 연예인-상품 관계가 claim.relation 과 맞는다(«추정» 이면 이름 사용 불가) | 승인 불가 |
| 효능·가격·추천 표현 | 17번 규칙 | 승인 불가 |
| 광고 고지 | 영상 안 고지 프레임 + 설명란 첫 줄 + 업로드 시 유료 프로모션 체크 | 업로드 버튼 잠김 |
| AI 표시 | 영상 끝 «AI 음성·자동 편집 사용» 문구 + 업로드 시 합성 콘텐츠 표시 | 업로드 버튼 잠김 |

출처를 적는 것만으로 저작권 문제가 풀린다고 보지 않는다. 그래서 **권리 기록이 없는 자료는 아예 렌더에 들어가지 않게** 막는다.

## 9. 1단계 MVP — 5조각으로 나눠 만들기

각 조각은 «돌려 보고 확인 → 다음» 이다. 조각마다 시험 + 화면 캡처 1장으로 보고한다.

| 조각 | 만드는 것 | 확인 방법 |
|---|---|---|
| ① | 앱 뼈대: 로컬 웹앱, SQLite, 설정(브랜드 색·슬로건), 백업/복원, 작업 로그 | `설치.bat` → 브라우저에서 첫 화면 |
| ② | 상품·출처·검증(4단계 분류)·제휴 링크·이미지 라이선스 등록 화면 | 상품 1개 등록 → 검증 «사용확인» 으로 바꾸기 |
| ③ | 대본 3안 생성(17번 규칙 통과) + 고치기 + 승인① | 모의 실행으로 3안, 규칙 위반 문장 넣으면 승인 막힘 |
| ④ | 레트로 렌더러: 템플릿 5종, 자막, 고지 프레임, TTS(선택)/무음, 음악(선택) → mp4 | 20초 영상 1편, 1080×1920, 캡처로 질감 확인 |
| ⑤ | 권리 검사 게이트 + 미리보기·다운로드 + 업로드용 제목·설명·해시태그 생성 + 승인② | 라이선스 없는 이미지 → 자체 그래픽 대체 확인 |

**레트로 템플릿 5종 (요청서 그대로):** 80년대 화장품 광고형 / 빈티지 패션잡지형 / 레트로 팝아트형 / 방송 속 화제템 소개형 / 스타 쇼핑 리스트형. 모두 같은 레이어(종이 → 망점 → 색면 → 상품 → 글자 → 별·궤도)를 쓰고 배치·색 비율·글자 움직임만 다르게 한다. 템플릿은 YAML 파일이라 설정 화면에서 고칠 수 있다.

**채널 그래픽:** 배너 2048×1152(가운데 안전 영역 1235×338 안에 채널명), 프로필 98×98(올릴 때는 800×800 로 만들어 축소)도 같은 렌더러로 ①~④ 사이에 만든다.

## 10. Windows 설치·실행 (계획)

1. Python 3.11 설치(python.org, «PATH 추가» 체크)
2. FFmpeg: `설치.bat` 이 winget 으로 설치를 시도하고, 안 되면 받는 곳과 넣을 폴더를 안내
3. `설치.bat` 더블클릭 → 가상환경·패키지 설치
4. `실행.bat` 더블클릭 → 브라우저가 `http://127.0.0.1:8017` 로 열림
5. 설정 화면에서 Claude API 키 입력(없으면 모의 실행만)

## 11. 테스트 방법

- 자동 시험: `python -m tools.programs test 17` (규칙·DB·렌더 크기·권리 게이트)
- 렌더 시험: 모의 데이터로 20초 영상 1편 → 해상도·길이·자막 줄 수·고지 프레임 존재를 숫자로 검사(`ffprobe`)
- 화면 시험: `tools/ui_shot.py` 로 너비·넘침 검사 + 캡처 1장
