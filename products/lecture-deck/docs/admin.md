# 강의 슬라이드 생성기 — 관리자 매뉴얼

> 이 프로그램을 **운영하고 판매하는 사람**을 위한 문서입니다.
> 구매자에게 줄 문서는 `docs/client.md` 입니다.

---

## 1장. 이 프로그램이 파는 것

### 1-1. 한 문단 요약

강의 주제와 시간을 넣으면 커리큘럼을 짜고, 모듈마다 슬라이드를 만들고,
슬라이드마다 발표자 노트를 채우고, 수강생 실습지까지 만듭니다.

### 1-2. 진짜 가치는 "발표자 노트"입니다

"AI로 PPT 만들어 드립니다"는 흔합니다. 그런데 대부분 **슬라이드만** 만듭니다.

강사가 실제로 아쉬운 건 슬라이드가 아니라 **말할 내용**입니다.
강의 직전에 노트가 비어 있으면 슬라이드를 읽게 되고, 그러면 강의가 지루해집니다.

이 도구는 **노트가 빈 슬라이드를 만들지 않습니다.** LLM 이 짧게 쓰면 프로그램이
채우고 `[강사가 채울 곳]` 표시를 남깁니다. 이걸 상세페이지에 앞세우세요.

### 1-3. 두 번째 가치는 "안 넘친다"입니다

슬라이드가 넘치는 것은 이 분야에서 가장 흔한 사고입니다.
LLM 에게 "짧게 써 달라"고 부탁하면 대체로 지키지만 가끔 어깁니다.
그 한 장이 강의 중에 문제가 됩니다.

그래서 프롬프트로 부탁만 하지 않고 **생성 후 검사해서 강제로 쪼갭니다.**
6줄·20자를 넘으면 의미 단위로 나누고 슬라이드를 분할합니다.

---

## 2장. 준비

### 2-1. API 키

1. https://console.anthropic.com/settings/keys 에서 키 발급 (`sk-ant-` 로 시작)
2. Billing 에서 카드 등록 + 충전
3. 저장소 맨 위 폴더의 `.env` 에 `ANTHROPIC_API_KEY=sk-ant-...` 저장
4. 대시보드 **기타 설정**에서 "API 키: 설정됨" 확인

> `.env` 는 절대 공유하지 마세요.

### 2-2. 비용 감각

| 단계 | 호출 수 |
|---|---|
| 커리큘럼 | 1회 |
| 슬라이드 | 모듈 수만큼 (5~8회) |
| **합계** | **6~9회** (재작성 발생 시 더) |

한 벌에 천 원 안팎입니다. 전자책(3번)보다 싸고 대본(2번)보다 비쌉니다.

**비용을 아끼는 지점은 커리큘럼 확인 단계입니다.** 커리큘럼은 1회 호출이라
여러 번 돌려도 싸고, 슬라이드는 모듈 수만큼 호출합니다.
커리큘럼이 마음에 안 들면 `n` 을 눌러 멈추고 입력을 고치세요.

## 3장. 운용

### 3-1. 입력 채우기

대시보드 **수정** 탭에서 `deck_input.yaml` 을 엽니다.

| 항목 | 잘 쓰는 법 |
|---|---|
| `course_title` | 실제 강의명 그대로 |
| `audience` | **좁게.** "직장인"(X) → "혼자 일하며 파일을 직접 관리하는 프리랜서"(O) |
| `total_minutes` | 실제 강의 시간. 쉬는 시간을 뺀 순수 강의 시간으로 |
| `style` | 3-3 참고 |
| `modules` | 비우면 제안받고, 적으면 그대로 씁니다 |

### 3-2. 커리큘럼 확인 단계

실행하면 커리큘럼을 보여 주고 물어봅니다. 세 가지를 보세요.

1. **모듈 제목만 읽어서 순서가 이해되는가** — 나열이면 다시 만드세요
2. **시간 합계가 맞는가** — 어긋나면 화면에 ⚠ 가 뜹니다
3. **실습 과제가 그 시간에 끝나는 크기인가** — 대개 과하게 나옵니다

`n` 을 누르면 슬라이드를 만들지 않고 종료합니다. 입력을 고쳐 다시 실행하세요.

배치나 대시보드처럼 입력을 받을 수 없는 곳에서 실행하면 자동으로 진행합니다.

### 3-3. 스타일 고르기

| 스타일 | 언제 |
|---|---|
| `minimal` | 기본값. 온라인 강의, 소규모 워크숍 |
| `bold` | 대비가 강해 **큰 강의실·프로젝터 화질이 나쁜 곳** |
| `corporate` | 사내 교육, B2B 제안형 강의 |

색을 바꾸려면 **수정** 탭에서 `templates/palettes.json` 을 고치세요.
새 스타일을 추가하려면 같은 키 구조로 항목을 하나 더 만들고
`lecture_deck/schema.py` 의 `STYLES` 에 이름을 넣습니다.

### 3-4. 실행 결과 읽기

```
✓ 본문 규칙 (6줄·20자): 전부 통과
✓ 발표자 노트: 빈 슬라이드 없음

⚠ 본문이 6줄·20자를 넘어 3장이 자동으로 나뉘었습니다.
```

| 표시 | 뜻 | 할 일 |
|---|---|---|
| 전부 통과 | 규칙 위반 없음 | 없음 |
| `N장이 자동으로 나뉘었습니다` | LLM 이 규칙을 어겨 프로그램이 쪼갬 | 제목에 `(1/2)` 가 붙은 슬라이드를 확인 |
| `N장을 자동으로 채웠습니다` | 노트가 짧아 프로그램이 보충 | `[강사가 채울 곳]` 을 본인 내용으로 |
| 금지 문구 | 2번 고쳐도 남음 | 직접 고쳐야 합니다 |

자동 분할이 자주 뜨면 `prompts/slides.md` 의 분량 규칙에 예시를 더 넣으세요.

### 3-5. 산출물 검토 순서

1. **`curriculum.md`** — 시간 배분과 실습 과제부터 봅니다
2. **`deck.pptx` 발표자 노트** — 본인 말투로 고칩니다. 가장 시간이 걸리는 작업입니다
3. **`[강사가 채울 곳]` 표시** — 전부 처리합니다
4. **`worksheet.docx`** — 빈칸 힌트가 적절한지 봅니다
5. 인쇄해서 한 번 넘겨 보세요. 화면에서 안 보이던 게 보입니다

## 4장. 품질을 올리는 법

효과가 큰 순서대로입니다.

| 순서 | 무엇을 | 비용 | 효과 |
|---|---|---|---|
| 1 | `audience` 를 좁게 쓴다 | 없음 | 가장 큼 |
| 2 | 모듈을 직접 적어 넣는다 | 없음 | 큼 |
| 3 | `prompts/slides.md` 를 고친다 | 없음 | 큼 |
| 4 | 발표자 노트를 직접 손본다 | 없음 | 큼 (시간이 듦) |
| 5 | 모델을 올린다 | 증가 | 보통 |

### 4-1. 모듈을 직접 적기

가르칠 내용이 이미 머리에 있다면 제목만이라도 적어 넣으세요.
LLM 이 목표·개념·시간·실습을 채웁니다. 제안받는 것보다 훨씬 정확합니다.

```yaml
modules:
  - title: "왜 지금 정리가 필요한가"
  - title: "자리 정하기"
  - title: "이름 규칙 만들기"
  - title: "버리는 기준"
  - title: "유지하는 법"
```

### 4-2. 프롬프트 수정

| 파일 | 바뀌는 것 |
|---|---|
| `prompts/curriculum.md` | 모듈 흐름, 시간 배분 방식, 학습 목표 쓰는 법 |
| `prompts/slides.md` | 슬라이드 뼈대 잡는 법, 노트 문체, 분량 규칙 |

효과 있는 수정 예:
- 분야 명시: "실무 강의 강사" → "소상공인 대상 실무 강의 강사"
- 본인 말투 예시를 "이런 톤으로" 하고 붙여두기 (노트 품질이 크게 올라갑니다)
- 싫어하는 상투구를 금지 목록에 추가

바꾼 뒤에는 **모의 실행이 아니라 실제 실행**으로 확인하세요.

## 5장. 문제 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| `모듈은 5~8개여야 합니다` | 직접 쓴 모듈 수가 범위 밖 | 5~8개로 맞추거나 비우세요 |
| `핵심 개념은 3~5개여야 합니다` | 개념 수가 범위 밖 | 3~5개 또는 비우기 |
| `total_minutes` 오류 | 30~960 범위 밖 | 범위 안으로 |
| `모르는 스타일입니다` | style 오타 | `minimal` / `bold` / `corporate` |
| 자동 분할이 많이 뜸 | LLM 이 분량 규칙을 못 지킴 | `prompts/slides.md` 에 예시 추가 |
| 노트 보정이 많이 뜸 | LLM 이 노트를 짧게 씀 | 같은 파일의 노트 규칙에 예시 추가 |
| 모듈 시간 합계가 안 맞음 | LLM 배분 오차 | `curriculum.md` 에서 직접 조정 |
| 특정 모듈만 계속 실패 | 그 주제가 정책에 걸릴 수 있음 | 모듈 제목을 바꿔 보세요 |
| `쿼터 초과` | 모듈을 연달아 부르다 한도 초과 | **1분 대기 후** 다시 |

## 6장. 판매할 때

### 6-1. 상세페이지에 넣을 것

- "초안 생성기이며 강의 전 강사 검수가 필수"라는 문장
- **발표자 노트가 빈 슬라이드가 없다는 점** — 이게 가장 큰 차별점입니다
- 6줄·20자를 프로그램이 강제한다는 점
- API 키는 구매자가 직접 발급하고 사용료는 별도(한 벌 천 원 안팎)

### 6-2. 쓰면 안 되는 표현

성과를 단정하는 표현은 쓰지 마세요. 프로그램이 산출물은 자동 검사하지만
**상세페이지는 검사하지 않습니다.** 대시보드 **기타 설정**에서 금지 문구 목록을
확인하고 직접 대조하세요.

### 6-3. 묶음 구성

- **3번 전자책 원고 생성기 + 4번** — 같은 주제로 책과 강의를 같이 만드는 세트
- **1번 퍼널 빌더 + 4번** — 강의를 만들고 그 강의를 파는 페이지까지
- 강의 자료 제작 대행으로 팔 수도 있습니다. 커리큘럼 확인 단계에서
  고객과 함께 보면서 정하면 수정 요청이 줄어듭니다.

### 6-4. 회원관리 연동

1. **회원관리** → 고객 추가
2. 고객 상세 → **라이선스 발급** → 프로그램 `lecture-deck` 선택
3. 대행 작업 시 테스트 탭에서 고객을 지정해 실행하면 이력이 남습니다
