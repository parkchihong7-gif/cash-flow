# 체험 서버를 따로 세우기

> **사장님용.** 체험 키를 내주실 자리를 만드는 일입니다. 한 번만 하시면 됩니다.

---

## 왜 따로 세우나

한동안 체험 키가 **사장님이 실제로 쓰시는 그 서버**를 열었습니다.

칸막이(`owner_key`)가 있어서 서로의 글은 안 보입니다. 그래도 **같은 서버**입니다.

| 같은 서버를 쓰면 | |
|---|---|
| AI 한도 | 체험 세 분이 오늘 9편 만들면, 그만큼 **사장님 몫이 줄어듭니다** |
| 메모리 | 한 서버가 2Gi 를 나눠 씁니다. 몰리면 느려집니다 |
| 탈이 나면 | 체험 쪽에서 난 탈이 **사장님 아침 글을 멈춥니다** |
| 지울 때 | 사장님 데이터 옆에서 지우는 일입니다. 실수의 여지가 남습니다 |

**맛보기는 맛보기용 자리에서.** 그래야 사장님 일이 안 흔들립니다.

### 돈은 거의 안 듭니다

서버가 하나 더 늘어도 **아무도 안 쓸 때는 잠듭니다.** 잠든 서버는 0원입니다.
체험 회원이 들어올 때만 깨어납니다.

---

## 1. 저장통 하나 더

`YOUR_PROJECT_ID` 를 사장님 것으로 바꾸십시오.

```bash
gcloud storage buckets create gs://maim-demo-YOUR_PROJECT_ID --location=us-central1
```

## 2. 서버 세우기

**대문자 네 곳**을 바꾸십시오.

```bash
cd ~/maim

gcloud run deploy maim-demo \
  --source . \
  --region=us-central1 \
  --allow-unauthenticated \
  --memory=2Gi \
  --min-instances=0 --max-instances=1 --concurrency=1 \
  --timeout=1800 \
  --set-env-vars=HOST=0.0.0.0,DATA_DIR=/tmp/maim-state,HOME=/tmp/maim-state/home,GCS_STATE_BUCKET=maim-demo-YOUR_PROJECT_ID,TIMEZONE=Asia/Seoul,CLAUDE_BIN=claude,DASHBOARD_TOKEN=YOUR_DEMO_PASSWORD,KEYSERVER_URL=YOUR_KEYSERVER_URL,KEYSERVER_PROGRAM=naver-blog
```

| 바꿀 곳 | 무엇을 |
|---|---|
| `YOUR_PROJECT_ID` | 콘솔 위쪽에 보이는 프로젝트 ID |
| `YOUR_DEMO_PASSWORD` | **사장님 서버와 다른** 비밀번호로 하십시오 |
| `YOUR_KEYSERVER_URL` | **사장님 서버와 같은 것.** 장부가 하나여야 체험 키가 통합니다 |

> `KEYSERVER_PROGRAM=naver-blog` 를 **사장님 서버와 똑같이** 두십시오.
> 그래야 대시보드에서 발급한 체험 키가 여기서도 통합니다.

끝나면 주소가 뜹니다.

```
Service URL: https://maim-demo-xxxxx-uc.a.run.app
```

**이 주소를 적어 두십시오.** 4번에서 씁니다.

## 3. AI 연결 — 이 서버 몫으로 한 번 더

**고르신 AI 에 따라 다릅니다.** 설치 안내서 **3-4** 와 같은 갈림길입니다.

### Gemini 를 쓰신다면 — 할 일이 거의 없습니다

체험 주소로 들어가 **[관리자 설정] → 1단계**에서 **Gemini** 를 고르고,
**본 서버에 넣으신 것과 같은 키**를 붙여넣으시면 끝입니다. 이 문단의
나머지는 건너뛰셔도 됩니다.

> 키를 따로 하나 더 받으셔도 됩니다. 그러면 체험 회원이 쓴 만큼이
> **사장님 한도와 따로 세어져서**, 체험 쪽이 몰려도 사장님 아침 글이
> 안 밀립니다. 무료 등급이라면 이쪽을 권합니다.

### Claude · Codex 를 쓰신다면 — 버킷 이름만 바꿔 한 벌 더

```bash
gcloud storage buckets add-iam-policy-binding gs://maim-demo-YOUR_PROJECT_ID \
  --member="user:$(gcloud config get-value account)" --role="roles/storage.objectAdmin"
```

```bash
gcloud storage rsync -r /tmp/maim-home/.claude gs://maim-demo-YOUR_PROJECT_ID/home/.claude
```

> `/tmp/maim-home/.claude` 는 **3-4 에서 이미 만드신 것**입니다. 그대로
> 한 벌 더 올리시면 됩니다. `claude login` 을 다시 하실 필요 없습니다.
> (검은 창을 새로 여셨다면 3-4 를 처음부터 한 번 더 하십시오.)
>
> Codex 면 `.claude` 를 `.codex` 로 **양쪽 다** 바꾸십시오.

제대로 갔는지 보시려면:

```bash
gcloud storage ls gs://maim-demo-YOUR_PROJECT_ID/home/.claude/
```

파일 이름들이 보이면 맞습니다. `.claude/` 가 **한 번 더** 보이면 잘못
들어간 것입니다.

## 4. 대시보드에 주소 바꿔 넣기

`products/naver-blog/program.yaml` 의 `live.demo` 를 **2번에서 받은 주소**로
바꾸고 대시보드를 다시 올리십시오.

```yaml
live:
  demo: https://maim-demo-xxxxx-uc.a.run.app/
```

```bash
cd ~/cash-flow && git pull && bash deploy/올리기.sh
```

## 5. 자명종은 **걸지 마십시오**

체험 서버에는 **Cloud Scheduler 를 걸지 않습니다.**

체험은 맛보기입니다. 매일 아침 글이 쌓일 이유가 없고, 걸어 두면 아무도
안 볼 글을 매일 만들며 **사장님 AI 한도만 축냅니다.** 체험 회원은
**[지금 생성]** 으로 한 편씩 만들어 보시면 됩니다 (하루 3건).

## 확인

```bash
curl -s https://maim-demo-xxxxx-uc.a.run.app/api/health | python3 -m json.tool
```

| 나와야 할 것 | |
|---|---|
| `db.ok` | `true` |
| `keyserver.set` | `true` |
| `keyserver.program` | `"naver-blog"` |

그다음 대시보드에서 **체험 키를 한 벌 발급**해 그 주소로 들어가 보십시오.
들어가지면 끝입니다.

## 나중에 — 비우고 싶으실 때

체험 회원이 쌓아 둔 것이 지저분해지면, 이 서버만 통째로 비우실 수 있습니다.
**사장님 서버는 아무 영향이 없습니다.** 이것이 따로 세운 이유입니다.

```bash
gcloud storage rm -r gs://maim-demo-YOUR_PROJECT_ID/**
gcloud run services update maim-demo --region us-central1 --update-env-vars=_RESET=$(date +%s)
```

> 두 번째 줄은 **서버를 다시 시작시키는** 것입니다. 비운 저장통을 다시
> 읽어 와야 화면에도 비워진 것이 보입니다.
