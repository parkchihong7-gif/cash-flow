# 블로그 포스팅 — 사장님 매뉴얼 (설치·운영·판매)

> 이 글은 **이 상품을 사신 분**을 위한 것입니다.
> 쓰는 법만 필요하시면 `client.md` 를 보십시오.

---

## 1. 이 상품이 무엇인가

**네이버 블로그에 올릴 글과 대표 이미지를 매일 아침 준비해 두는 프로그램**입니다.
발행은 사람이 합니다.

### 왜 **사장님 서버에** 세우나

이것이 이 상품의 핵심입니다.

| | 남의 서버를 빌려 쓰면 | **사장님 서버에 세우면** |
|---|---|---|
| 글이 쌓이는 곳 | 빌려준 쪽 서버 | **사장님 서버** |
| 서비스가 닫히면 | 글도 같이 사라짐 | 그대로 남음 |
| 값 | 매달 냄 | **한 번 사면 끝** |
| 글 수·카테고리 수 | 요금제만큼 | **제한 없음** |

그래서 설치 안내서를 함께 드립니다. **한 번만 세우시면 그 뒤로는 사장님
것입니다.** 저희가 들여다볼 수 없고, 저희가 문을 닫아도 계속 돕니다.

> 받으신 접속키는 **라이선스 확인용**입니다. 사장님 서버가 "정품인가" 를
> 물을 때만 쓰입니다. 글은 그 길로 오가지 않습니다.

---

## 2. 절대 되살리면 안 되는 것 — 자동 발행

**이 장을 맨 앞에 두는 이유가 있습니다. 한 번 데였습니다.**

### 무슨 일이 있었나

처음에는 Playwright 로 네이버 스마트에디터를 열어 **자동으로 발행**하는 구조였습니다.
실제 시험 중 **네이버가 자동화를 탐지해 계정 보호조치**(비밀번호 강제 재설정)가
걸렸습니다.

그 뒤 네이버 자동 로그인·발행 코드를 **전부 삭제**했습니다. 지금 이 프로그램에는
네이버 비밀번호를 넣는 칸이 **아예 없습니다.**

### 그래서 구조가 이렇습니다

```
Claude 가 글·이미지 준비  →  화면에 카드로 쌓임  →  사람이 복사  →  네이버에 붙여넣고 발행
                                                      ↑ 여기가 사람 자리
```

**마지막 한 단계만 사람이 합니다.** 복사 한 번이 계정을 지킵니다.

### "그래도 자동으로 올리고 싶은데" 하는 생각이 드시면

쓰시다 보면 마지막 복사 한 번도 귀찮아지는 날이 옵니다. 그때 이 글을
다시 보십시오.

네이버는 블로그 글쓰기 공개 API 를 **열어 두지 않았습니다.** 남은 방법은
비밀번호를 프로그램에 넣어 브라우저를 조작하는 것뿐인데, 그건 약관
위반이고 **실제로 잡혔습니다.**

**잃는 것은 그동안 쌓은 글 전부입니다.** 5분을 아끼려다 몇 년을 잃습니다.
복사 한 번이 훨씬 쌉니다.

---

## 3. 설치 — 한 번만 하시면 됩니다

> **30~60분 걸립니다.** 어려운 것은 없고, 붙여넣기만 하시면 됩니다.
> 중간에 막히시면 **10번**을 보십시오.

### 3-0. 준비물 셋

| | 무엇 | 왜 |
|---|---|---|
| ① | **구글 계정** | 서버를 여기에 세웁니다 |
| ② | **AI 계정 하나** | 글을 씁니다. **셋 중 아무거나** — 아래 표를 보십시오 |
| ③ | 카드 한 장 | 구글에 등록만 합니다. 무료 한도 안이라 실제로 빠져나가는 돈은 거의 없습니다 (5번 참고) |

#### ②는 **셋 중 하나만** 있으면 됩니다

| 어느 AI | 무엇이 필요한가 | 설치가 어떻게 되나 |
|---|---|---|
| **Gemini** (Google) | **①의 구글 계정 그대로.** AI 스튜디오에서 **키 한 줄**을 받습니다. 무료 등급이 있어 카드 등록 없이 시작하실 수 있습니다 | **검은 창이 필요 없습니다.** 화면 칸에 키를 붙여넣고 [저장] |
| **Claude** (Anthropic) | Claude Pro 또는 Max 구독 | 검은 창에서 네 줄 (3-4 참고) |
| **Codex** (OpenAI) | ChatGPT Plus 이상 구독 | 검은 창에서 네 줄 (3-4 참고) |

> **이미 쓰시는 것이 있으면 그것을 쓰십시오.** 없으시면 **Gemini** 가
> 제일 쉽습니다 — ①에서 만드신 구글 계정으로 키를 받아 화면에 붙여넣기만
> 하면 되고, 검은 창을 안 거칩니다.
>
> 하루 몇 건까지 무료인지는 구글이 수시로 바꿉니다. 지금 값은
> https://ai.google.dev/gemini-api/docs/rate-limits 에서 보십시오.

### 3-1. 검은 창 열기 (Cloud Shell)

1. https://console.cloud.google.com 에 구글 계정으로 들어갑니다
2. 화면 **오른쪽 위**의 `>_` 모양 아이콘을 누릅니다
3. 화면 아래에 검은 창이 열립니다 (처음엔 10~30초 걸립니다)

| 화면에서 찾으실 것 | 어디에 |
|---|---|
| `>_` 모양 아이콘 | **오른쪽 위**, 종(🔔)과 점 세 개(⋮) 사이 |
| 검은 창 | 누르면 **화면 아래쪽**에 열립니다 |
| `$` 와 깜빡이는 커서 | 검은 창 안. 여기에 붙여넣습니다 |

**중간에 창이 두 번 뜹니다. 둘 다 눌러 주셔야 넘어갑니다.**

| 뜨는 창 | 뭐라고 적혀 있나 | 누를 것 |
|---|---|---|
| **Cloud Shell** | "모든 사용자가 Cloud Shell을 무료로 사용할 수 있습니다" | **[계속]** |
| **Cloud Shell 승인** | "사용자 인증 정보를 사용하여 Google Cloud API를 호출하기 위해 권한이 필요합니다" | **[승인]** |

> **[승인] 을 [거부] 하시면 그다음 명령이 그냥 실패합니다.** 그런데 화면에는
> 왜 실패했는지 잘 안 보여서, 명령이 틀린 줄 알고 한참 헤매시게 됩니다.
> 이 창은 `gcloud` 를 처음 쓸 때 **한 번만** 뜹니다.

> 같은 안내가 프로그램 화면(**관리자 설정 → 1단계 → [매뉴얼 보기]**)에도
> **실제 화면 그림과 함께** 들어 있습니다. 그쪽이 보기 편하십니다.


**화면 위쪽에 보이는 「프로젝트 ID」를 적어 두십시오.** 아래에서 계속 씁니다.
(`my-project-123456` 같은 모양입니다.)

### 3-2. 저장통 만들기

아래를 붙여넣고 Enter. **`YOUR_PROJECT_ID` 를 사장님 것으로 바꾸십시오.**

```bash
gcloud storage buckets create gs://maim-data-YOUR_PROJECT_ID --location=us-central1
```

> `Creating gs://...` 이 뜨면 된 것입니다.

**여기가 글이 쌓이는 곳입니다.** 사장님 계정 안에 있습니다.

### 3-3. 서버 세우기

먼저 프로그램을 받습니다.

```bash
git clone https://github.com/parkchihong7-gif/maim.git && cd maim
```

그리고 아래를 붙여넣습니다. **대문자 다섯 곳을 바꾸십시오.**

```bash
gcloud run deploy maim \
  --source . \
  --region=us-central1 \
  --allow-unauthenticated \
  --memory=2Gi \
  --min-instances=0 --max-instances=1 --concurrency=80 \
  --timeout=1800 \
  --set-env-vars=HOST=0.0.0.0,DATA_DIR=/tmp/maim-state,HOME=/tmp/maim-state/home,GCS_STATE_BUCKET=maim-data-YOUR_PROJECT_ID,TIMEZONE=Asia/Seoul,CLAUDE_BIN=claude,DASHBOARD_TOKEN=YOUR_PASSWORD,KEYSERVER_URL=YOUR_KEYSERVER_URL,KEYSERVER_PROGRAM=naver-blog
```

| 바꿀 곳 | 무엇을 넣나 |
|---|---|
| `YOUR_PROJECT_ID` | 3-1 에서 적어 두신 것 |
| `YOUR_PASSWORD` | **사장님이 정하시는 비밀번호.** 아무도 모르는 것으로 |
| `YOUR_KEYSERVER_URL` | 저희가 메일로 함께 보내 드린 주소 |

> **`--concurrency=80` 을 1 로 바꾸지 마십시오.**
>
> 1 로 두면 **서버 전체가 한 번에 요청 하나만** 받습니다. 그런데 화면을
> 한 번 열 때 프로그램은 설정·카테고리·초안 따위를 **예닐곱 개 한꺼번에**
> 물어봅니다. 하나만 통과하고 나머지는 «요청 실패 (429)» 로 튕깁니다.
> 화면이 텅 빈 채로 뜹니다.
>
> 더 나쁜 것은, **글을 쓰는 1~3분 동안 대시보드가 통째로 죽는다**는
> 것입니다. 그 사이에는 아무 화면도 안 열립니다.
>
> **`--max-instances=1` 은 그대로 두셔야 합니다.** 이건 다른 이야기입니다 —
> 서버가 **두 대로 늘지 않게** 막는 설정이고, 자료(SQLite)가 한 곳에서만
> 써져야 하기 때문에 꼭 필요합니다. 한 대 안에서 여러 요청을 받는 것은
> 아무 문제가 없습니다.
>
> **이미 1 로 배포하셨다면** 이 한 줄이면 고쳐집니다. 다시 배포 안 하셔도
> 됩니다.
>
> ```bash
> gcloud run services update maim --region=us-central1 --concurrency=80
> ```

> **`--memory=2Gi` 를 줄이지 마십시오.** 512Mi 로 뒀다가 데이터가 깨진
> 적이 있습니다. 이 프로그램은 잠들어 있는 동안 요금이 0원이라, 메모리를
> 키워도 돈이 더 나가지 않습니다.

5~10분 걸립니다. 끝나면 이런 줄이 뜹니다.

```
Service URL: https://maim-xxxxx-uc.a.run.app
```

**이 주소가 사장님 프로그램 주소입니다. 적어 두십시오.**

### 3-4. AI 연결 — 빠뜨리면 글이 안 나옵니다

**고르신 AI 에 따라 방법이 완전히 다릅니다.** 둘 중 사장님 것만 보십시오.

| 고르신 AI | 보실 곳 |
|---|---|
| **Gemini** | 아래 **[가] 길** — 검은 창 없이 키 한 줄 |
| **Claude · Codex** | 아래 **[나] 길** — 검은 창에서 네 줄 |

---

#### [가] Gemini — 키 한 줄 (검은 창 필요 없음)

1. https://aistudio.google.com/apikey 에 **①의 구글 계정**으로 들어갑니다
2. **[Create API key]** 를 누릅니다. 키가 바로 나옵니다
3. 그 한 줄을 복사합니다
4. 사장님 프로그램 주소 → **[관리자 설정] → 1단계** 에서 **Gemini** 를 고릅니다
5. 나타나는 칸에 붙여넣고 **[저장]**
6. **[연결 테스트]** 를 눌러 «연결 성공» 이 뜨면 끝입니다

> **왜 Gemini 만 다른가요?**
> Gemini 는 **서버에서 브라우저 로그인 방식을 쓸 수 없습니다.** 검은 창에서
> 아무리 잘 로그인하고 그 폴더를 올려도, 서버가 다시 «브라우저로 승인하세요»
> 를 요구하며 멈춥니다. 이건 저희가 고칠 수 있는 것이 아니라 구글이 그렇게
> 만들어 둔 것입니다 — 공식 문서가 «사람이 없는 자리에서는 API 키를 쓰라» 고
> 적어 두었습니다. 그래서 키 방식만 엽니다. 대신 **사장님에겐 이쪽이 훨씬
> 쉽습니다.**

---

#### [나] Claude · Codex — 검은 창에서 **네 줄**

**두 줄이 아니라 네 줄입니다.** 마지막 ④를 빠뜨리는 분이 제일 많은데,
그러면 검은 창에서는 로그인이 됐는데 **서버는 그걸 모릅니다.**

고르신 AI 의 줄을 쓰십시오.

| 어느 AI | 설치 명령 | 로그인 명령 | 로그인이 남는 폴더 |
|---|---|---|---|
| **Claude** | `npm install -g @anthropic-ai/claude-code` | `claude login` | `.claude` |
| **Codex** | `npm install -g @openai/codex` | `codex login` | `.codex` |

> 화면에서 고르시면 **이 네 줄이 저장통 이름까지 채워진 채로** 그 자리에
> 뜹니다. **[관리자 설정] → 1단계.** 복사 단추도 붙어 있습니다.
> **손으로 옮겨 적는 것보다 그쪽이 훨씬 안전합니다.**

아래는 Claude 기준입니다. Codex 면 `claude` → `codex`, `.claude` → `.codex`
로 **나오는 곳마다 전부** 바꾸십시오.

**① 명령 도구를 설치합니다**

```bash
npm install -g @anthropic-ai/claude-code
```

*added N packages* 같은 줄이 뜨면 된 것입니다.

**② 내 계정이 저장통에 쓸 수 있게 허락합니다**

```bash
gcloud storage buckets add-iam-policy-binding gs://maim-data-YOUR_PROJECT_ID \
  --member="user:$(gcloud config get-value account)" --role="roles/storage.objectAdmin"
```

`maim-data-YOUR_PROJECT_ID` 를 사장님 저장통 이름으로 바꾸십시오. 기억이
안 나시면 먼저 `gcloud storage buckets list` 를 쳐 보십시오.
*Updated IAM policy* 가 뜨면 된 것입니다.

**③ 진짜 로그인입니다**

```bash
mkdir -p /tmp/maim-home && HOME=/tmp/maim-home claude login
```

파란 링크가 뜹니다. 누르셔서 **사장님 계정**으로 들어가고 승인하십시오.

> ⚠️ **앞의 `HOME=` 을 지우지 마십시오. 그리고 앞에 `export` 를 붙이지
> 마십시오.** `export HOME=...` 로 쓰시면 그 뒤로 **같은 검은 창의 `gcloud`
> 명령이 전부 제 설정을 못 찾아 줄줄이 실패합니다.** 그런데 화면에는 그
> 이유가 잘 안 보여서, 무엇이 잘못됐는지 알 수가 없습니다.

**④ 로그인 정보를 서버가 읽는 자리로 옮깁니다 — 이게 빠지면 헛수고입니다**

```bash
gcloud storage rsync -r /tmp/maim-home/.claude gs://maim-data-YOUR_PROJECT_ID/home/.claude
```

제대로 갔는지 확인하시려면:

```bash
gcloud storage ls gs://maim-data-YOUR_PROJECT_ID/home/.claude/
```

파일 이름들이 보이면 맞습니다. `.claude/` 가 **한 번 더** 보이면 잘못 들어간
것이니 ④를 다시 하십시오.

**⑤ 확인**

프로그램 주소 → **[관리자 설정] → 1단계 → [연결 테스트]**.
«연결 성공» 이 뜨면 끝입니다.

### 3-5. 이미지 키 셋 — 셋 다 넣으십시오

무료 사진 사이트 세 곳입니다. 가입하면 바로 받습니다.

| 곳 | 받는 곳 | 시간당 한도 |
|---|---|---|
| Unsplash | unsplash.com/developers | 50회 |
| Pexels | pexels.com/api | 200회 |
| Pixabay | pixabay.com/api/docs | 5,000회 |

```bash
gcloud run services update maim --region us-central1 \
  --update-env-vars=UNSPLASH_ACCESS_KEY=키1,PEXELS_API_KEY=키2,PIXABAY_API_KEY=키3
```

> `--update-env-vars` 입니다. **`--set-env-vars` 를 쓰면 3-3 에서 넣은 설정이
> 전부 지워집니다.** 한 번 그렇게 날린 적이 있습니다.

**하나만 넣으면** 그것이 한도에 걸릴 때 글만 나오고 사진이 안 붙습니다.
셋을 넣으면 하나가 막혀도 나머지가 받습니다.

### 3-6. 자동 포스팅 켜기 — **이게 진짜 마지막이고, 제일 많이 빠뜨립니다**

**여기를 안 하시면 매일 아침 초안이 안 쌓입니다.** 프로그램은 멀쩡한데
아무 일도 안 일어납니다.

왜 그런가 — 이 서버는 **아무도 안 쓸 때 잠듭니다.** 그래서 요금이 0원입니다.
그런데 잠든 서버는 스스로 못 깨어납니다. **깨워 줄 자명종**이 따로 필요합니다.

| 시각 | 무슨 일이 | 이걸 안 걸면 |
|---|---|---|
| 06:00 | **Cloud Scheduler** 가 서버를 두드립니다 | 아무도 안 두드립니다 |
| 06:00 | 잠든 서버가 깨어납니다 | 계속 잠들어 있습니다 |
| ~06:10 | 글과 이미지를 준비합니다 | **아무 일도 안 일어납니다** |
| | 서버가 다시 잠듭니다 (요금 0원) | |


```bash
gcloud scheduler jobs create http maim-daily \
  --location=us-central1 \
  --schedule="0 6 * * *" \
  --time-zone="Asia/Seoul" \
  --uri="https://사장님-서비스-URL/api/run/daily" \
  --http-method=POST \
  --attempt-deadline=1800s \
  --headers="x-dashboard-token=YOUR_PASSWORD"
```

`사장님-서비스-URL` 은 3-3 에서 적어 두신 것, `YOUR_PASSWORD` 도 3-3 에서
정하신 것입니다.

> ⚠️ **`--attempt-deadline=1800s` 를 빠뜨리지 마십시오.**
>
> 이걸 안 적으면 **3분**이 됩니다(구글이 정한 기본값). 그런데 글 한 편에
> 1~3분이 걸리고 하루에 여러 편을 만드니, 3분으로는 **무조건 모자랍니다.**
>
> 모자라면 어떻게 되느냐 — 서버는 계속 글을 쓰고 있는데 **Cloud Scheduler
> 쪽에서 먼저 손을 놓고 「실패」로 적습니다.** 그러면 화면에는 매일
> 실패로 뜨는데 글은 나와 있는, 알아보기 어려운 상태가 됩니다.
>
> 1800초(30분)가 이 항목의 **최댓값**입니다.

**이미 만들어 두셨다면** 이 한 줄로 고치시면 됩니다. 지우고 다시 만들 것
없습니다.

```bash
gcloud scheduler jobs update http maim-daily \
  --location=us-central1 --attempt-deadline=1800s
```

지금 값이 궁금하시면:

```bash
gcloud scheduler jobs describe maim-daily --location=us-central1 \
  --format="value(attemptDeadline)"
```

`1800s` 가 나오면 맞습니다. `180s` 이면 위 고침을 하셔야 합니다.

| 시각을 바꾸시려면 | `--schedule` |
|---|---|
| 매일 새벽 6시 | `"0 6 * * *"` |
| 매일 아침 8시 | `"0 8 * * *"` |
| 평일만 아침 7시 | `"0 7 * * 1-5"` |

> **컴퓨터를 켜 두실 필요는 없습니다.** 구글 쪽에서 깨웁니다. 사장님 컴퓨터가
> 꺼져 있어도, 주무시는 동안에도 초안은 쌓입니다. **다만 이 자명종을 걸었을
> 때만 그렇습니다.**

### 3-7. 하루 몇 편 나오게 할지 정하기

설치 직후에는 **카테고리마다 하루 1편**으로 잡혀 있습니다. 카테고리가
아홉이면 매일 아홉 편이 나옵니다 — 그만큼 올리시는 분은 없습니다.

| 어디서 | 무엇을 |
|---|---|
| **[블로그 관리]** 각 카테고리 | **하루 편수** (0~10). 0 이면 그 카테고리는 쉽니다 |
| **[관리자 설정] → 4) 포스팅 예약 설정** | **시각** · **하루 총 건수**(최대 10) · **차례** |

차례는 하루 상한(**10편**)에 걸려 뒤가 잘릴 때 **무엇이 잘리는지**를 정합니다.

| 차례 | 이럴 때 |
|---|---|
| **순차적** | 카테고리 순서가 곧 중요도일 때 |
| **랜덤** | 매일 다른 것이 나왔으면 할 때 |
| **덜 쓴 것 먼저** | **고르게 돌리고 싶을 때 (기본값)** |

같은 카테고리를 연달아 쓰지 않고 **돌아가며** 넣습니다. 연달아 쓰면 같은
주제 세 편이 잇달아 나와 서로 겹칩니다.

> 이 화면이 **내일 아침에 나올 순서를 그대로 보여 줍니다.** 맞게 넣었는지
> 다음 날까지 기다리지 않으셔도 됩니다.

#### 시각 — **손이 두 번 갑니다**

준비 시각은 화면 맨 위에 큰 숫자로 보입니다. **[시각 바꾸기]** 로 고치십니다.

다만 **화면에서 바꾸는 것만으로는 안 바뀝니다.**

**왜 그런가** — 3-6 에서 보신 그대로입니다. 이 서버는 아무도 안 쓸 때
**잠듭니다**(그래서 요금이 0원입니다). 잠든 서버는 스스로 못 일어나서
구글이 밖에서 깨워 주는데, **깨우는 시각은 구글 쪽에 적혀 있습니다.**
프로그램이 남의 집 자명종을 혼자 고칠 수는 없습니다.

대신 **고칠 명령을 만들어 드립니다.** 저장하면 화면에 이렇게 뜹니다.

```
아직 반만 바뀌었습니다
  이 프로그램은   08:30 으로 압니다        ✅ 끝
  그런데 구글은   아직 06:00 에 깨웁니다   ← 한 줄이 남았습니다
```

**세 걸음입니다.**

| | |
|---|---|
| **1** | 그 아래 **[복사]** |
| **2** | 검은 창(Cloud Shell)에 붙여넣고 Enter |
| **3** | 화면으로 돌아와 **[넣었습니다]** |

`Updated job [maim-daily]` 같은 줄이 뜨면 된 것입니다. **[넣었습니다]** 를
누르시면 그 알림이 사라집니다.

> **귀찮습니다. 그래서 자주 하실 일이 못 됩니다.**
> 처음에 한 번 정하시고 그대로 두십시오. 바꾸실 일이 생기면 그때
> 세 걸음을 한 번 더 밟으시면 됩니다.
>
> 집 서버·VPS 처럼 **늘 켜 두고** 쓰시면 이 절차가 아예 없습니다 —
> 화면에서 저장하면 끝이고, 그 알림도 안 뜹니다.

**처음에는 하루 2~3편으로 시작하십시오.** 쌓이기만 하고 안 올리시면
Claude 한도만 축납니다.

### 3-8. 체험 서버는 **따로** 세우십니다 (나중에 하셔도 됩니다)

사시려는 분께 맛보기를 드리실 거라면, **서버를 하나 더** 세우십시오.

같은 서버를 쓰면 체험 회원이 **사장님 Claude 한도와 메모리를 나눠 씁니다.**
체험 세 분이 오늘 9편 만들면 그만큼 사장님 몫이 줄고, 그쪽에서 탈이 나면
사장님 아침 글이 같이 멈춥니다.

**서버가 하나 더 늘어도 요금은 거의 안 붙습니다** — 아무도 안 쓸 때 잠듭니다.

> 절차는 `체험서버-세우기.md` 에 따로 적어 두었습니다. 30분이면 됩니다.
> **지금 당장 하실 필요는 없습니다.** 맛보기를 드릴 때 하시면 됩니다.

### 3-9. 접속키 넣고 확인

1. 3-3 에서 받으신 주소를 엽니다
2. 메일로 받으신 **1차 인증키**와, 지금 쓰시는 기기에 맞는 **2차 인증키**를 넣습니다
3. 들어가지면 **[블로그 관리]** 에서 카테고리를 만드십시오
4. **[지금 생성]** 을 눌러 글이 나오는지 보십시오 (2~5분)

글이 나오면 **설치 끝입니다.**

## 4. 매일 쓰시는 법 — 5분

설치가 끝나면 하실 일은 이것뿐입니다.

```
① 아침에 주소 열기      ② 마음에 드는 제목 고르기
③ [복사하기]           ④ 네이버에 붙여넣기
⑤ 내 이야기 한두 줄     ⑥ 발행
⑦ [발행 완료로 표시]
```

### ⑤번을 빼먹지 마십시오

AI 가 쓴 글은 AI 가 아는 것만 씁니다. **겪은 것은 사장님만 아십니다.**
직접 겪은 이야기 한두 줄이 이 글을 검색에 올려 줍니다.

> 예) "지난주에 상담 온 분도 이걸 물어보셨는데요"
> 예) "제가 3년 해 보니 이 부분이 제일 헷갈립니다"

### ⑦번을 빼먹으면 글이 겹칩니다

프로그램은 네이버를 들여다볼 수 없습니다. 실제로 올리셨는지 알 길이
없어서, **눌러 주신 것으로 압니다.** 안 누르시면 다음 글이 같은 주제로
나올 수 있습니다.

### 화면 여섯 개

| 메뉴 | 여기서 하는 일 |
|---|---|
| **홈** | 오늘 몇 개 준비됐나 한눈에 |
| **블로그 관리** | 어떤 주제로 쓸지 (카테고리) |
| **포스팅** | **매일 오시는 곳.** 초안을 보고 복사합니다 |
| **발행 이력** | 언제 무엇을 올렸나 |
| **관리자 설정** | AI 연결·톤·**포스팅 예약**(차례와 하루 편수) |
| **사용법** | 짧은 판 |

드리면** 됩니다.

## 7. 이럴 때는 이렇게

**"이미지가 하나도 안 나와요"**
무료 API 키가 없거나 전부 한도를 넘긴 것입니다. 홈 화면 **"AI 연결 상태"** 카드에
살아 있는 소스 개수가 나옵니다. 0 이면 **3-5** 로 돌아가 키 셋을 다시 넣으십시오.

**"지금 생성이 가끔 실패해요"**
Cloud Run 의 요청 제한 시간에 걸린 것입니다. 3-3 의 `--timeout=1800` 이
들어갔는지 확인하십시오. 기본값(5분)이면 다 되어 가던 요청이 끊깁니다.

**"접속키를 잃어버렸어요"**
받으신 메일을 다시 찾아보십시오. 없으면 **사신 곳에 말씀하시면** 새로
발급해 드립니다.

**"다른 기기에서 열었더니 먼저 쓰던 게 끊겼어요"**
**같은 2차키를 두 기기에서 쓰신 것입니다.** 2차키는 PC·노트북·휴대폰용이
따로 있습니다. 지금 기기에 맞는 것을 넣으십시오.

**"같은 주제가 또 나왔어요"**
최근 제목 20개와 안 겹치게 쓰고 있습니다. 그보다 더 거슬러 올라가면 겹칠 수
있습니다. 카테고리를 늘리시는 편이 낫습니다.

## 8. 막혔을 때

| 이런 증상 | 십중팔구 이것입니다 |
|---|---|
| [지금 생성] 을 눌렀는데 오류 | **3-4 의 마지막 줄**을 빠뜨리셨습니다 |
| 아침에 초안이 안 쌓임 | **3-6 자명종**을 안 거셨습니다. [관리자 설정 → 4) 포스팅 예약 설정] 맨 위에 경고가 떠 있는지 보십시오 |
| 아침에 너무 많이 쌓임 | **3-7** 에서 하루 건수를 줄이십시오 |
| 바꾼 시각에 안 나옴 | **3-7 의 세 걸음** 중 2번(검은 창에 붙여넣기)을 안 하신 것입니다. 예약 화면에 「아직 반만 바뀌었습니다」가 떠 있는지 보십시오 |
| Cloud Shell 명령이 자꾸 실패 | **3-1 의 [승인]** 을 [거부] 하셨을 수 있습니다. 검은 창 탭을 닫았다 다시 여시면 그 창이 다시 뜹니다 |
| 글은 나오는데 사진이 없음 | 이미지 키 한도. 3-5 에서 셋 다 넣으셨는지 |
| 첫 접속이 느림 | 정상입니다. 잠든 서버가 깨는 데 2~10초 |
| 데이터가 깨졌다는 말 | 메모리가 2Gi 인지 확인 (3-3) |
| 접속키가 안 통함 | `KEYSERVER_URL` 이 들어갔는지 확인. 체험 서버도 **같은 값**이어야 합니다 |
| 체험 회원 화면이 비어 있다 | 처음 들어가실 때 카테고리 셋이 깔립니다. 안 깔렸다면 그분이 이미 다 지우신 것입니다 |

설정을 다시 보시려면:

```bash
gcloud run services describe maim --region us-central1 --format="value(spec.template.spec.containers[0].env)"
```

그래도 안 되면 **사신 곳에 문의**하십시오. 위 명령의 결과를 함께 보내 주시면
빠릅니다. (비밀번호 줄은 지우고 보내십시오.)

  "매일 아침 준비돼 있다" 까지입니다

  [연결 테스트]로 확인하시고, 3-4 의 ⓑ와 마지막 줄을 한 번 더 하시면 됩니다
- **Gemini 는 무료 등급에도 하루 한도가 있습니다.** 하루 10편이면 대개 한참
  남지만, 한도는 구글이 수시로 바꿉니다 —
  https://ai.google.dev/gemini-api/docs/rate-limits 에서 지금 값을 보십시오
