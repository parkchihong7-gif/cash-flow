# 퍼널 빌더 — 관리자 매뉴얼

> 이 문서는 **프로그램을 운영하고 판매하는 사람**을 위한 것입니다.
> 구매자에게 줄 문서는 `docs/client.md` 입니다.

## 0. 이 프로그램이 하는 일 (한 문단)

판매자가 상품 정보 9개를 적으면, Claude 가 그걸 읽고 랜딩 페이지 문구·이메일 5통·
무료 자료 목차를 초안으로 써줍니다. 사람이 쓰면 하루 걸리는 일을 몇 분으로 줄이는 것이
목적이고, **글을 대신 써주는 것이지 판매를 대신 해주는 것이 아닙니다.**

## 1. 처음 한 번만 하는 준비

### 1-1. API 키 넣기

Claude API 키가 있어야 실제 생성이 됩니다.

1. https://console.anthropic.com/settings/keys 에서 키를 만듭니다 (`sk-ant-` 로 시작).
2. 저장소 맨 위 폴더의 `.env` 파일을 엽니다. 없으면 `.env.example` 을 복사해 만듭니다.
3. `ANTHROPIC_API_KEY=sk-ant-...` 줄에 키를 붙여넣고 저장합니다.
4. 대시보드 **전체 설정** 화면에서 "API 키: 설정됨" 으로 바뀌었는지 확인합니다.

> `.env` 는 절대 남에게 보내거나 GitHub 에 올리면 안 됩니다. 키가 유출되면 요금이 그대로 나갑니다.

### 1-2. 비용 감각 (먼저 알아두세요)

한 번 실행할 때 LLM 을 5번 부릅니다 (헤드라인 → 랜딩 본문 → FAQ → 리드매그넷 목차 → 이메일).
금지 문구가 나오면 그 섹션만 최대 2번 더 부릅니다.

| 상황 | 대략 호출 수 |
|---|---|
| 정상 | 5회 |
| 한 섹션 재생성 | 6~7회 |

1회 실행에 수백 원 수준입니다. 정확한 금액은 Anthropic 콘솔 사용량에서 확인하세요.
**입력이 확정되기 전에 실제 실행을 반복하지 마세요.** 모의 실행으로 형태를 먼저 보세요.

### 1-3. 결제 수단 등록

Anthropic 콘솔에 결제 수단이 없으면 키가 있어도 호출이 거절됩니다.
콘솔의 Billing 에서 카드를 등록하고 소액(10달러 정도)을 충전해두세요.

## 2. 매일 쓰는 흐름

```
입력 채우기 → 모의 실행 → 실제 실행 → 빌드 리포트 확인 → 사람이 수정 → 발행
```

터미널 대신 **통합 관리자 대시보드**에서 전부 할 수 있습니다.

```
python -m dashboard          # 저장소 맨 위 폴더에서
```

왼쪽 목록에서 **1. 퍼널 빌더** 를 누르면 탭 5개가 나옵니다.
열람(읽기) → 수정(입력·설정) → 테스트(실행) → 회원관리 → 매뉴얼 순으로 쓰면 됩니다.
전체 사용법은 저장소 공통 [관리자 매뉴얼](/manual/admin) 3장에 있습니다.

### 2-1. 입력 채우기

대시보드 **수정** 탭에서 `funnel_input.yaml` 을 엽니다. 9개 항목이 있습니다.

| 항목 | 잘 쓰는 법 |
|---|---|
| `product_name` | 실제 판매명 그대로. 산출물 폴더 이름이 됩니다 |
| `target` | **좁을수록 좋습니다.** "직장인"(X) → "퇴근 후 1시간 쓰는 3년차 사무직"(O) |
| `price` | 숫자만. 쉼표나 '원'을 넣으면 오류가 납니다 |
| `core_promise` | 결과 하나만. "시간이 준다"보다 "2시간 → 20분" |
| `lead_magnet_title` | 무료로 줄 자료 제목 |
| `pain_points` | 3~5개. **고객이 실제로 쓰는 말**로 적으세요 |
| `proof` | 실적·후기. **없으면 대괄호 두 개 `[]` 로 비웁니다** |
| `cta_url` | 결제 페이지 주소. `https://` 로 시작해야 합니다 |
| `sender_name` | 이메일 발신자 이름 |

가장 흔한 실수 세 가지:
- 가격에 `149,000` 처럼 쉼표를 넣음 → `149000` 으로
- `pain_points` 를 2개만 씀 → 최소 3개
- 후기가 없는데 그럴듯하게 지어냄 → **하지 마세요.** 비우면 섹션이 빠집니다

### 2-2. 모의 실행부터

**테스트** 탭 → **모의 실행**. 비용이 들지 않고 몇 초면 끝납니다.
나온 랜딩 페이지를 보고 "아, 이런 모양이구나"를 확인하세요. 본문 글은 예시라 의미가 없습니다.

입력을 고칠 때마다 모의 실행을 다시 돌리지는 마세요. 형태는 항상 같습니다.

### 2-3. 실제 실행

**테스트** 탭 → **실제 실행**. 2~4분 걸립니다. 화면이 멈춘 것처럼 보여도 기다리세요.

실행이 끝나면 결과가 셋 중 하나입니다.

| 표시 | 뜻 | 할 일 |
|---|---|---|
| 성공 | 산출물이 다 만들어졌고 금지 문구도 없음 | 다음 단계로 |
| 경고 | 만들어졌지만 금지 문구가 남음 | `build_report.md` 를 보고 해당 부분 수정 |
| 실패 | 만들어지지 않음 | 로그를 보고 3장 문제 해결 참고 |

### 2-4. 빌드 리포트를 먼저 봅니다

`build_report.md` 에 이런 게 들어 있습니다.

- **금지 문구 검사 표** — 섹션마다 몇 번 만에 통과했는지. 2회 이상이면 그 섹션은 한 번 더 읽어보세요
- **헤드라인 10개와 사용한 심리 요인** — A/B 테스트 결과를 해석할 때 씁니다
- **FAQ 3대 반론 커버리지** — ✗ 가 있으면 FAQ 를 직접 보강하세요
- **발행 전 체크리스트**

### 2-5. 사람이 고쳐야 하는 것 (건너뛰면 안 됨)

1. **랜딩 푸터의 환불 정책** — 자리만 비워뒀습니다. 전자상거래법상 청약철회 기간·조건·
   연락처를 반드시 적어야 합니다. 안 적으면 과태료 대상입니다.
2. **사업자 정보** — 상호·대표자·사업자등록번호·통신판매업 신고번호·주소·전화.
3. **이메일 5통 전문 읽기** — 어색한 문장, 사실과 다른 내용이 있는지.
4. **증거 섹션 대조** — 적힌 실적이 실제 자료와 맞는지.

## 3. 문제가 생겼을 때

| 증상 | 원인 | 해결 |
|---|---|---|
| `설정 오류: ANTHROPIC_API_KEY 가 없습니다` | 키 미등록 | 1-1 을 다시 |
| `Claude API 오류 401` | 키가 틀림 | 콘솔에서 키를 새로 발급 |
| `Claude API 쿼터 초과` | 분당 한도 초과 | **재시도하지 말고** 1분 기다렸다 다시 |
| `Claude API 오류 400 credit balance` | 잔액 없음 | 콘솔에서 충전 |
| `입력이 올바르지 않습니다` | YAML 형식 오류 | 메시지에 어느 항목인지 나옵니다 |
| 실행이 15분 넘게 안 끝남 | 타임아웃 | 자동 중단됩니다. 다시 실행 |
| 한글이 깨짐 | 파일 인코딩 | UTF-8 로 저장 |

## 4. 카피 품질을 올리는 법

효과가 큰 순서대로입니다.

| 순서 | 무엇을 | 비용 | 효과 |
|---|---|---|---|
| 1 | `target` 을 더 좁게 쓴다 | 없음 | 가장 큼 |
| 2 | `pain_points` 를 고객이 쓰는 말로 바꾼다 | 없음 | 큼 |
| 3 | `prompts/hooks.md` 를 고친다 | 없음 | 큼 |
| 4 | 모델을 올린다 | 증가 | 보통 |

모델을 올리기 전에 1~3을 먼저 해보세요. 입력이 뭉뚱그려져 있으면 어떤 모델을 써도
뭉뚱그려진 카피가 나옵니다.

**`prompts/hooks.md` 를 고치는 것이 코드 수정 없이 가장 효과가 큽니다.** 이 파일이 모든 생성 호출의
시스템 프롬프트로 들어갑니다. 코드를 건드릴 필요가 없습니다.

효과 있는 수정 예:
- 업종을 좁힌다 — "한국어 카피라이터" → "소상공인 대상 온라인 강의 카피라이터"
- 금지 표현을 추가한다 — 본인이 싫어하는 상투구를 직접 적어두기
- 예시를 넣는다 — 잘 나온 헤드라인 2~3개를 "이런 톤으로" 하고 붙여두면 톤이 안정됩니다

바꾼 뒤에는 **모의 실행이 아니라 실제 실행**으로 확인해야 합니다. 모의 실행은 프롬프트를
쓰지 않기 때문입니다.

## 5. 판매할 때 주의

- 상세페이지에 "수익이 난다"는 취지의 표현을 쓰지 마세요. 고액 부업 강의 관련 소비자 피해가
  실재하고, 표현 하나로 상품이 내려갈 수 있습니다.
- 대시보드 **전체 설정 → 금지 문구** 에서 현재 검사 목록을 볼 수 있습니다.
- 구매자에게는 `docs/client.md` 를 그대로 전달하세요. 대시보드 매뉴얼 화면에서 복사할 수 있습니다.
- API 키는 **구매자가 각자 발급**받아야 합니다. 본인 키를 공유하면 요금이 본인에게 청구됩니다.
  이 내용은 구매자 매뉴얼에도 적혀 있습니다.

## 6. 2번 후킹 대본 생성기와 묶어 팔기

퍼널 빌더(판매 페이지)와 후킹 대본 생성기(유입 콘텐츠)는 같은 고객을 봅니다.
강의를 파는 사람은 사람들을 데려올 콘텐츠도 필요하기 때문입니다.

- 퍼널 빌더 = 온 사람을 결제로 넘기는 장치
- 후킹 대본 생성기 = 사람을 데려오는 장치

묶음 플랜을 만들 때는 **회원관리**에서 두 프로그램의 라이선스를 각각 발급하세요.
어느 쪽을 먼저 쓰게 할지는 고객 상황에 따라 다릅니다. 이미 채널이 있으면 퍼널 빌더부터,
채널이 없으면 대본 생성기부터가 자연스럽습니다.

## 7. 회원관리 연동

구매자가 생기면 대시보드 **회원관리** 에 등록하세요.

1. **고객 추가** → 이름·이메일·유입 경로 입력
2. 고객 상세에서 **라이선스 발급** → 프로그램과 플랜(템플릿 15만 / 세팅 대행 30만) 선택
3. 문의가 오면 고객 상세의 **응대 기록**에 남깁니다

대행 세팅을 해줄 때는 테스트 탭에서 **고객을 지정해 실행**하면 실행 이력에 누구 것인지 남습니다.
