# 퍼널 빌더 (funnel-builder)

강의·전자책 판매자가 **입력 5종이 담긴 YAML 한 장**으로 랜딩 페이지·이메일 5통·리드매그넷 목차까지
한 번에 뽑는 CLI입니다. 카피를 백지에서 쓰는 시간을 줄이는 것이 목적이고,
발행 전 사람이 읽고 고치는 것을 전제로 만들었습니다.

## 설치

```bash
# 저장소 루트에서
pip install -r requirements.txt

cp .env.example ../../.env      # 루트에 .env 가 없다면
# ANTHROPIC_API_KEY 를 채웁니다
```

## 실행

```bash
cd products/funnel-builder
python cli.py build funnel_input.yaml
```

옵션:

| 옵션 | 설명 |
|---|---|
| `--platform own\|kmong\|instagram` | **어디에 올릴 것인가** (기본: own) |
| `--serve` | 만든 뒤 브라우저로 바로 보기 (8000 포트) |
| `--model MODEL` | 사용할 Claude 모델 ID (기본: `.env` 의 `CLAUDE_MODEL`) |
| `--no-ai-label` | AI 생성물 표시를 끕니다. 표시 의무를 직접 처리할 때만 쓰세요 |
| `--out DIR` | 산출물 상위 폴더 (기본: `outputs/`) |

종료 코드는 0(정상), 2(금지 문구가 남아 사람 수정 필요), 1(오류)입니다.

### 어디에 올릴 것인가 — `--platform`

```bash
python cli.py build funnel_input.yaml                        # 내 사이트 (기본)
python cli.py build funnel_input.yaml --platform kmong       # 크몽
python cli.py build funnel_input.yaml --platform instagram   # 인스타
```

| 플랫폼 | 첫 화면 | 왜 다른가 |
|---|---|---|
| `own` | `landing.html` | 내 도메인에 그대로 올립니다 |
| `kmong` | `detail_page.md` | **크몽은 HTML 을 못 올립니다.** 글과 이미지뿐입니다 |
| `instagram` | `reels_captions.md` + `dm_flow.yaml` | 프로필 링크 하나로 모읍니다 |

**이메일 5통·리드매그넷 목차·카피 변형·빌드 리포트는 어느 쪽이든 똑같이 나옵니다.**
달라지는 것은 첫 화면뿐입니다. 같은 입력으로 세 번 돌려 세 곳에 다 쓰셔도 됩니다.

### 미리 보기 — `--serve`

```bash
python cli.py build funnel_input.yaml --serve     # 만들고 바로 열기
python cli.py serve outputs/<폴더>                 # 이미 만든 것 열기
python cli.py serve                               # 가장 최근 것 열기
```

8000 포트가 쓰이고 있으면 다음 포트로 옮겨 갑니다.
**그 폴더 밖은 보이지 않습니다.** 산출물에 고객 이름이 들어갈 수 있어
상위 폴더가 통째로 열리지 않게 막아 두었습니다.

## 입력 — `funnel_input.yaml`

| 키 | 설명 |
|---|---|
| `product_name` | 상품명. 산출물 폴더 이름이 됩니다 |
| `target` | 한 줄 페르소나. 구체적일수록 카피가 좁아집니다 |
| `price` | 판매가 (원, 정수) |
| `core_promise` | 한 줄 핵심 약속 |
| `lead_magnet_title` | 무료 리드매그넷 제목 |
| `pain_points` | 고객의 통증 3~5개 |
| `proof` | 실적·후기. **없으면 빈 리스트** — 비면 랜딩의 증거 섹션 자체가 빠집니다 |
| `cta_url` | 결제·신청 링크 |
| `sender_name` | 이메일 발신자 이름 |

`proof`를 비워두면 증거를 지어내지 않고 섹션을 생략합니다. 없는 실적을 만들어 쓰는 것이
가장 큰 사고이기 때문입니다.

## 산출물 — `outputs/<상품명>/`

| 파일 | 내용 |
|---|---|
| `landing.html` | 단일 파일 랜딩. CSS 인라인, 모바일 반응형, 외부 스크립트 없음 |
| `emails/01~05.md` | 이메일 5통. 상단에 `subject:` / `send_day:` 프론트매터 (D+0,1,3,5,7) |
| `lead_magnet_outline.md` | 리드매그넷 목차 7~10항목 + 각 2줄 요약 |
| `copy_variants.json` | A/B 테스트용 헤드라인 10개 + CTA 5개. 헤드라인마다 사용한 후킹 태그 |
| `build_report.md` | 금지 문구 검사 결과, 사용된 후킹 규칙, 생성 시각, 발행 전 체크리스트 |

플랫폼을 바꾸면 첫 줄만 달라집니다.

| 파일 | 언제 |
|---|---|
| `detail_page.md` | `--platform kmong` — 크몽 상세페이지 순서 그대로 |
| `reels_captions.md` | `--platform instagram` — 릴스 캡션 5개 + 프로필 문구 + 댓글 유도문 |
| `dm_flow.yaml` | `--platform instagram` — 댓글 키워드 → DM 자동응답 시나리오 |

랜딩 섹션 순서는 고정입니다: 히어로 → 문제 공감 → 해결 약속 → 커리큘럼 → 증거(있을 때만)
→ 가격·구성 → FAQ 5개 → 최종 CTA → 푸터.

이메일 5통의 흐름: ①리드매그넷 전달 ②문제 심화 ③해결 원리+사례 ④상품 소개+가격 ⑤마감.

## 어떻게 만드는가

섹션을 한 번에 만들지 않고 **헤드라인 → 랜딩 본문 → FAQ → 리드매그넷 목차 → 이메일** 순으로
나눠 호출합니다. 앞 단계 결과가 뒤 단계 프롬프트의 컨텍스트로 들어가서, 헤드라인에서 정한
톤과 약속을 이메일까지 그대로 끌고 갑니다.

후킹 규칙은 `prompts/hooks.md`에 있고 모든 호출의 시스템 프롬프트로 들어갑니다.
사람이 멈추는 8가지 이유(돈·시간·관계·지위·안전·호기심·비교·손실회피)를 헤드라인마다
2개 이상 결합하고, 쓴 이유를 태그로 남깁니다. FAQ는 "비싸지 않을까 / 나한테 맞을까 /
믿어도 될까" 3대 반론을 선제적으로 답합니다.

생성된 모든 텍스트는 `shared/banned_phrases.py`로 검사합니다. 걸리면 그 섹션만 최대 2회
다시 만들고, 그래도 남으면 `build_report.md`에 경고로 남깁니다. 조용히 넘어가지 않습니다.

## 인스타 — 댓글 키워드 DM (`dm_flow.yaml`)

`--platform instagram` 은 **댓글을 남긴 사람에게만** 보내는 자동응답 시나리오를
같이 만듭니다.

```
릴스 캡션의 "'가이드' 댓글 남겨 주시면 DM으로 보내드려요"
        ↓ (사람이 댓글을 답니다)
   24시간 안에 자동 응답 → 자료 전달 → 뒤이어 묻기
        ↓ (가격·환불·불만이 나오면)
   사람에게 넘김
```

ManyChat·포크레터·키티챗 같은 **공식 도구**에 그대로 옮겨 적을 수 있는 형식입니다.

### 이 파일에 없는 것 — 일부러 없습니다

- **콜드 DM** (먼저 말을 건 적 없는 사람에게 보내는 DM) — Meta 정책 위반,
  계정 정지 사유입니다
- 자동 팔로우 / 언팔로우 / 자동 좋아요
- 24시간이 지난 뒤 보내는 흐름

허용되는 것은 **사용자가 먼저 행동한 대화에 24시간 안에 답하는 것**뿐입니다
(CLAUDE.md §3-4). 시작점을 댓글 하나로 못 박아 둔 이유입니다.

시나리오에는 '그만' 처리와 사람에게 넘기는 조건도 들어 있습니다. 빼지 마세요.

## 발행 전에 반드시

- [ ] 랜딩 푸터의 **환불 정책과 사업자 정보**를 채웁니다 (전자상거래법상 필수 표기)
- [ ] 증거 섹션의 실적이 실제 자료와 일치하는지 대조합니다
- [ ] 이메일 5통을 처음부터 끝까지 읽고 승인합니다

산출물은 초안입니다. "초안 생성 → 사람 승인 → 발행" 3단계를 건너뛰지 마세요.

## 크몽 상세페이지 초안

### 강의·전자책 판매 퍼널, 하루 만에 초안까지

강의를 만드는 것보다 파는 글을 쓰는 게 더 오래 걸립니다.
랜딩 한 장, 이메일 다섯 통, 무료 자료 목차. 백지에서 시작하면 주말이 사라집니다.

이 프로그램은 상품 정보 9개를 YAML 한 장에 적으면 그 다섯 가지를 초안으로 만들어 드립니다.

**이런 분께 맞습니다**
- 강의·전자책을 이미 만들어뒀고 판매 페이지만 없는 분
- 카피를 매번 새로 쓰느라 런칭이 밀리는 분
- 랜딩과 이메일의 톤이 따로 노는 게 신경 쓰이는 분

**이런 분께는 맞지 않습니다**
- 팔 상품이 아직 정해지지 않은 분 — 입력할 내용이 없습니다
- 카피라이터가 이미 있는 팀 — 초안 단계가 필요 없습니다
- 코드를 전혀 실행하지 않으실 분 — 터미널에서 명령어 한 줄을 실행해야 합니다

**드리는 것**
- 랜딩 페이지 HTML 단일 파일 (모바일 대응, 그대로 업로드 가능)
- 이메일 5통 (발송일 D+0/1/3/5/7 지정)
- 리드매그넷 목차 7~10항목
- A/B 테스트용 헤드라인 10개 + CTA 5개
- 빌드 리포트 (어떤 후킹 규칙을 썼는지, 검수할 부분은 어디인지)

**차별점**
- 헤드라인마다 어떤 심리 요인을 썼는지 태그로 남깁니다. A/B 테스트 결과를 해석할 수 있습니다.
- 성과를 단정하는 표현 30개를 자동으로 검사하고, 걸리면 그 부분만 다시 씁니다.
- 실적을 입력하지 않으면 증거 섹션을 만들지 않습니다. 없는 후기를 지어내지 않습니다.
- 인공지능기본법(2026.1.22 시행) 표시 의무에 맞춰 AI 생성물 표시를 기본 탑재했습니다.

**미리 알려드립니다**
- 산출물은 **초안**입니다. 그대로 발행하지 마시고 반드시 읽고 고치세요.
- 환불 정책·사업자 정보는 자리만 만들어 두었습니다. 직접 채우셔야 합니다.
- 성과는 상품·가격·트래픽에 따라 다릅니다. 이 도구는 쓰는 시간을 줄일 뿐,
  판매 결과는 검증이 필요합니다.
- Claude API 키가 필요하며 API 사용료는 별도입니다 (1회 생성 시 수백 원 수준).
