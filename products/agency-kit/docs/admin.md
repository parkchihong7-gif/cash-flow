# 관리자 매뉴얼 — 11. 자동화 대행 납품 키트

이 키트를 **팔고 설치하고 관리하는 사람**을 위한 문서입니다.

---

## 1장. 이 상품이 다른 상품과 다른 점

1~10번 상품은 **프로그램을 파는 것**이었습니다. 이건 **설치를 파는 것**입니다.

| | 1~10번 | 11번 (이 키트) |
|---|---|---|
| 파는 것 | 프로그램 파일 | 설치 + 운영 |
| 값 | 9~12만 원 | 55~120만 원 |
| 한 번 팔면 | 끝 | **월 유지비가 이어짐** |
| 고객이 하는 일 | 직접 돌림 | 시트만 고침 |

크몽에서 누적 6억을 한 판매자의 구조가 이것입니다(CLAUDE.md §2-1).
프로그램 단품이 아니라 **프로그램 + 1:1 교육 + 운영 구조**를 묶어 팝니다.

값이 10배인 이유는 코드가 10배 좋아서가 아닙니다. **설치와 책임**이 붙어서입니다.

## 2장. 세 모듈의 설계 이유

### A. 카카오 FAQ 챗봇 — 왜 시트인가

고객이 답변을 고칠 때 **저를 부르지 않아도 되게** 하려고요.

시트 한 줄을 고치면 5분 안에 챗봇 답이 바뀝니다. 이게 없으면 "영업시간 바뀌었는데
고쳐 주세요" 전화가 매달 옵니다. 그 전화가 유지비보다 비쌉니다.

**시트에 있는 답은 AI 가 다시 쓰지 않습니다.** 고객이 검수한 문장 그대로 나갑니다.
환불 규정 같은 문장이 조금씩 달라지면 분쟁이 됩니다.

### A-2. 5초 제한을 어떻게 지키나

```
글자 맞추기       0초      (Claude 안 부름 — 실제 질문의 상당수가 여기서 걸림)
뜻 맞추기         남은 시간까지
답 짓기           남은 시간까지
시간 초과         "잠시 후 다시 문의"
```

기본 예산은 4초입니다. 1초는 네트워크 몫입니다.

**기다리다 못 받으면 버립니다.** 늦게 온 답은 쓸 데가 없고, 그때는 이미
오픈빌더가 연결을 끊은 뒤입니다.

### B. 주간 보고서 — 숫자와 말의 경계

이 모듈에서 가장 중요한 줄은 `narrate.py` 의 확인 부분입니다.

Claude 가 쓴 글에 집계에 없는 숫자가 있으면 **다시 시킵니다.** 두 번 해도
안 되면 보고서에 "확인하세요" 를 적습니다. 조용히 넘어가지 않습니다.

왜 이렇게까지 하냐면, 보고서 숫자가 시트와 다르면 그 보고서는 한 번에 못 쓰게
되고 대행 계약도 거기서 끝나기 때문입니다.

### C. 인스타 — 왜 승인을 강제하나

사람이 안 읽은 글이 고객 계정에서 나가면, 그 사고는 대행사 책임이 됩니다.
오타 하나면 다행이고 잘못된 가격이 나가면 환불 사태가 됩니다.

그래서 `approved` 가 아닌 줄은 큐 조회에서도 빠지고, 발행 직전에 한 번 더
봅니다. **캡션을 고치면 승인이 자동으로 풀립니다.**

## 3장. 팔 때 하는 말

### 처음 상담에서 물을 것

1. **하루 문의가 몇 건인가요** — 5건 미만이면 챗봇을 권하지 마세요.
   직접 답하는 게 빠릅니다. 이걸 솔직히 말하면 신뢰가 생기고,
   나중에 다른 걸 삽니다
2. **같은 질문이 반복되나요** — 반복되지 않으면 FAQ 로 못 잡습니다
3. **매출을 어디에 기록하시나요** — 시트가 아니면 모듈 B 를 못 붙입니다
4. **인스타 계정이 비즈니스인가요** — 개인 계정은 API 로 발행이 안 됩니다

### 하지 말아야 할 말

- "문의가 절반으로 줄어듭니다" — 모릅니다
- "매출이 오릅니다" — 이 도구가 하는 일이 아닙니다
- "완전 자동입니다" — 인스타는 사람이 승인해야 합니다

### 대신 할 말

"같은 질문에 같은 답을 하는 시간을 줄여 드립니다. 그 시간에 무엇을 하실지는
사장님이 정하십니다."

## 4장. 설치 순서

`deliverables/INSTALL_GUIDE.md` 가 고객용이고, 이 장은 제 쪽 순서입니다.

| 일차 | 할 일 | 시간 |
|---|---|---|
| 1 | 상담, 준비물 안내 | 1시간 |
| 2 | 고객이 키 발급 (지켜보며 도와주기) | 1시간 |
| 2~3 | **FAQ 30줄 함께 채우기** | 2시간 |
| 3~4 | 서버 올리고 오픈빌더 연결 | 2시간 |
| 5 | 점검표 20항목 함께 확인 | 1시간 |

**FAQ 채우는 시간이 제일 깁니다.** 여기서 고객과 같이 앉아 있는 것이
이 상품의 실제 값어치입니다. 코드는 이미 다 되어 있으니까요.

### 모든 키는 고객 계정으로

대행사 계정으로 발급하면 계약이 끝날 때 서로 곤란해집니다.
API 요금이 제 카드로 나가고, 고객은 제가 없으면 아무것도 못 합니다.

점검표 3번 항목이고, 어기면 나중에 반드시 문제가 됩니다.

## 5장. 값 매기기와 유지비

| 패키지 | 값 | 제 작업 시간 | 시간당 |
|---|---|---|---|
| BASIC | 550,000원 | 6~8시간 | 약 7만 원 |
| STANDARD | 880,000원 | 10~12시간 | 약 8만 원 |
| PREMIUM | 1,200,000원 | 15~18시간 | 약 7만 원 |

처음 두세 건은 시간이 두 배 걸립니다. 그건 배우는 시간이라고 보세요.

### 유지비가 본체입니다

한 번 설치로 끝나면 매달 새 고객을 찾아야 합니다. 유지비 10만 원 고객이
10명이면 월 100만 원이 고정으로 들어옵니다.

유지비를 받을 수 있는 근거는 셋입니다.

1. **인스타 토큰 60일 만료** — 안 하면 멈춥니다
2. **못 답한 질문 정리** — 매달 FAQ 를 채워 가는 일
3. **규격 변경 대응** — 카카오·구글·메타가 예고 없이 바꿉니다

첫 달 점검 보고를 잘 만들어 보내면 대부분 계속 갑니다.
`python manage.py stats` 결과를 그대로 붙이면 됩니다.

## 7장. 문제가 생겼을 때

**챗봇이 "잠시 후 다시 문의" 만 합니다**
Claude API 키가 없거나 잔액이 없습니다. `manage.py stats` 의 '못 답함' 이
100% 면 거의 이것입니다.

**시트를 못 읽습니다 (403)**
서비스 계정 이메일을 시트에 공유하지 않았습니다. 가장 흔합니다.

**응답이 4초를 넘습니다**
`manage.py stats` 에 느린 응답이 나옵니다. FAQ 가 60줄을 넘으면 프롬프트가
길어집니다. 카테고리를 나눠 블록을 분리하시거나 FAQ 를 줄이세요.

**보고서 숫자가 시트와 다릅니다**
범위를 잘못 잡았을 가능성이 큽니다. 시트 위에 제목 줄이 있으면
`매출!A3:F` 처럼 잡아야 합니다.

**인스타가 어느 날부터 안 올라갑니다**
토큰 60일 만료입니다. `manage.py refresh-token`.

**인스타 미디어 오류**
구글드라이브 링크를 썼을 가능성이 큽니다. 인스타가 직접 받아 갈 수 있는
공개 https 주소여야 합니다.

## 8장. 확장

이 키트의 구조는 **모듈을 더 붙이기 좋게** 되어 있습니다.

- 네이버 스마트스토어 주문 → 시트 (Commerce API)
- 카카오 알림톡 발송 (별도 심사 필요)
- 구글 캘린더 예약 연동

다만 새 모듈을 붙이기 전에 **지금 세 개를 5건 이상 팔아 보세요.**
팔아 보면 고객이 실제로 무엇을 원하는지 알게 되고, 대개는
"기능을 더" 가 아니라 "이미 있는 걸 더 쉽게" 입니다.

## 9장. 정직하게 말해야 하는 것

1. **AI 답변은 틀릴 수 있습니다.** 그래서 중요한 내용은 시트에 정확한 문장으로
   넣어 두는 구조입니다
2. **문의가 적으면 필요 없습니다.** 하루 5건 미만이면 권하지 마세요
3. **매출을 약속하지 않습니다.** 시간을 줄일 뿐입니다
4. **인스타 자동 팔로우·좋아요는 만들지 않습니다.** 요청받아도 하지 마세요.
   계정이 정지되면 그건 고객 자산이 사라지는 일입니다
5. **카카오·구글·메타 규격은 바뀝니다.** 그래서 유지보수가 필요합니다.
   "한 번 설치하면 영원히" 라고 말하지 마세요
