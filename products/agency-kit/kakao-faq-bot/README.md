# 모듈 A — 카카오톡 채널 FAQ 챗봇

카카오 i 오픈빌더 **스킬 서버**입니다. 고객이 채널에 물으면 구글시트의 FAQ 로
답합니다.

---

## 5초 안에 답해야 합니다

오픈빌더는 5초 안에 응답을 못 받으면 끊습니다. 끊기면 고객 화면에는
"오류가 발생했습니다" 만 보입니다.

그래서 이 서버는 **무슨 일이 있어도 시간 안에 무언가를 돌려줍니다.**

| 단계 | 걸리는 시간 |
|---|---|
| 글자로 맞추기 | 0초 (Claude 안 부름) |
| 뜻으로 맞추기 | 남은 시간까지만 |
| 시간 초과 | "잠시 후 다시 문의" 로 넘어감 |

기다리다 못 받으면 **버립니다.** 늦게 온 답은 쓸 데가 없습니다.

기본 예산은 4초입니다(`CLAUDE_TIMEOUT_SECONDS`). 1초는 네트워크 몫으로 둡니다.

---

## 답을 만드는 순서

1. 시트 FAQ 와 맞춰 봅니다 (글자 → 뜻)
2. 맞으면 **시트 답을 그대로** 냅니다
3. 안 맞으면 시트 전체를 근거로 Claude 가 답하되 "담당자 확인 필요" 를 붙입니다
4. 끝에 AI 응답 표시를 붙입니다

### 2번이 중요합니다

시트에 적힌 답은 **고객이 검수한 문장**입니다. 같은 뜻으로 다시 쓰면 조금씩
달라지고, 그 조금이 환불·보증 같은 데서 문제가 됩니다. 그래서 맞는 항목이
있으면 한 글자도 고치지 않고 내보냅니다.

## 설치

```bash
pip install -r requirements.txt
cp .env.example .env

# 띄우기
uvicorn app:get_app --factory --host 0.0.0.0 --port 8080
# 또는
docker compose up -d
```

### 확인

```bash
curl -s localhost:8080/health

curl -s -X POST localhost:8080/skill \
  -H 'Content-Type: application/json' \
  -d '{"userRequest":{"utterance":"영업시간이 어떻게 되나요?","user":{"id":"u1"}},
       "bot":{"id":"b"},"action":{"name":"faq"}}'
```

`{"version":"2.0","template":{"outputs":[{"simpleText":{"text":"…"}}]}}` 가 나오면 됩니다.

## 구글시트

시트 이름 `FAQ`, 칸은 **질문 / 답변 / 카테고리 / 수정일**.

- 칸 **순서**가 아니라 **이름**으로 찾습니다. 고객이 순서를 바꿔도 괜찮습니다
- ⚠️ 시트를 **서비스 계정 이메일에 '뷰어' 로 공유**해야 읽힙니다.
  가장 흔한 실수입니다. 이것만 빠뜨려도 403 이 납니다
- 권한은 **읽기 전용**만 받습니다. 쓰기까지 받으면 실수 한 번으로 고객 자료가
  날아갑니다

### 5분 캐시

질문마다 시트를 읽으면 그것만으로 1~2초를 씁니다. 그래서 5분 동안은 읽어 둔
것을 씁니다. 고객이 "방금 고쳤는데 왜 안 바뀌죠" 하면 **최대 5분**이라고
답하시면 됩니다. 급하면 `POST /reload` 를 부르세요.

시트를 못 읽으면 **마지막으로 읽은 것을 계속 씁니다.** 빈 답보다 예전 답이
낫기 때문입니다. 그 상태는 `/health` 에 `degraded` 로 나옵니다.

## 오픈빌더 연결

1. 카카오 i 오픈빌더 → 스킬 → 새 스킬
2. URL 에 이 서버의 **https 주소** + `/skill` 을 넣습니다
3. 블록의 응답을 '스킬데이터' 로 바꾸고 이 스킬을 고릅니다

**https 여야 합니다.** 이 컨테이너는 http 로 뜨므로 앞에 Caddy·Nginx 를 두거나
클라우드의 https 주소를 쓰세요. 설치 가이드 3장에 두 가지 길을 적었습니다.

## 기록과 개인정보

`logs.db` 에 남기는 것: 시각 · 이용자 **해시** · 질문 · 맞은 번호 · 답 · 걸린 시간

- 이용자 아이디는 **원문을 저장하지 않습니다.** 해시로 바꿉니다
- 질문에 섞인 **전화번호·이메일·카드번호·주민번호는 지웁니다**
- 오래된 기록은 `manage.py purge --before 2026-06-01` 로 지웁니다.
  계약서에 적은 보관 기간을 지키는 손잡이입니다

완벽한 가림은 아닙니다. 그래서 기록은 상담 개선용으로만 쓰고 오래 두지 않습니다.

## 운영

```bash
python manage.py stats          # 일별 질문 수, 못 답한 질문, 느린 응답
python manage.py unmatched      # 시트에 추가할 후보 (CSV 로 바로 붙일 수 있게)
python manage.py ask "영업시간" --dry-run   # 서버 없이 답만 만들어 보기
```

`stats` 가 **리테이너의 실제 내용물**입니다. 매달 "이만큼 응대했고, 이건 못
답했으니 시트에 이렇게 추가하시죠" 를 보여 드리는 것이 월 유지비의 근거가
됩니다.
